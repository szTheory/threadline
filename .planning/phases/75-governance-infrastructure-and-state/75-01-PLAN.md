# Phase 75: Governance Infrastructure & State - Plan

## Goal
Foundations for background operations and DB state are established.

## Requirements
- **INFRA-01**: Introduce Ecto schemas and migrations for `threadline_export_jobs`, `threadline_retention_runs`, and `threadline_saved_views`.
- **INFRA-02**: Define `Threadline.Storage` and `Threadline.ExportQueue` behaviours to formalize pluggable backend components for storage and background task orchestration.

## Task Breakdown

### 1. Migrations (INFRA-01)
- **Task 1.1**: Create `lib/threadline/governance/migration.ex`.
  - Implement `migration_content/0` returning a string of the migration defining `threadline_export_jobs`, `threadline_retention_runs`, and `threadline_saved_views` tables with `binary_id` primary keys.
- **Task 1.2**: Update `lib/mix/tasks/threadline.install.ex`.
  - Add logic to generate `_threadline_governance_schema.exs` using `Threadline.Governance.Migration.migration_content()`.
  - Add `existing_governance_migration?/1` to avoid overwriting.

### 2. Schemas (INFRA-01)
- **Task 2.1**: Create `lib/threadline/governance/export_job.ex`.
  - Fields: `status` (string), `query_params` (map), `actor_ref` (Threadline.Semantics.ActorRef), `file_path` (string), `error_message` (string), `started_at` (utc_datetime_usec), `completed_at` (utc_datetime_usec), `expires_at` (utc_datetime_usec).
- **Task 2.2**: Create `lib/threadline/governance/retention_run.ex`.
  - Fields: `status` (string), `deleted_count` (integer), `duration_ms` (integer), `error_message` (string), `started_at` (utc_datetime_usec), `completed_at` (utc_datetime_usec).
- **Task 2.3**: Create `lib/threadline/governance/saved_view.ex`.
  - Fields: `name` (string), `actor_ref` (Threadline.Semantics.ActorRef), `filters` (map).

### 3. Behaviours (INFRA-02)
- **Task 3.1**: Create `lib/threadline/storage.ex`.
  - Define callbacks: `put/2`, `get/1`, `download_url/2`, `delete/1`.
- **Task 3.2**: Create `lib/threadline/storage/local.ex`.
  - Implement `Threadline.Storage` behaviour using local `File` operations.
- **Task 3.3**: Create `lib/threadline/export_queue.ex`.
  - Define callback: `enqueue/1`.

## Dependency Analysis
- Tasks within section 1 must be completed together to provide the migration capability.
- Section 2 depends on the schema definitions from Section 1 for coherence, though they can be implemented in parallel.
- Section 3 is independent.

## Goal-Backward Verification
- Can adopters run DB migrations for these schemas? Yes, via `mix threadline.install` which generates `_threadline_governance_schema.exs` (INFRA-01).
- Can developers reference explicit `Threadline.Storage` and `Threadline.ExportQueue` behaviours? Yes, the behaviours are defined in `lib/threadline/` (INFRA-02).
