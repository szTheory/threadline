# Phase 167 — UI Design Contract

> Visual and interaction contract for the component-retune phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase goal:** Every dark-tuned visual effect renders as an explicitly designed light treatment — nothing ships into light unreviewed or merely recolored.
>
> **Nature of this phase:** This is a *retune + verification* phase, not a greenfield design phase. The 45-token light lane already exists (Phase 166, `style.ex` lines 187–287). The contract below does not re-derive tokens — it (a) declares which dark-effect families need an *additive light-lane override* because a token-recolor alone produces a wrong effect on white, (b) declares which families ride the shared status-tint system and need confirmation only, and (c) sets the explicit light-mode design-review criteria for the data-viz-adjacent surfaces (the Grafana lesson). Every token reference is anchored to the Phase 166 lane; no unanchored values are invented.

---

## Hard Constraints (carry into every plan/task)

1. **Additive light lane only.** Every light treatment in this spec MUST be expressible as an additive `.threadline-ui[data-tl-theme="light"]` (and the mirrored `@media (prefers-color-scheme: light) .threadline-ui[data-tl-theme="system"]`) override against the existing dark base block. Never rewrite a base `.tl-*` rule. (Success criterion 4: dark mode visually unchanged.)
2. **Token-anchored.** If a needed value is not in the Phase 166 45-token lane, FLAG it in the plan rather than inventing an unanchored literal. The only sanctioned new *non-color* primitives are blur radii (see Glass families) — and even those should reuse `--tl-blur-*` if the existing values work.
3. **Dark byte-stability.** `style_contract_test.exs` asserts the frozen dark-hex catalog. Do not touch dark token values or base rules. The seven theme-aware assertions and the `theme-toggle` ban (test line 28, 837) stay intact.
4. **No new theme UI.** No toggle, segmented control, or settings surface for theme selection is introduced (carried from Phase 166 Interaction Contract).
5. **Do not touch the uncommitted nav-overhaul lane** (~29 files under `lib/`, `examples/`, `test/`, incl. its 3 pre-existing test failures).

## Color

The light lane is the Phase 166 lane verbatim. The 60/30/10 split below maps the dark-first brand ratio (Brand Book §10: 70/20/10) onto the light surface; accent stays a 10% signal, never decoration.

| Role | Token (light value) | Usage |
|------|---------------------|-------|
| Dominant (~60%) | `--tl-color-bg #F7F9FC` (Paper), `--tl-color-surface #FFFFFF` | Page background, primary panels/cards/tables |
| Secondary (~30%) | `--tl-color-surface-raised #EEF3FA`, `--tl-color-surface-hover #E7ECF4`, `--tl-color-surface-selected #DDE8FF`, `--tl-color-border #C9D3E2` | Raised panels, nav/toolbar/coverage-command chrome, hover/selected states, rails |
| Accent (~10%) | `--tl-color-accent #1557C0` (+ `accent-strong #0E459B`, `accent-soft .12`, `accent-border .28`, `accent-inset .16`) | See reserved-for list |
| Destructive | `--tl-color-danger #A33434` (+ `danger-bg .10`, `danger-border .28`) | Delete-op rails, danger chips/alerts, job-error rows only |

**Accent reserved for (explicit — never "all interactive elements"):**
- Links and link-hover (`a` → `accent` / `accent-strong`)
- Active nav item (`tl-shell-nav__item--active` / `[aria-current="page"]`): `accent-soft` bg, `accent-border` border, `accent-inset` inset
- Pressed segmented control (`tl-segmented__item[aria-pressed="true"]`)
- Home front-door card kicker + primary card wash (`accent-wash` gradient)
- Focus ring (`--tl-focus-ring` uses `accent`-derived `rgba(21,87,192,0.22)` + `border-focus #1557C0`)
- Info-status tint family (op-update, info chips/facts) which aliases the accent hue

Second signal color: `--tl-color-signal #0F8F85` (teal) is reserved exclusively for the home front-door "thread" signature line and correlation/positive-flow accents — it is NOT a general accent.

## Component Retune Contract (COMP-01) — the ~9 dark-effect families

Each family is currently dark-tuned via translucent `surface-tint` tokens, `backdrop-filter: blur()`, or low-alpha insets. On white these can wash out (the glass reads as flat opaque white) or the effect inverts wrong (a dark glow). For each, the table states the **light intent** and the **additive override** that must be expressible under `[data-tl-theme="light"]`. "Confirm only" means the Phase 166 token-recolor already produces the correct light effect and the plan must *verify*, not author.

| # | Family | Source anchor | Dark effect today | Designed light intent | Additive light-lane treatment |
|---|--------|--------------|-------------------|----------------------|-------------------------------|
| 1 | Glass: topbar | `style.ex:384` (`.tl-topbar`) | `surface-tint rgba(20,27,45,.94)` + `blur(8px)` over dark = frosted dark glass | Frosted light glass that stays *legibly distinct* from the white page beneath; the blur must remain perceptible, not collapse to flat white | `surface-tint` light value `rgba(255,255,255,0.92)` already differs from `bg #F7F9FC` — **confirm** the 0.92 translucency + `border-bottom border #C9D3E2` reads as a layered chrome on scroll. If the glass is indistinguishable from page, override `--tl-blur-panel` perception by lowering tint alpha (e.g. add a light-lane `surface-tint rgba(255,255,255,0.82)`) — FLAG as token-alpha tuning, keep additive. |
| 2 | Glass: shell-nav | `style.ex:470` (`.tl-shell-nav`) | same tint + bottom border | Same as topbar — the sticky nav band must read as chrome distinct from page | Confirm with topbar; same treatment. Single shared `surface-tint` token covers both. |
| 3 | Glass: toolbar | `style.ex:966` (`.tl-toolbar`) | `surface-tint-strong rgba(11,16,32,.96)` + `border` + `shadow-border,shadow-subtle` + `blur(8px)` | Raised glass card that floats above content rows with a real (not invisible) light shadow | `surface-tint-strong` light `rgba(247,249,252,0.96)` + `shadow-subtle` light (`rgba(15,23,40,.08/.06)`) — **confirm** the shadow is visible on white (dark-lane shadows at .50/.34 alpha invert correctly to the .08/.06 light values from Phase 166). |
| 4 | Glass: coverage-command + subview header | `style.ex:3047` (`.tl-coverage-command`), `style.ex:2748` (`.tl-subview__header`) | `surface-tint-strong` / `surface-tint` + `blur` | Command panel reads as the focal raised surface; drawer header reads as sticky frosted chrome over scrolling drawer content | Confirm shared with #1/#3. Subview header rides `surface-tint` + `blur-panel`; coverage-command rides `surface-tint-strong` + `shadow-border,shadow-subtle`. |
| 5 | Drawer scrim | `style.ex:2722` (`.tl-subview-backdrop`) | `backdrop rgba(2,4,10,.62)` + `blur(1px)` — heavy dark veil | A light scrim must still **dim and recede** the page behind the drawer; a near-white scrim fails. Phase 166 set light `backdrop rgba(15,23,40,0.42)` — a translucent *ink* veil, correct intent | **Confirm** `rgba(15,23,40,0.42)` darkens the white page enough to read as "behind/inactive" without going muddy. This is the single most likely-to-fail light effect — give it explicit review. If too weak, FLAG token-alpha bump (still additive). |
| 6 | Drawer shadow | `style.ex:2740` (`.tl-subview` `box-shadow: var(--tl-shadow-raised)`) | dark `shadow-raised 0 18px 48px rgba(2,4,10,.66)` | The off-canvas drawer must cast a believable light shadow so it reads as elevated above the dimmed page | Confirm light `shadow-raised 0 18px 48px rgba(15,23,40,0.24)` (Phase 166) renders as a real edge shadow on `surface #FFFFFF`. |
| 7 | Focus glow | `style.ex:156`/`322` (`--tl-focus-ring` + `:focus-visible`) | dark ring `rgba(127,169,255,.42)` halo on `border-focus #7FA9FF` | Focus must remain a clearly visible 3px ring on white without the dark-tuned high-alpha halo blooming | **Confirm** light `--tl-focus-ring 0 0 0 3px rgba(21,87,192,0.22), 0 0 0 1px #1557C0` (Phase 166). Non-text contrast of the ring is formally proven in Phase 168 (A11Y-02) — here, confirm it is *perceptible* and not washed out. Also covers the chip status-dot glow `box-shadow: 0 0 0 3px color-mix(... currentColor 14% ...)` at `style.ex:1539` — `currentColor`-based, adapts automatically, **confirm only**. |
| 8 | Home-card signature effects | `style.ex:681` (`.tl-home__card--primary`), `:692` (`::before` thread line) | `accent-wash` gradient over `surface-raised`; Signal-cyan `#4EDFD1` thread line fading to transparent | The front-door card's accent wash and the Signal "thread draw" must read on white as a *subtle luminous accent*, not a muddy or invisible band | Confirm `accent-wash` light `rgba(21,87,192,0.06)` over `surface-raised #EEF3FA` is perceptible. Confirm the thread line `linear-gradient(90deg, signal, transparent 80%)` with light `signal #0F8F85` (teal, darker than dark-lane cyan) reads as a deliberate signal line on white — this is a designed inversion (luminous-on-dark → saturated-on-light), give it explicit review. |
| 9 | Shell-nav active inset | `style.ex:588` (`.tl-shell-nav__item--active`) | `accent-soft` bg, `accent-border` border, `box-shadow: inset 0 0 0 1px accent-inset` | The active-nav inset hairline must remain visible against white so the active item is unambiguous | **Confirm** light `accent-inset rgba(21,87,192,0.16)` inset + `accent-soft .12` bg + `accent-border .28` border (all Phase 166) compose into a clearly-selected state. This is the token that was un-stray-ed in Phase 166 (TOKEN-03); confirm it carries the same read in light. |

**Rule for #1–#9:** Default disposition is *confirm the Phase 166 token-recolor is correct*. Author an additive `[data-tl-theme="light"]` override ONLY where confirmation fails (most likely #5 scrim strength, #1 glass-vs-page distinctness, #8 signal-line read). Any override must be mirrored into the `system`/`prefers-color-scheme: light` branch in the same task. Any new value that is not derivable from the existing 45-token lane is FLAGGED, not silently invented.

## Tint-Rider Verification Contract (COMP-01/TOKEN-02) — the ~20 families that need confirmation only

These ride entirely on the Phase 166 shared status-tint system (tinted background + darkened text + status-colored rail). The contract **asserts they need no new per-component work** — only confirmation that each resolves correctly through the shared tokens. A plan that adds per-component light overrides for any of these is OUT of contract unless it first proves the shared token fails for that family.

| Family | Source anchor | Rides tokens |
|--------|--------------|--------------|
| Status chips (info/warning/danger/success/accent/muted/neutral) | `style.ex:1529–1602` | `*-bg`, `*-text`/`*-border`, status-dot `currentColor` |
| Alerts | `style.ex:1735–1755` | `*-bg`, `*-border`, status-stripe via `inset` rail |
| Timeline facts | `style.ex:1022–1044` | `info/warning/success-text`/`-border` rail |
| Op badges (insert/update/delete) | `style.ex:1881–1894` | `op-*-bg`/`op-*-text` → alias `success/info/danger` |
| Redaction rows | `style.ex:1813–1829` | status `*-bg`/`*-text` + rail |
| Policy drift rows | (status-tint family) | `warning`/`danger` tint set |
| Job error states | `style.ex:2123` (status stripe) | `danger` rail + tint |

**Verification assertion:** All seven families above resolve their light appearance from the Phase 166 status-tint decision (tinted bg + darkened text, the documented light inversion of dark-mode glow). No per-component `[data-tl-theme="light"]` selector is required or permitted for these unless a specific family is *proven* to misresolve. The plan's verification pass produces a checklist confirming each renders correctly on white; that checklist is the deliverable, not new CSS.

## Data-Viz Design-Review Contract (COMP-02) — the Grafana lesson

Coverage, timeline, and diff surfaces must pass an **explicit light-mode design review** — dark-tuned dense content recolored to light without thought reads as broken. These surfaces are *not* free-rethemes; they get named review criteria. The review is a human-gateable judgment recorded in the plan/verification, not just a passing test.

| Surface | Source anchor | Review criteria (must all hold on white) |
|---------|--------------|------------------------------------------|
| Coverage matrix / command | `style.ex:3047` (`.tl-coverage-command`), coverage table | Status pills/metrics legible at dense sizes; covered/uncovered/partial states distinguishable by tint AND non-color cue (Brand Book §10: never color alone); the raised command panel reads as focal, not flat; small mono metadata (`font-size-xs/sm`) stays readable on `surface #FFFFFF`. |
| Timeline | `style.ex:980` (`.tl-timeline-command`), `:1022` facts, timeline rows | Status-rail stripes (`inset 3px`) remain visible on white; the "thread" reading (connected history) survives — rails and dividers (`border #C9D3E2`) must not vanish; dense rows keep row-to-row separation; tabular-nums timestamps legible. |
| Diff views | `style.ex:2262` (`.tl-diff`), `:2277` arrow | Before/after values distinguishable; the `surface #FFFFFF` diff panel + `border` reads as a contained block; mono diff text at body/label size legible; the `→` arrow (`muted #3B4762`) visible but not louder than the values; add/remove/change semantics carried by status tint + non-color cue, never color alone. |

**Review disposition:** Default is *confirm the token-recolor produces a designed-quality light surface*. Where a dense surface reads as washed-out or loses a structural cue (most likely: low-contrast rails, near-invisible dividers, or tint pills that merge on white), author an additive light-lane override anchored to existing tokens (e.g. promote a divider from `border` to `border-strong #A7B4C8`). Record each review outcome (pass / override-needed) explicitly — that record satisfies "no dark-tuned content ships unreviewed."

## Copywriting Contract

This phase changes **no copy**. It is a pure visual-treatment phase over existing surfaces; all CTAs, empty states, and error states are pre-existing and theme-agnostic. Listed for the checker, sourced from the existing operator surface — do not alter.

| Element | Copy (existing, unchanged) |
|---------|---------------------------|
| Primary CTA | Existing per-surface labels (e.g. home front-door "Start a walkthrough", coverage "Run coverage check") — sentence case per Brand Book §7; not modified this phase |
| Empty state heading | Existing (e.g. home resume "Nothing in progress") — not modified |
| Empty state body | Existing — not modified |
| Error state | Existing job-error / policy-drift copy — specific, transparent, fix-oriented per Brand Book §6; not modified |
| Destructive confirmation | None introduced this phase. No destructive action is added; delete-op *display* (op-delete rail) is read-only visualization, not an action. |

If a plan finds an empty/error surface that is *visually* broken in light (e.g. a status tint that erases its own text), the fix is a token/treatment fix, not a copy change.
