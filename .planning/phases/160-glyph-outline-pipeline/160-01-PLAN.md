Locked decisions from 160-CONTEXT.md (NON-NEGOTIABLE):
- fontkit, not opentype.js (fontkit parses woff2/Brotli natively; `font.layout()` applies real GPOS kerning).
- Ephemeral deps — NO `node_modules`, `package.json`, or `package-lock.json` committed anywhere. Commit only the script and its outputs.

- Counters (e/a/d holes) must render via preserved winding from the font outlines — nonzero fill rule with opposing contour directions. NEVER "simplify", reverse, or merge contours.
- Script lives in the phase dir during the phase, with a copy under `brandbook/tools/` so outlines stay regenerable after archive. brandbook/tools/ is the ONLY brandbook/ touch allowed; existing brandbook assets must not change.

Create `.planning/phases/160-glyph-outline-pipeline/tools/text-to-paths.mjs` (~100 lines, ESM, no dependencies beyond fontkit resolved at runtime).

CLI contract: `node text-to-paths.mjs --font <path-to-woff2> --out <output-prefix> [--text "Threadline"]`. `--font` and `--out` required; `--text` defaults to "Threadline". Emits `<output-prefix>.svg` and `<output-prefix>.json`. The `--font` arg is the future-typeface scaffolding per CONTEXT.md (optional scaffolding decision) — no other typeface support needed.

Ephemeral fontkit wiring (Claude's discretion area — this is the chosen mechanism, document it in the script's header comment as the canonical invocation):

    FONTKIT_DIR=$(mktemp -d)
    npm install --prefix "$FONTKIT_DIR" --no-fund --no-audit --silent fontkit@2.0.4
    NODE_PATH="$FONTKIT_DIR/node_modules" node tools/text-to-paths.mjs --font priv/fonts/geist-500.woff2 --out <prefix>

CRITICAL footgun: ESM `import` ignores NODE_PATH. The script must resolve fontkit via `module.createRequire(import.meta.url)` and `require('fontkit')` — CJS resolution honors NODE_PATH. Fail with a clear error message naming the canonical install command if fontkit cannot be resolved. Nothing is ever committed from the temp install.

Shaping: use `font.layout(text)` (applies real GPOS kerning — this is why fontkit was locked over opentype.js per CONTEXT.md). Walk `run.glyphs` + `run.positions` in parallel, accumulating the pen x position from `xAdvance` (+ `xOffset` per glyph). Record each glyph's kerned pen x.

Serialization (do NOT use `glyph.path.toSVG()` — it emits unrounded coordinates and no y-flip; CONTEXT.md notes unrounded output bloats files 5-10x). Walk `glyph.path.commands` and serialize manually:
- Coordinate space: font units. Y-flip: `ySvg = ascent - yFont` so the baseline sits at y = ascent and SVG y grows downward. Apply to every point including bezier control points.
- Round every emitted coordinate through ONE canonical formatter: `toFixed(2)` then strip trailing zeros and trailing dot deterministically (e.g. `(-0).toFixed(2)` must normalize to `0`, never `-0`). Same formatter for SVG and JSON.
- Each glyph: glyph-local `d` (pen offset NOT baked in) wrapped as `<path id="g-{index}-{glyphName}" transform="translate({kernedX} 0)" d="..."/>` — keeps the d editable for Phase 161 motif work while the transform + JSON expose the kerned offset.
- One `<path>` per glyph, never merged. No `fill-rule` attribute (SVG default nonzero is required for counters). Preserve contour order and winding exactly as fontkit emits them.
- Root: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 {totalAdvance} {ascent - descent}">` (descent is negative in font units). All numbers through the canonical formatter. No `<text>`, no `<script>`, no timestamps, no comments containing dates/versions that would break byte-determinism. Single trailing newline.
- Combined convenience path per weight: OMIT (discretion decision — keeps the contract minimal; per-glyph paths are the primary output).

JSON schema (Claude's discretion area — this is the chosen layout):

    {
      "text": "Threadline",
      "font": { "file": "<basename>", "postscriptName": ..., "weight": 500,
                "unitsPerEm": ..., "ascent": ..., "descent": ...,
                "capHeight": ..., "xHeight": ..., "baseline_y_svg": <ascent> },
      "total_advance": ...,
      "glyphs": [ { "index": 0, "name": "T", "code_points": [84],
                    "advance_width": ..., "x_offset_kerned": ...,
                    "y_offset": 0, "bbox": {...}, "d": "<same glyph-local d as SVG>" } ],
      "stem_widths": { "l": ..., "T": ..., "units": "font_units", "method": "<description>" }
    }

Weight: derive from the font filename suffix (geist-500 → 500) or `font['OS/2'].usWeightClass`. Keys in fixed insertion order; `JSON.stringify(obj, null, 2)` + trailing newline (deterministic).

Stem widths (required by CONTEXT.md footgun: glyph outlines are fills, the Phase 161 thread motif is a stroke — 161 needs these to match stroke width to letterform stems):
- "l": layout "l", stem width = glyph bbox width (`maxX - minX`) — Geist lowercase l is a single vertical stem.
- "T": layout "T", collect all on-path and control x-coordinates from commands whose y (font units) is below capHeight/2 — the lower half contains only the vertical stem (crossbar is at top); stem width = max(x) - min(x) of that set.
- Record the method string in JSON so Phase 161 knows how values were measured.

Determinism requirements: no Date/random/env-dependent output; iteration order fixed by layout order; same formatter everywhere; outputs written with `\n` line endings.
