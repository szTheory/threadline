<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Auth assigns -> shell destinations | Server-side feature gates determine whether Coverage, Evidence, Redaction, Retention, and Exports appear. |
| Browser -> theme POST | Native radio form submits untrusted theme input through the existing CSRF-protected route. |
| Browser -> Home launcher events | EF1 and EF4 form input crosses into LiveView event handlers before route construction. |
| HEEx templates -> operator browser | Shell/Home copy and attributes render into the browser and must stay HEEx-escaped. |
| Shell CSS -> operator usability | Focus, sticky chrome, and overflow behavior can block keyboard/mobile operators if broken. |

## ASVS L1 Baseline

ASVS L1 applies to this implementation plan. Any high-severity route exposure, feature-gate leakage, CSRF regression, unsafe launcher route construction, hidden focus/overflow denial, or raw HTML/XSS regression blocks plan completion.

| ASVS Area | Plan Mapping |
|-----------|--------------|
| V4 Access Control | Keep feature-gated groups server-rendered from existing auth assigns and preserve router/auth gates. |
| V3 Session Management / V6 Cryptography | Keep server-resolved theme and CSRF-backed POST form; do not add client-only theme mutation. |
| V5 Validation, Sanitization, and Encoding | Keep mapped-table validation, record id validation, correlation id length validation, and URI encoding in `StartLive`. |
| V14 Configuration | Keep root optional Phoenix/LiveView posture and no new UI/browser package. |
