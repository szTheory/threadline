# Phase 183 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 183 makes the `/audit` operator shell and Home page unmistakably navigable and task-led. It polishes the existing Phoenix LiveView operator surface; it does not add routes, change auth/capture/query semantics, introduce public components, replace `/audit/__stress`, or add a root Tailwind/shadcn design system.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none; shadcn gate not applicable because Threadline is Phoenix LiveView, not React/Next/Vite |
| Preset | not applicable |
| Component library | Private Phoenix function components in `Threadline.OperatorSurface.UI` plus `Threadline.OperatorSurface.Components.SurfaceHeader` |
| Icon library | Internal inline SVG icons via `Threadline.OperatorSurface.Components.Icon`; no icon package dependency |
| Font | Geist for UI text; IBM Plex Mono for refs, route paths, technical labels, and short status metadata |

Source: `.planning/REQUIREMENTS.md` SHELL-01 through SHELL-03; `.planning/ROADMAP.md` Phase 183 success criteria; `lib/threadline/operator_surface/components/surface_header.ex`; `lib/threadline/operator_surface/live/start_live.ex`; `lib/threadline/operator_surface/style.ex`; Phase 182 UI-SPEC convention.

Design-system contract:

- Keep the runtime shell inside `UI.shell/1`, `SurfaceHeader.surface_header/1`, and scoped `.threadline-ui` CSS. Do not add a new shell component, LiveComponent, layout dependency, Tailwind config, shadcn registry, Radix, or public UI API.
- Preserve route paths and destination meaning: `/audit`, `/audit/timeline`, `/audit/coverage`, `/audit/evidence`, `/audit/policy/redaction`, `/audit/policy/retention`, and `/audit/exports`.
- Preserve existing `data-testid` values for shell and Home affordances unless a phase task records and verifies the change in source and browser tests.
- Preserve feature gates. Coverage, Evidence, Redaction, Retention, and Exports appear only when their existing assigns enable them; disabled or absent destinations must not leave empty nav groups or duplicate CTAs.
- Keep `data-tl-theme="dark" | "light" | "system"` as the theme contract. Phase 183 may retune shell/Home CSS within existing tokens, but must not add a theme toggle variant or parallel theme token family.
- Keep `/audit/__stress` and PhoenixStorybook as verification/dev lanes only. The operator Home page is not a component catalog or stress route index.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Dense nav label offsets, compact stack gaps, radio-option internal gaps |
| sm | 8px | Nav item padding units, topbar gaps, button icon gaps, Home chip gaps |
| md | 16px | Default shell gutter, card stack gap, page padding, panel padding |
| lg | 24px | Home card padding on narrow screens, hero rhythm, grouped launcher spacing |
| xl | 32px | Home earned-flow section gaps, nav group separation where space allows |
| 2xl | 48px | Major Home section breaks using existing `--tl-space-12` only when needed |
| 3xl | 64px | Reserved page-level spacing; do not introduce a Phase 183-specific token |

Exceptions: Existing `style.ex` tokens `--tl-space-3` (12px), `--tl-space-5` (20px), `--tl-space-10` (40px), and brand-only `--tl-space-20` (80px) may remain where already used. Do not add new spacing tokens in Phase 183.

Interaction spacing rules:

- `--tl-hit-area: 40px` remains the minimum mobile/nav/theme-picker hit target. At tablet and desktop, shell nav links may keep compact `--tl-control-height-compact: 32px` only when the label remains fully visible and focus is not clipped.
- Topbar height remains `--tl-header-height-mobile: 52px` on the mobile base and `--tl-header-height: 44px` at the desktop layer. Sticky nav offsets and `scroll-padding-top` must continue to reconcile to those tokens.
- Desktop/tablet shell gutter remains `--tl-shell-gutter: var(--tl-space-4)` unless implementation proves a smaller or larger gutter is needed for 768px readability.
- Home layout must remain one scroll surface at mobile width. No nested scroll panels, no fixed Home cards, and no card-inside-card composition.
- Home cards, earned-flow panels, and saved-view chips must have stable dimensions under hover/focus. Hover, active, checked, loading, and error states must not resize the shell or card grid.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | regular 400 | 1.5 |
| Label | 14px | semibold 600 | 1.4 |
| Heading | 20px | semibold 600 | 1.2 |
| Display | 32px | semibold 600 | 1.15 |

Typography rules:

- New or changed Phase 183 text declares only regular 400 and semibold 600. Existing `--tl-weight-medium` uses in `style.ex` may remain, but do not introduce additional weights.
- The Home H1 remains the only display-scale text in this phase. On mobile, the existing title-size fallback may remain so the headline fits without horizontal scroll.
- Shell group labels use mono only for short category labels such as `Investigate`, `Audit readiness`, `Evidence & exports`, and `Theme`. Do not use mono for Home body copy or job-card titles.
- Letter spacing is `0` for normal text. Caps tracking may remain only on existing compact labels that already use `--tl-tracking-caps`.
- Do not add marketing hero copy, oversized landing-page type, decorative eyebrows, or explanatory in-app instructions. The shell and Home should orient through labels, hierarchy, and task affordances.
- Preserve exact capitalization for visible destination names: `Overview`, `Timeline`, `Coverage`, `Evidence`, `Redaction`, `Retention`, `Exports`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Dark: `#0B1020` / `--tl-color-bg`; Light/System light branch: `#F7F9FC` | Page background and shell ground inside `.threadline-ui` |
| Secondary (30%) | Dark: `#141B2D` and `#1B253A`; Light/System light branch: `#FFFFFF` and `#EEF3FA` | Topbar, shell nav, Home cards, earned-flow panels, raised surfaces |
| Accent (10%) | Dark: `#4F8CFF`; Light/System light branch: `#1557C0` | Current nav state, primary Timeline CTA, selected theme option, focus-adjacent borders, selected saved-view chips |
| Destructive | Dark: `#FF8585`; Light/System light branch: `#A33434` | Destructive status evidence and existing Retention destructive flow only |

Accent reserved for: `aria-current="page"` nav item state, primary `Open the timeline` CTA, active/checked theme option, keyboard focus rings and focus-adjacent borders, Home primary investigation card cue, saved-view chips, deep links, and copy success where existing components already use accent or signal tokens.

Semantic color rules:

- Signal Cyan remains reserved for live thread/correlation movement, copy success, and positive system movement. It is not a second general accent.
- Coverage gaps use warning tokens. Failed exports and failed retention health signals use danger tokens. All-clear health uses success tokens.
- The topbar coverage chip and Home health row must remain visually distinct: the topbar reports coverage count/status, while Home health states the operator consequence or all-clear status.
- Do not add decorative orbs, bokeh, broad page gradients, or new color families. The only allowed Home accent wash is the existing restrained primary-card treatment and its thread cue.
- Dark, light, and system branches must preserve text/background contrast for nav labels, active states, status chips, theme picker options, Home card copy, form controls, and error alerts.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Open the timeline` |
| Empty state heading | `Pick up where you left off` |
| Empty state body | `No saved timeline searches yet. Use timeline filters when you are ready to save a repeat investigation.` |
| Error state | `Select a table for row history.`, `Select a mapped table for row history.`, `Enter a record id for row history.`, `Enter a correlation id to open the timeline.`, `Correlation id must be 256 bytes or fewer.` |
| Destructive confirmation | None in Phase 183. Existing Retention destructive confirmation remains out of scope and must not be changed here. |

Copy rules:

- Shell nav group labels are exactly `Investigate`, `Audit readiness`, `Evidence & exports`, and `Theme`.
- Home job-card titles are exactly `Find what changed`, `Check audit readiness`, and `Use evidence and exports`.
- Home keeps one primary investigation path: `Open the timeline`. The readiness path is `Check coverage`. Proof/governance destinations remain specific links, not one redundant generic cross-page CTA.
- Home earned-flow launchers are specific shortcuts, not builders: `Open row history` for table plus record id, and `Open Timeline` for correlation id.
- Preserve existing calm, exact Threadline voice. Avoid exclamation marks, "Prove/proof" as generic marketing language, CamelCase model names, and implementation jargon in shell/Home visible text.
- Use canonical operator nouns: Timeline, Coverage, Evidence, Redaction, Retention, Exports, row history, correlation id, saved timeline search, system health, scoped view.
- Error messages must name the failed field and next action. They render as `role="alert"` near the relevant launcher and must not navigate.

## Shell Navigation Interaction Contract

Global structure:

- Every mounted `/audit` operator page with a `base_path` renders one global navigation surface: `<nav class="tl-shell-nav" data-testid="operator-nav-shell" aria-label="Audit navigation">`.
- The brand link remains the Home affordance with `aria-label="Threadline operator home"` and `href` equal to the active base path.
- The first keyboard stop remains `.tl-skip-link` with text `Skip to main content`; Enter moves focus to `<main id="tl-main" tabindex="-1">`.
- There is exactly one `aria-current="page"` in the shell nav for the active page. Drill-down breadcrumbs must not create a second page-current marker.
- `Overview` appears before grouped nav destinations and maps to `/audit`. It is active when `current={:start}`.

Desktop/tablet contract:

- At `min-width: 768px`, the nav is visibly present as the left rail without requiring disclosure interaction.
- The nav rail width stays within `minmax(196px, 232px)` unless a phase task updates tests and proves labels remain readable at 768px and 1024px.
- The nav must be visible, scrollable if needed, and visually secondary to the task content. It should provide orientation, not compete with Home cards or page workflows.
- Active nav state must combine shape, border/inset, and text weight, not color alone.

Mobile contract:

- Below 768px, mobile nav remains native `<details>` plus `<summary>Audit navigation</summary>`. Do not replace it with custom JS, checkbox hacks, hidden inputs, or a drawer dependency.
- The collapsed summary is clearly labeled, keyboard reachable, and uses a visible chevron that rotates through `[open]`.
- Opening the summary reveals Overview, all enabled groups, and the theme picker in the same panel. Focus must not be obscured by the sticky topbar.
- The mobile shell must not horizontally scroll at 320px, 375px, or Pixel 5 viewport widths.

Feature-gated groups:

- `Audit readiness` appears only when Coverage is enabled.
- `Evidence & exports` appears only when at least one of Evidence, Redaction/Retention policy, or Exports is enabled.
- If a group is disabled, remove the whole group and its label. Do not render disabled links for unavailable pages.
- The theme group is always available when the shell header is rendered.

Theme picker:

- Theme choices remain native radios named `theme` with values `system`, `light`, and `dark`, plus a submit button labeled `Apply theme`.
- The selected option is indicated by the native checked state plus a non-color visual cue via existing `:has(:checked)` styling.
- The form posts to `{base_path}/theme` and includes a CSRF token. No inline event handlers, `onchange`, or client-only theme mutations.

## Home Orientation Contract

Home hierarchy:

- `/audit` is a task launcher, not an info dump. The first screen must show the Threadline shell, Home H1, short lede, system health when enabled, and at least the primary investigation job.
- The H1 remains `Follow what happened.` with lede: `Every change is connected to the action, context, and story around it. Pick where you want to start.`
- Home cards mirror shell destinations but do not duplicate the full nav. They surface top jobs in this order: Timeline, Coverage when enabled, Evidence & exports when any proof/governance destination is enabled.
- The Timeline card is primary and spans the full card row where the current grid supports it.
- Coverage and proof/governance cards are secondary. They must not visually overpower Timeline.

Task-launch paths:

- The primary investigation path is the Timeline card CTA: `Open the timeline`.
- The readiness path is the Coverage card CTA: `Check coverage`.
- Proof/governance links stay specific: `Evidence`, `Redaction`, `Retention`, and `Exports`; Exports may remain under the `Handoff` sublabel.
- Earned flow EF1 remains a direct row-history launcher with `data-earned-flow="EF1"`, `data-persona="P2"`, `data-jtbd="J4"`, a mapped-table select, record id input, and submit label `Open row history`.
- Earned flow EF4 remains a direct correlation launcher with `data-earned-flow="EF4"`, `data-persona="P1"`, `data-jtbd="J1"`, correlation id input, and submit label `Open Timeline`.
- Do not add speculative builders, advanced Timeline filters, bulk export builders, row-history pseudo-routes, correlation pseudo-routes, or generic "Get started" CTAs to Home.

System health:

- Home health uses `<div class="tl-home__health" role="status" aria-label="System health">`.
- All-clear copy is `All systems healthy`.
- Coverage-gap health copy is consequence-oriented: `Close coverage gaps before relying on timeline answers`.
- Failed export health copy stays actor-scoped and count-specific. It must not leak failures belonging to other actors.
- Failed retention health copy points to Retention and uses danger status.

Saved searches:

- The resume section heading is `Pick up where you left off`.
- When saved views exist, show actor-owned saved timeline searches as chips linking to canonical Timeline URLs.
- When empty, show only the empty-state body above. Do not render placeholder chips, disabled links, or a generic Timeline CTA in the empty state.

## Responsive and Accessibility Contract

Viewport contract:

- The shell and Home must be readable and operable at 320, 375, 768, 1024, 1280, and 1440 px.
- Existing media layers remain mobile-first with only the governed `@media (min-width: 768px)` and `@media (min-width: 1280px)` literals unless a source-contract test is updated in the same phase.
- At 320px, no Home text, nav label, chip, button, form field, or saved-view name may cause horizontal document overflow.
- At 768px and 1024px, the rail must be visible while content remains the primary work area.
- At 1280px and wider, Home can use the two-column card/earned-flow layout, but the first viewport must still reveal the task launcher and hint at the next Home section.

Keyboard and focus:

- Tab order starts at skip link, then main page controls or nav according to browser flow; no hidden focus traps.
- Focus rings use existing `--tl-focus-ring` or equivalent token-backed focus styling and must be visible in dark/light/system.
- Mobile summary, nav links, theme radios, Apply theme, Home CTAs, Home forms, saved-view chips, and health links are all keyboard reachable.
- The active nav item can receive focus and remain visible in the rail or opened mobile panel.
- Error alerts for Home launchers appear near the submitted form and do not steal focus unless an implementation task explicitly adds tested focus repair.

Motion:

- Use existing motion tokens only: fast 120ms, base 180ms, slow 240ms.
- Shell/Home motion must be transform/opacity-oriented and reduced-motion aware through existing CSS.
- Do not add decorative animation, `transition: all`, extra keyframes, scroll-driven effects, or attention-grabbing nav motion.

## Verification Contract

Required source-level verification:

- Surface header tests prove the grouped shell IA, current-state contract, feature-gated groups, theme picker form, and preserved header affordances.
- Copy contract tests prove shell group labels and Home job-card titles stay exact and unsafe vocabulary stays out of primary shell/Home copy.
- Style contract tests prove mobile `<details>` nav, token-backed sticky offsets, active nav state styling, `100svh`, no checkbox nav hack, and allowed breakpoint literals.
- StartLive tests prove Home orientation, health states, actor-scoped saved views, earned-flow launchers, validation copy, canonical navigation, scoped view affordance, and theme rendering.

Required browser verification:

- Desktop nav perception: at 1280px and 1024px, assert the nav rail is visible without opening a disclosure, current item is visible, and Home remains visually task-led.
- Tablet nav perception: at 768px, assert the rail is visible, readable, scrollable if needed, and does not squeeze Home launchers into horizontal overflow.
- Mobile nav perception: at 320px and 375px, assert native summary is labeled `Audit navigation`, opens with keyboard and pointer, exposes enabled destinations and theme controls, and keeps focus visible.
- Home task-launch flows: assert `Open the timeline`, `Check coverage`, EF1 row-history lookup, EF4 correlation lookup, saved-view resume, and health links navigate to the expected stable routes or show the specified error copy.
- Theme coverage: run at least dark default and the existing desktop light/system lane; assertions must cover active nav state, selected theme option, topbar status, Home cards, and error alerts.
- Overflow and focus: browser tests must assert no horizontal overflow after nav open, Home form validation, route transitions, and representative destination navigation.

Browser test names may build on existing suites such as `operator-home-nav-mobile.spec.ts`, `operator-accessibility.spec.ts`, `operator-earned-flows.spec.ts`, and responsive/mobile-first tests. Add new tests only where existing suites do not cover Phase 183 success criteria.
