# Phase 187 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 187 is a proof, documentation, and adversarial closeout phase over the already-polished v1.38 operator UI. It must not redesign pages, add operator capabilities, change routes or stable `data-testid`s, alter capture/query/auth/export semantics, add a public component API, add Tailwind/shadcn, introduce a new UI dependency, or broaden screenshot ownership.

Sources: `.planning/REQUIREMENTS.md` A11Y-01, A11Y-02, MOTION-01, DOC-01, and CLOSE-01; `.planning/ROADMAP.md` Phase 187 success criteria; `.planning/phases/187-accessibility-motion-docs-and-adversarial-closeout/187-CONTEXT.md`; `.planning/phases/187-accessibility-motion-docs-and-adversarial-closeout/187-RESEARCH.md`; `lib/threadline/operator_surface/style.ex`; `lib/threadline/operator_surface/ui.ex`; `lib/threadline/operator_surface/components/surface_header.ex`; prior Phase 184-186 UI specs.

## Spacing Scale

Declared values are multiples of 4 and must map to existing `--tl-*` tokens where available.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Focus offset checks, icon gaps, copy-button internals, compact status spacing |
| sm | 8px | Button/icon gaps, inline metadata gaps, nav/theme option spacing, alert/status internals |
| md | 16px | Default stack gap, panel padding, table/card padding, browser-proof target spacing |
| lg | 24px | Workflow section breathing room, modal/drawer form spacing where existing CSS already uses it |
| xl | 32px | Major section gaps through `--tl-gap-section`; closeout artifact section rhythm |
| 2xl | 48px | Large page breaks only where existing `--tl-space-12` already exists |
| 3xl | 64px | Standard upper-bound scale value; do not add a new Phase 187 CSS token for this value |

Exceptions: existing operator CSS uses `--tl-space-3` (12px), `--tl-space-5` (20px), `--tl-space-10` (40px), `--tl-hit-area: 40px`, compact controls at 32px, chips at 24px/22px, and drawer width at 760px. Preserve these inherited values. New or repaired source in Phase 187 should prefer existing semantic gaps: `--tl-gap-inline` (8px), `--tl-gap-stack` (16px), and `--tl-gap-section` (32px).

Phase 187 spacing rules:

| Surface | Contract |
|---------|----------|
| Keyboard/focus proof | Assert existing controls keep at least `--tl-hit-area: 40px` where intended. Do not reduce hit targets to make tests pass. |
| Modal/dialog proof | Retention modal and stress modal must keep title, description, initial focus target, close/cancel, and submit visible without overlap at 375px. |
| Drawer proof | Row-history drawer and stress drawer keep existing `--tl-drawer-width: 760px` and mobile width bounded to the viewport. Focusable controls must not be hidden behind fixed chrome. |
| Docs/closeout artifacts | Use compact markdown sections. Evidence tables should be scannable and not create decorative dashboard layouts. |
| Screenshot boundary | Do not add layout padding or baseline masks only to quiet screenshot churn. Classify visual failures instead. |

## Typography

Use exactly these four Phase 187 text sizes and two declared weights for any new or retuned user-facing copy. Existing private component internals that already use 12px, 13px, 15px, 32px, or weight 500 may remain, but do not create new Phase 187 text roles around those values.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label / metadata | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Title | 24px | 600 | 1.2 |

Typography rules:

- Normal letter spacing is `0`. Existing caps tracking may remain only on inherited compact labels.
- Use Title for modal/drawer/detail titles, Heading for sections, Body for evidence and consequence copy, and Label for metadata keys, chips, table labels, and compact button text.
- Use IBM Plex Mono only for exact refs, IDs, schema/table names, policy name `default`, command snippets, exported file metadata, exact timestamps, and copied technical values.
- Long refs must use existing wrapping/truncation and copy-full contracts: `UI.ref/1`, `Presentation.ref/2`, or `Presentation.value_token/1`. Never rely on CSS ellipsis for the only visible/copyable value.
- Do not add hero/display-scale typography in Phase 187. This phase closes proof; it does not reframe the product.

## Color

Use the existing dark-primary operator palette with light/system token branches preserved.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Dark `#0B1020` via `--tl-color-bg`; light `#F7F9FC` | Shell and page background |
| Secondary (30%) | Dark `#141B2D` / `#1B253A`; light `#FFFFFF` / `#EEF3FA` | Page headers, panels, tables, dialogs, drawers, nav surfaces, closeout evidence surfaces |
| Accent (10%) | Dark `#4F8CFF`; light `#1557C0` | Focus rings, current/selected state, primary links/actions, valid route pivots, `Apply theme`, Coverage `Apply schema`/`Refresh`/`Use public schema`, valid export queue/download actions |
| Destructive | Dark `#FF8585`; light `#A33434` | Retention prune action, destructive confirmation, failed/destructive states only |

Accent reserved for: focus-visible rings/borders, active shell nav, selected theme/schema/filter state, `Apply theme`, Timeline route pivots, Coverage refresh/schema recovery, valid `Queue Timeline export`, valid `Download export`, `Open transaction`, `Open row history`, `Open timeline`, and copy success affordances when existing Signal treatment already applies. Accent is not decoration and must not color every control, metric, card title, or trust rail.

Additional semantic colors:

| Semantic | Token | Reserved for |
|----------|-------|--------------|
| Signal | `--tl-color-signal` | Copy success, correlation/live trace cues, positive system flow only |
| Warning | `--tl-color-warning-*` | Stale/reconnect states, capped results, retention consequence context, readiness caution |
| Success | `--tl-color-success-*` | Ready/covered/completed states only |
| Info | `--tl-color-info-*` | Neutral status, queued/running export state, non-blocking context |
| Danger | `--tl-color-danger-*` | Failed exports, invalid context, destructive consequences, prune errors |

Color never carries status alone. Status must also include text, shape/icon, stripe, chip label, role-specific copy, or accessible name.

## Copywriting Contract

Phase 187 should not introduce new operator-product copy except focused repairs to documentation, tests, and closeout artifacts. If a source repair changes visible UI copy, it must preserve the phase-specific contracts from Phases 183-186.

| Element | Copy |
|---------|------|
| Primary CTA | `Review verification` for Phase 187 closeout artifacts; no new primary CTA in the operator UI |
| Empty state heading | `No residual failures recorded` for closeout artifacts when all targeted checks pass |
| Empty state body | `Targeted Phase 187 verification passed without in-scope residuals. Keep the command log with this closeout.` |
| Error state | `Verification failed. Record the failing command, owner, impact, and next action before closing the requirement.` |
| Destructive confirmation | No new destructive actions. Retention remains the only destructive flow and keeps `Prune retention window permanently?`, `Type the policy name default to confirm`, `Keep retention window`, and `Prune records permanently`. |

Required docs truth repairs:

| Topic | Required copy contract |
|-------|------------------------|
| Runtime theme picker | Docs must say the operator surface supports a runtime server-posted dark/light/system theme picker through `POST {base_path}/theme`, native radios, CSRF token, cookie/session/plug resolution, no JavaScript, and no `localStorage`. |
| Theme default | Docs must still state dark is the brand-primary default and `:system` resolves from `prefers-color-scheme` through `data-tl-theme`. |
| Storybook dev lane | Docs must say PhoenixStorybook lives only in `examples/threadline_phoenix` dev/test maintainer tooling and is not a root `threadline` dependency or production route. |
| Stress route | Docs must say `/audit/__stress` is the authenticated operator-flow stress harness, not a production public component gallery. |
| Export gates | Docs must say direct HTTP export routes remain protected by server/controller/auth-plug behavior even if LiveView hides affordances. |
| Coverage selected schema | Docs must describe URL-addressable schema selection, invalid schema recovery, non-public Timeline links, stale last-good behavior, and `mix threadline.verify_coverage --schema=NAME`. |
| CSP | Docs must keep the shell/theme picker CSP-clean: no inline handlers, no client storage requirement, and no `script-src 'unsafe-inline'` requirement for the theme picker. |
| Production exclusions | Docs must state Storybook is dev-only, the stress route is authenticated/maintainer-focused, root Phoenix/LiveView remains optional, and no public component API is created. |

Voice rules:

- Use Threadline nouns exactly: Timeline, transaction, row history, actor, correlation id, Coverage, Evidence, Exports, Redaction, Retention, export job, retention run, policy name, audit readiness.
- Be precise and calm. Name the object, failure, owner, and next action.
- Do not use hype, sales framing, SIEM/compliance-suite language, screen-reader certification claims, exclamation marks, or vague verbs such as `Continue` for destructive actions.
- Do not mark A11Y-01, A11Y-02, MOTION-01, DOC-01, or CLOSE-01 complete by assertion. Completion copy must point to evidence.

## Accessibility And Interaction Contract

Phase 187 must prove the current UI contracts rather than inventing new ones.

### Required User Flows

| Flow | Required proof |
|------|----------------|
| Investigation | Home launcher, shell nav, skip link, Timeline filters, Timeline rows, transaction route, row-history route or drawer, route pivots, copy controls, and pager controls are keyboard-operable with visible non-obscured focus. |
| Readiness | Coverage schema picker, `Apply schema`, `Refresh`, invalid-schema recovery, row disclosures, covered-row Timeline links, and stale last-good state are keyboard-operable and correctly named. |
| Export | Timeline/Evidence handoff to Exports, queue action, valid download links, unavailable download states, failure recovery, and direct HTTP route boundaries are pointer/keyboard/AT-correct. |
| Retention | `Run retention prune`, modal open, initial focus, type-to-confirm input, cancel, Escape, submit, mismatch/runtime error, reconnect mutating state, and focus return to opener are proven. |
| Shell/theme | Desktop/tablet nav, mobile native navigation disclosure, skip link to `#tl-main`, topbar coverage status, scoped view, and runtime theme picker are visible, named, and keyboard reachable. |

### Focus Rules

| Case | Contract |
|------|----------|
| Global focus | `.threadline-ui` focus styles use `--tl-focus-ring`; do not weaken ring contrast or remove `:focus-visible` selectors. |
| Skip link | First Tab exposes `Skip to main content`; activation focuses `#tl-main`. |
| Mobile nav | Native disclosure remains keyboard reachable and focus is not hidden behind sticky topbar/nav. |
| Dialog/drawer open | Focus moves inside through existing `JS.focus_first` and `data-tl-initial-focus` contracts. |
| Dialog/drawer close | Escape, close, cancel, and click-away restore focus to the invoker through existing `JS.pop_focus` or equivalent. |
| Copy controls | Every copy button has a specific accessible name and visible focus. It copies the full source value, not visible truncation. |
| Error/focus rescue | Error summaries and hard-error states may focus a heading/summary with `tabindex="-1"`; this must not create a hidden or dead focus target. |
| Non-obscured focus | Browser proof must assert focused control geometry is visible and not covered by topbar, drawer, modal, toast, or sticky elements. |

### APG And Native Control Rules

| Widget family | Contract |
|---------------|----------|
| Modal/dialog | `role="dialog"`, `aria-modal="true"`, labelled title, described body where present, Escape/click-away/close, initial focus, focus restoration. |
| Drawer | Same dialog contract as modal; drawer content remains visible and usable at 320/375px. |
| Dropdown/menu | Trigger has `aria-haspopup="menu"`, `aria-expanded`, and menu has `role="menu"` with named items. Primary row actions must not be hidden only in menus. |
| Popover/tooltip | Trigger/name relationship uses `aria-controls`/`aria-describedby` as appropriate; tooltip content uses `role="tooltip"`. |
| Tabs | `role="tablist"`, `role="tab"`, `aria-selected`, and `aria-controls` remain paired. |
| Segmented controls | Use existing `role="group"` plus pressed/active state. State cannot rely on color alone. |
| Accordion/disclosure | Custom accordion uses `aria-expanded` and labelled region. Native `<details>/<summary>` stays native where used. |
| Combobox/listbox | Existing combobox keeps `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-autocomplete`, listbox, and option roles only where the current UI already uses it. |
| Native controls | Do not role-inflate native `<select>`, `<input>`, `<button>`, `<a>`, `<table>`, `<details>`, `<summary>`, or forms. |

Accessibility evidence must use existing source contracts plus rendered Playwright role/name/keyboard/focus checks. Accessibility-tree snapshots are allowed proof. Real screen-reader certification is out of scope unless explicitly performed and recorded.

## Motion Contract

| Interaction | Contract |
|-------------|----------|
| Default motion | Use existing tokens only: `--tl-motion-fast: 120ms`, `--tl-motion-base: 180ms`, `--tl-motion-slow: 240ms`, `--tl-ease-standard`, and `--tl-ease-out`. |
| Overlay/drawer/modal | Opacity and transform transitions only; no layout-shifting motion and no new overlay keyframes. |
| Dropdown/popover/accordion/details | Existing compositor-safe open/close behavior remains; proof uses computed styles in Chromium. |
| Toast/copy feedback | Existing Signal treatment and short fade/transform feedback remain allowed. |
| Button press | Existing subtle press feedback is allowed; disabled/mutating controls must not animate into a misleading enabled state. |
| Home signature motion | Existing tokenized motion may remain, but reduced-motion proof must verify collapse. |
| Reduced motion | `prefers-reduced-motion: reduce` collapses positional transforms and durations while keeping UI visible and usable. Do not use source-only proof if behavior changed. |
| Prohibited | `transition: all`, unapproved keyframes, motion libraries, decorative animation, row/card entrance animations, gradient/orb motion, scroll-jacking, or per-page experiments. |

MOTION-01 closure requires both source and browser evidence unless the executor proves no browser-observable motion path changed. `style_contract_test.exs` remains the source authority. `operator-motion.spec.ts` remains the browser computed-style authority.
