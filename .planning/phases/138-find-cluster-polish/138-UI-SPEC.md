## Visual Hierarchy

Primary focal point: the operator's current investigation handle and next pivot, not page chrome or raw identifiers.

| Surface | Focal Point | Secondary Scan | Background |
|---------|-------------|----------------|------------|
| Timeline | Filtered result set and active investigation context | Operation, table, actor, correlation, transaction action | Orientation rail, coverage warning, export side actions |
| Transaction | Transaction identity plus row-level diff content | Actor, correlation, table, primary key, row-history action | Breadcrumbs and explanatory lede |
| Row-history | As-of timestamp and row snapshot/delta values | Row timeline, operation chips, unavailable-state reason | Drawer shell and close affordance |
| Actor | Actor identity and touched-record blast radius | Time-window selector, operation/table/change-count per transaction | Timeline/export links and empty-window guidance |
| Coverage | Capture gap and direct remediation | Table name, status, View activity / fix action | Repeated consequence copy |

Hierarchy rules:

| Rule | Contract |
|------|----------|
| One active handle | Each Find surface must expose exactly one active handle at first scan: filter summary on Timeline, transaction id on Transaction, as-of row id on Row-history, actor ref on Actor, table gap on Coverage. |
| Diff first | Transaction and Row-history are diff/value surfaces. Mono values may be prominent inside the diff/KV panel, but IDs and navigation labels remain secondary. |
| Pivot clarity | Timeline rows, Transaction rows, and Actor rows must expose the next investigation pivot in consistent compact secondary-button weight: `Open transaction`, `Open row history`, or `Open in timeline`. |
| Correlation treatment | Correlation IDs use Signal Cyan emphasis only for the correlation/as-of/thread-path concept; they still use middle truncation, full `title`, and copy affordance when interactive. |
| Empty recovery | Empty states must name the likely recovery path: widen time range, clear table filter, choose a longer actor window, configure schema mapping, or add capture. |
| Mobile pressure | Timeline's dense/mobile contract is local to Phase 138: make dense rows scannable, truncate long values, and avoid first-scan elements that make results look missing. Full nav/mobile architecture remains Phase 142. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline value gaps, copy-button gaps, compact diff separators |
| sm | 8px | Compact row spacing, chip/button gaps, toolbar hints |
| md | 16px | Default element spacing, row groups, panel padding |
| lg | 24px | Section padding, toolbar-to-content separation |
| xl | 32px | Layout gaps, summary-to-results separation |
| 2xl | 48px | Major section breaks and compact hero spacing |
| 3xl | 64px | Page-level spacing only |

Exceptions: none. Existing intermediate legacy tokens such as 12px, 20px, and 40px may remain in `style.ex`, but new Phase 138 layout decisions must map to the declared 4/8/16/24/32/48/64 contract unless preserving an existing control-size token.

Control-size contract:

| Token | Value | Usage |
|-------|-------|-------|
| control | 40px | Inputs, filter controls, primary/secondary buttons, nav hit targets |
| compact-control | 32px | Dense row actions, compact export links, segmented-control items |
| chip | 24px | Status, operation, filter, coverage, and assertion chips |
| copy-hit | 32px | Copy affordance beside IDs; visually compact but keyboard reachable |
| row-status | max-content | Mobile stacked badges/chips; never stretch status chips to full width |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.4 |
| Heading | 18px | 600 | 1.2 |
| Display | 28px | 400 | 1.15 |

Typography rules:

| Element | Contract |
|---------|----------|
| Page titles | Keep existing Find titles unless this phase touches the heading: Timeline `Investigate audit activity`; Transaction `Transaction <id>`; Actor `Actor: <type> / <id>`; Row-history `Row history: <table> / <record>`. Use middle-truncated visible IDs with full `title`. |
| CTA labels | Use verb+noun copy: `Apply filters`, `Clear filters`, `Queue export`, `Open transaction`, `Open row history`, `Open in timeline`, `Add capture`, `Copy transaction id`, `Copy correlation id`. |
| IDs and refs | Use mono font, middle truncation, full `title`, and copy affordance where interactive. Do not use hard prefix-only truncation for UUIDs, actor refs, record ids, correlation ids, or `schema.table` names. |
| Diff/KV values | Use mono body/label sizes with semantic formatting: muted `null`, formatted timestamps, quoted strings only when the quote is meaningful to the data, and before/after values separated by an explicit arrow. |
| Toolbar hints | Use 12px body/label treatment, regular weight unless the hint names a disabled reason. |
| Empty and error text | Use body size and regular weight. Empty/error headings use Heading size and must not compete with active transaction or actor handles. |

Only the four sizes above may be introduced during this phase. Existing `--tl-font-size-xs`, `--tl-font-size-ui`, and `--tl-font-size-title` may remain in the legacy stylesheet but must not create a new hierarchy.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B1020` | Page background and dark-only brand base |
| Secondary (30%) | `#141B2D` / `#1B253A` | Cards, panels, toolbars, drawers, tables, rows, and raised surfaces |
| Accent (10%) | `#4F8CFF` | Text links, active segmented state, focus affordance, `Apply filters`, non-destructive primary action slots |
| Destructive | `#FF8585` | Coverage/capture failures, invalid filters, deleted-row states, and destructive confirmation copy only |

Accent reserved for: text links, focus ring, active nav item, active segmented item, `Apply filters`, non-destructive primary action slots, and explicit deep links. Never use Thread Blue for operation status, verdict posture, warning copy, unknown actor, null values, or generic row metadata.

Signal Cyan (`#4EDFD1`) remains reserved for correlation IDs, as-of/thread-path emphasis, selected Row-history timeline point, and positive system-flow traces. Do not use it as a generic second accent.

Semantic status map:

| Concept | Canonical Treatment |
|---------|---------------------|
| INSERT / created | Success operation chip plus success row stripe only when row operation is the status owner |
| UPDATE / changed | Info operation chip; do not let info blue look like a link by omitting underline/action affordance |
| DELETE / removed | Danger operation chip and deleted-record empty/snapshot treatment |
| Coverage captured | Success text, success border, soft success background |
| Coverage missing / expected gap | Warning or muted-but-distinct treatment with remediation copy; never neutral bare text |
| Unknown actor / unavailable id | Muted neutral label such as `Actor unknown`; never the same weight as real actor refs |
| Invalid filter / unmapped schema / failed load | Danger alert with recovery path |
| Null value | Muted inline `null` token, not raw `nil` |

## Primitive Contract

| Primitive | Contract |
|-----------|----------|
| Secondary ref | Reuse `Presentation.secondary_ref/2` and `.tl-secondary-ref` for actor refs, subject refs, transaction IDs, record IDs, correlation IDs, and long table names when they are secondary metadata. |
| Copy affordance | Use existing dependency-free `[data-tl-copy]` / `.tl-copy`. Copy buttons must read as enabled secondary controls, not disabled grey text. |
| Operation chip | Use the shared INSERT/UPDATE/DELETE operation modifier everywhere operations appear, including Row-history timeline links and Actor rows. |
| Diff row | Transaction diffs and Row-history snapshots must converge on one mono value/KV/diff treatment. Empty INSERT diffs render inserted column values when available; otherwise show diagnostic empty copy, not a blank card. |
| Timeline row | First line: operation chip, table, time. Second line: actor and correlation with truncation/copy. Action slot: one compact secondary `Open transaction`; add `Open row history` only where a row-level target is unambiguous. |
| Actor transaction row | Must include operation summary, table name, and change count before the transaction id. Rows should not be visually identical when blast radius differs. |
| Segmented control | Active Actor window uses `[aria-pressed="true"]` Thread Blue selected treatment already present in Phase 136; inactive items remain neutral. |
| Date/as-of control | `datetime-local` controls use dark surface, readable text, focus ring, and Signal Cyan only for the as-of axis/selected point. |
| Alert | Invalid filter and schema-mapping errors use inset `tl-alert` spacing inside the current content width. Message includes the exact recovery path. |
| Empty state | Diagnostic heading plus next action. No generic `No data found`, `No results`, or `Nothing here`. |
| Coverage action | Coverage uncovered rows get one real remediation action or CLI snippet. Repeated consequence copy moves to section/callout level, not every action cell. |
| Content column | Transaction short-result layouts constrain the content column and keep the row card near the header; do not leave a single change card floating above a massive empty viewport. |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Apply filters |
| Empty state heading | No captured changes match this window |
| Empty state body | Widen the time range, or clear the table filter to search every audited table. Scoped views only show records you are authorized to see. |
| Error state | Timeline filters could not be applied. Fix the highlighted value, then apply filters again; correlation IDs may be up to 256 characters. |
| Destructive confirmation | none |

Surface-specific copy:

| Surface | Title | Empty Heading | Empty Body | Error / Recovery |
|---------|-------|---------------|------------|------------------|
| Timeline | Investigate audit activity | No captured changes match this window | Widen the time range, or clear the table filter to search every audited table. Scoped views only show records you are authorized to see. | Timeline filters could not be applied. Fix the highlighted value, then apply filters again. |
| Timeline future window | Investigate audit activity | No captured changes in this time window | This window has no matching changes, but Threadline has audit data outside it. Move the window back toward recent activity or clear filters. | Same as Timeline. |
| Transaction | Transaction `<id>` | No row-level changes recorded | Threadline found the transaction, but no row-level field changes were captured for it. Check capture coverage for this table, then return to Timeline. | Transaction not found. The transaction may not exist, may be outside your scope, or may have been purged by retention. Return to Timeline. |
| Row-history | Row history: `<table>` / `<record>` | Record did not exist at this time | Choose a later as-of time from the row timeline, or return to the transaction that created the record. | Row history could not be loaded. Confirm the table is mapped to an Ecto schema in operator surface configuration. |
| Actor | Actor: `<type>` / `<id>` | No events in this window | Choose a longer window, or open this actor in Timeline to combine actor and table filters. | Invalid actor reference. Return to Timeline and choose an actor link from a captured row. |
| Coverage | Coverage | Capture missing for this table | Add the capture trigger or confirm this is an expected gap, then use View activity to inspect existing rows. | Coverage could not be loaded. Re-run trigger coverage and verify repository connectivity before trusting Timeline completeness. |

Destructive actions in scope: none. Existing saved-view deletion is already in Timeline but is not a Phase 138 visual focus; preserve its current ghost-danger/icon treatment and do not introduce a new destructive flow.

## Audit Finding Closure Contract

| Finding | Required UI Decision |
|---------|----------------------|
| F-201(render) | Transaction INSERT rows render inserted column values when `field_changes` exists; if no fields exist, show diagnostic empty copy tied to coverage, not a blank diff area. |
| F-401 | Timeline empty copy uses the widening/clear-table recovery nudge. |
| F-402 | Future-window empty state explains that data exists outside the selected window when true. |
| F-403 | FIND / EXPLAIN / PACKAGE journey strip must either deep-link to real destinations or be visually demoted to a caption/legend that cannot be mistaken for stat cards. |
| F-404 | Disabled Actor id input for anonymous actor kind includes inline `n/a for anonymous` hint. |
| F-405 | Long correlation IDs and `schema.table` names use middle ellipsis, full `title`, and copy affordance where interactive. |
| F-501 | Coverage uncovered rows include a real remediation affordance: CLI snippet, Add capture guidance, or equivalent fix link. |
| F-502 | Repeated `Timeline may be incomplete` copy moves out of each row action cell into section/callout copy; action cells contain actions only. |
| F-504 | Expected-gap coverage/evidence treatment is deliberate muted/warning semantic styling, not neutral unstyled text. |
| F-505 | Expected-gap footer copy uses correct singular/plural grammar. |
| F-701 | Transaction and Actor UUID-like values use middle truncation with full `title` and copy affordance; no hard prefix truncation. |
| F-702 | Transaction short-result pages use a constrained content column and short-content treatment. |
| F-703 | Actor rows add operation color, table name, and change count so blast radius is visible without opening every transaction. |
| F-704 | Actor time-window segmented control exposes selected state via `[aria-pressed="true"]` Thread Blue active styling. |
| F-705 | Transaction copy control uses enabled secondary copy styling distinct from disabled controls. |
| F-706 | Row-history snapshot values render muted `null` and formatted timestamps instead of raw `nil` and quoted ISO strings. |
