# Phase 181 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 181 is a baseline audit and guard-repair phase. It establishes current rendered truth for `/audit`, repairs stale verification when the fix restores an accepted invariant, and records owned findings for later page polish. It must not redesign Shell, Home, Timeline, Coverage, detail pages, governance pages, motion, or copy hierarchy.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - shadcn gate not applicable because Threadline is Phoenix LiveView, not React/Next/Vite |
| Preset | not applicable |
| Component library | Private Phoenix function components in `Threadline.OperatorSurface.UI` plus `SurfaceHeader`; no external UI component library |
| Icon library | Internal inline SVG icons via `Threadline.OperatorSurface.Components.Icon`; no package dependency |
| Font | Geist for UI text; IBM Plex Mono for refs, code, and technical anchors |

Source: `181-CONTEXT.md` D-181-06, D-181-16; `181-RESEARCH.md` Standard Stack; `lib/threadline/operator_surface/style.ex`; `brandbook/tokens.json`.

Design-system contract:

- Use the existing `.threadline-ui` scoped CSS and `--tl-*` tokens. Do not add Tailwind, shadcn, Radix, Storybook UI runtime dependencies, or root package dependencies in this phase.
- Use existing private components before page-specific markup: `page_header`, `stack`, `cluster`, `data_panel`, `toolbar`, `detail_header`, `empty_state`, `error_state`, `loading_state`, `stale_banner`, `ref`, `kv`, `data_table`, `pager`, `modal`, `drawer`, `toast`, and `surface_header`.
- Preserve dark-primary theming with light/system lanes through server-resolved `data-tl-theme`. No localStorage theming, no JS theme flash, no decorative consumer-app effects.
- Keep `/audit/__stress` as the authenticated operator-flow stress harness. PhoenixStorybook remains Phase 182 example-app dev/test work only.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, dense inline offsets, compact control vertical padding |
| sm | 8px | Default inline gaps, button icon gap, cluster gap |
| md | 16px | Default stack gap, panel padding, page padding |
| lg | 24px | Detail-header breaks, larger form/section separation |
| xl | 32px | Section gaps, audit packet grouping, major page blocks |
| 2xl | 48px | Large page breaks where already supported by existing tokens |
| 3xl | 64px | Reserved page-level spacing from brand token scale; do not introduce a new `style.ex` token in Phase 181 |

Exceptions: Existing `style.ex` tokens `--tl-space-3` (12px), `--tl-space-5` (20px), and `--tl-space-10` (40px) may remain where already used. New Phase 181 work should not create additional spacing tokens. Hit targets stay on the current `--tl-hit-area: 40px`; compact controls stay at `--tl-control-height-compact: 32px`; chip and badge heights stay existing unless a later accessibility phase explicitly changes them.

Interaction spacing rules:

- Use `--tl-gap-inline` (8px), `--tl-gap-stack` (16px), and `--tl-gap-section` (32px) for new audit-packet or stress evidence layouts.
- Do not nest cards inside cards. Audit findings should be direct rows, tables, panels, or single-card units.
- New semantic hooks such as `data-testid` or `aria-*` must not change layout rhythm.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | regular 400 | 1.5 |
| Label | 14px | semibold 600 | 1.4 |
| Heading | 20px | semibold 600 | 1.2 |
| Display | 32px | semibold 600 | 1.15 |

Typography rules:

- Phase 181 declares only 400 and 600. Existing grandfathered component use of other weights may remain, but do not add new standalone 500-weight text in this phase.
- Use mono only for refs, IDs, SQL-ish commands, route paths, file paths, policy names, and copied technical anchors.
- Letter spacing is `0` for normal text. Caps labels may use the existing caps tracking only where the component already does.
- Do not add hero-scale type, marketing copy, or broad explanatory UI text to operator pages.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Dark: `#0B1020` / `--tl-color-bg`; Light: `#F7F9FC` | Page background and shell ground |
| Secondary (30%) | Dark: `#141B2D` and `#1B253A`; Light: `#FFFFFF` and `#EEF3FA` | Cards, nav, panels, tables, modals, audit evidence surfaces |
| Accent (10%) | Dark: `#4F8CFF`; Light: `#1557C0` | Primary commands, active/current navigation, deep links, selected states, focus-adjacent borders, Threadline mark stitch in UI |
| Destructive | Dark: `#FF8585`; Light: `#A33434` | Destructive actions only, especially retention prune confirmation and failed/destructive status evidence |

Accent reserved for: primary buttons, active nav/current state, focused/selected controls, deep links, current-view export affordances, and the Threadline mark stitch when rendered by the UI component. Do not use accent as generic decoration, card tint, or screenshot/audit-packet ornament.

Semantic color rules:

- Keep existing warning, success, info, signal, and neutral tokens for status meanings already present in the operator surface.
- Use Signal Cyan only for correlation/live-trace/copy-confirmation style signals, not as a second generic accent.
- Use destructive color only when the object or action can fail, delete, prune, deny, or represent irreversible risk.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | No new operator-facing CTA. If a maintainer-only Phase 181 audit control is added: `Refresh baseline evidence` |
| Empty state heading | `No baseline findings recorded` |
| Empty state body | `Run the rendered audit before planning page polish.` |
| Error state | `Baseline audit could not complete. Re-run the failing check and record the command in 181-GUARD-REPAIR.md.` |
| Destructive confirmation | No new destructive action. Existing Retention flow remains: `Prune retention window permanently?` plus `Type the policy name default exactly`; submit copy `Prune records permanently` |

Copy rules:

- Use Threadline's current voice: calm, exact, plain, technically literate, and useful over impressive.
- Preserve canonical nouns: Audit Action, Audit Transaction, Audit Change, Actor, Subject, Request, Job, Correlation, Coverage, Evidence, Redaction, Retention, Export, Saved View, Timeline Entry, Diff, Snapshot.
- Preserve canonical UI verbs: filter, scan, open, copy, compare, refresh, remediate, queue export, download, confirm destructive action, return.
- Hide backend details from operators unless needed for remediation, proof, or performance constraints; expose technical anchors as secondary raw details, copyable refs, commands, or docs links.
- Do not rewrite page IA, CTA strategy, or page-level copy polish in Phase 181. Record findings to the audit packet with later-phase owners.

## Phase Interaction Contract

Allowed UI-affecting changes in Phase 181:

- Update stale E2E selectors to current stable `data-testid`, role, label, URL, or rendered behavior.
- Retire removed contracts only with rationale, replacement, and later-phase owner in `181-GUARD-REPAIR.md`.
- Repair `/audit/__stress` fixtures, ledger rows, `DESIGN-SYSTEM.md`, screenshot allowlist references, and projection freshness without lowering ratchets.
- Add focused source-contract tests for routes, feature gates, stable IDs, optional dependencies, auth/export/stress boundaries, and no-production stress/story exposure.
- Add missing semantic guard hooks only when additive and non-redesign, such as a missing `data-testid`, `aria-current`, accessible label, or status role.

Prohibited UI-affecting changes in Phase 181:

- No Shell/Home/Timeline/Coverage visual hierarchy changes, layout redesign, CTA strategy changes, copy polish, or design-approved screenshot rebaselining.
- No route path changes and no `data-testid` renames/removals unless a later phase explicitly records and verifies the breaking change.
- No capture/query/auth semantic changes, public component API, root PhoenixStorybook dependency, production Storybook/stress route, Tailwind/shadcn migration, or runtime destructive redaction.

Locator and guard contract:

- Prefer Playwright role, label, and URL/rendered behavior locators for user-facing semantics.
- Use `getByTestId` when the stable ID itself is the contract.
- Source contracts and semantic browser checks must accompany screenshots for route/auth/a11y/motion claims.

## State And Accessibility Contract

State rendering:

- Loading uses `loading_state` with `role="status"` and `aria-busy="true"`; default copy stays `Loading audit changes...`.
- No-data, permission, unavailable, redacted, pruned, source-down, and generic error states must stay visually and semantically distinct by role, icon shape, heading, and body copy.
- Stale data uses `stale_banner` above still-visible last-good data; it must not replace the data region.
- Permission and source-down states use `role="alert"` where the current component contract already does.

Keyboard and focus:

- Keep visible `--tl-focus-ring` on buttons, links, inputs, selects, summaries, and custom controls.
- Modal/drawer changes must use existing LiveView JS helpers and focus restoration patterns.
- Additive hooks must not create keyboard traps, remove native semantics, or hide focus behind sticky shell elements.
- Disabled or reconnecting mutating controls must keep real disabled/`aria-disabled` enforcement, not dimming alone.

Motion:

- Use only existing motion tokens: fast 120ms, base 180ms, slow 240ms.
- Motion must be transform/opacity-oriented and purposeful.
- No `transition: all`, decorative animation, new keyframes, or new motion tokens in Phase 181.
- Reduced motion keeps the existing collapse behavior and removes positional transforms.

Evidence tiers:

- Tier A source/CI contracts cover 11 pages x 7 paths, themes `dark|light|system`, viewports `320|375|768|1024|1440`, ledger freshness, story/fixture parity, route/auth gates, feature gates, and no score backslide.
- Tier B rendered CI slices cover overflow, nav, and header behavior for all real `/audit` pages at 320 and 1440; Shell/Home/Timeline/Coverage also cover 375, 768, and 1024 where specified.
- Tier C local/human packet captures all 11 real pages at desktop 1280 and mobile 375, plus light desktop for Shell/Home/Timeline/Coverage and selected stress stories for happy/error/permission/boundary states.

Issue taxonomy:

- JTBD/IA drift
- stale selector or copy contract
- screenshot or ledger drift
- accessibility/focus/motion proof gap
- route/auth/feature-gate invariant gap
- later-phase polish follow-up
