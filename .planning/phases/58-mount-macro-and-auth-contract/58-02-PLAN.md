<objective>
Implement the compile-time AST checking in the Router mount macro to ensure fail-closed secure defaults.

Purpose: Prevent accidental exposure of the operator surface by verifying a `pipe_through` exists or an explicit `:authorize_fn` is provided. (D-01)
Output: Robust macro implementation in `Threadline.OperatorSurface.Router`.
</objective>

<feature>
  <name>Operator Surface Mount Macro</name>
  <files>lib/threadline/operator_surface/router.ex, test/threadline/operator_surface/router_test.exs</files>
  <behavior>
    - Case 1: Compiling a module that calls `threadline_operator_surface/2` without `pipe_through` or opts raises a CompileError.
    - Case 2: Compiling with `pipe_through :browser` succeeds.
    - Case 3: Compiling without `pipe_through` but with `authorize_fn: &auth/1` succeeds.
    - Case 4: Compiling without `pipe_through` but with `adopter_acknowledges_unauthenticated: true` succeeds.
    - Output: Macro injects a `live_session :threadline` mapping to `Threadline.OperatorSurface.Auth` `on_mount` hook.
  </behavior>
  <implementation>
    In `router.ex`, write a `defmacro threadline_operator_surface(path, opts \\ [])`.
    Inspect `Module.get_attribute(__CALLER__.module, :phoenix_top_scopes)`. Pattern match for `%{pipes: [_ | _]}`.
    Check `opts` for `:authorize_fn` and `:adopter_acknowledges_unauthenticated`.
    Raise `CompileError` if none of these grant access. The error description MUST be exactly: "Threadline Operator Surface must be mounted inside a secure pipeline. Add `pipe_through :admin_browser` or explicitly provide an `:authorize_fn`."
    Quote the `import Phoenix.LiveView.Router, only: [live_session: 3]` and emit `live_session :threadline, on_mount: [{Threadline.OperatorSurface.Auth, unquote(opts)}] do ... end`.
    In tests, use dynamically defined modules or `Code.compile_quoted` inside a try/rescue to capture and assert on the `CompileError` for negative paths, and successful compilation for positive paths.
  </implementation>
</feature>
