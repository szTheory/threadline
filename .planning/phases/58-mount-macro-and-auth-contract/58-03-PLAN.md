<task type="tdd">
  <name>Operator Surface Auth Hook</name>
  <files>lib/threadline/operator_surface/auth.ex, test/threadline/operator_surface/auth_test.exs</files>
  <behavior>
    - Case 1: `authorize_fn` returns `:ok` -> connection continues, telemetry `:granted` emitted.
    - Case 2: `authorize_fn` returns `{:ok, scope}` -> connection continues with socket assigned (:threadline_scope), telemetry `:granted` emitted.
    - Case 3: `authorize_fn` returns `true` -> connection continues, telemetry `:granted` emitted.
    - Case 4: `authorize_fn` returns `false`, `nil`, or any other value -> connection halts with redirect or 403, telemetry `:denied` emitted.
    - Case 5: `authorize_fn` crashes or raises -> handled gracefully via try/rescue, halts, telemetry `:error` emitted.
  </behavior>
  <action>
    In `auth.ex`, implement `on_mount(opts, params, session, socket)`.
    Extract `authorize_fn` from `opts` (passed via the macro). If missing but allowed due to pipeline checking, default to `true` or `:ok` to permit flow.
    Execute the auth function passing the `socket` (dual-contract) wrapped in a `try/rescue` block to catch crashes. Handle the return values (`:ok | true | {:ok, scope}`).
    For `{:ok, scope}`, use `Phoenix.Component.assign(socket, :threadline_scope, scope)` to thread the scope.
    In the `rescue` block, catch exceptions, halt the connection (e.g., `{:halt, Phoenix.LiveView.redirect(socket, to: "/")}`), and emit `:error` telemetry.
    Call `:telemetry.execute([:threadline, :operator_surface, :authorize], %{result: result}, %{path: path, actor_ref: actor_ref, scope_keys: scope_keys})` based on the outcome, following the telemetry dispatch pattern from `lib/threadline/telemetry.ex`. Derive `actor_ref` and `scope_keys` from the returned scope or socket assigns. Denied endpoints return `{:halt, Phoenix.LiveView.redirect(socket, to: "/")}` or similar.
    In tests, use `Phoenix.LiveViewTest` isolation primitives or direct function calls to mock the socket and assert on telemetry emissions using the `:telemetry_test` library or explicit telemetry handlers.
  </action>
  <verify>
    <automated>mix test test/threadline/operator_surface/auth_test.exs</automated>
  </verify>
  <done>Auth hook properly evaluates outcomes, handles crashes, threads scope, and emits comprehensive telemetry.</done>
