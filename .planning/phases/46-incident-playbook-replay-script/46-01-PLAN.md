# Phase 46 Implementation Plan

## Objective
Deliver Phase 46 (incident-playbook-replay-script) by providing a canonical incident playbook for support engineers, locking its promises via a doc-contract test, and shipping a guarded incident-replay script in the example application to validate these workflows under realistic conditions.

## Key Files & Context
- `guides/incident-playbook.md` (New)
- `test/threadline/incident_playbook_doc_contract_test.exs` (New)
- `examples/threadline_phoenix/priv/scripts/incident_replay.exs` (New)
- `examples/threadline_phoenix/test/threadline_phoenix/incident_replay_smoke_test.exs` (New)

## Implementation Steps

### 1. Draft the Incident Playbook
Create `guides/incident-playbook.md` structured around the five canonical incidents:
1. "who changed this row at time T?"
2. "what did service-account X do today?"
3. "did this Oban job actually mutate the DB?"
4. "what did this row look like at time T?"
5. "single-transaction drilldown"

Each section will have a locked structure: Scenario / Diagnosis (API) / Diagnosis (raw SQL) / Expected output / Recovery.
- Add a "Reading `change_diff`" subsection to explain INSERT/UPDATE/DELETE shapes and the `changed_from` opt-in matrix.
- Ensure no `SELECT *` is used in any SQL block.
- Add a `<!-- LIVE-JOIN-WARNING -->` callout on recipes that join live application tables.

### 2. Add Doc-Contract Test
Create `test/threadline/incident_playbook_doc_contract_test.exs`.
- Read `guides/incident-playbook.md`.
- Assert the presence of all five canonical incident headings and the `change_diff` subsection.
- Assert the presence of `<!-- LIVE-JOIN-WARNING -->`.
- Assert that `SELECT *` does not appear anywhere in the raw SQL blocks.

### 3. Create Guarded Replay Script
Create `examples/threadline_phoenix/priv/scripts/incident_replay.exs`.
- Implement a guard check for `System.get_env("THREADLINE_REPLAY_DISPOSABLE_DB") == "1"` and ensure the DB name clearly indicates it is disposable. Abort before mutation if conditions are not met.
- Use `OptionParser` to parse `--incident=<slug>` and a `--execute` flag. Default to `--dry-run` behavior.
- Implement the reproduction for three of the five scenarios against the example application's seeded data.

### 4. Create Replay Smoke Test
Create `examples/threadline_phoenix/test/threadline_phoenix/incident_replay_smoke_test.exs`.
- Shell out to `mix run priv/scripts/incident_replay.exs` using `System.cmd/3` (with appropriate env vars set).
- Assert the expected JSON output shape.
- Verify that without the required environment variable, the script aborts with a non-zero exit code.

## Verification & Testing
- Run `mix test test/threadline/incident_playbook_doc_contract_test.exs` in the root repository.
- Run `mix test test/threadline_phoenix/incident_replay_smoke_test.exs` in the `examples/threadline_phoenix/` directory.
- Manually run the replay script with and without `--execute` and `THREADLINE_REPLAY_DISPOSABLE_DB` to confirm guard rails.
