**Source-text pins vs rendered output.** Two kinds of check fail when a component moves, and they are handled differently:
- *Source-text pins* match call-site spelling, not HTML: the storybook_stories_test contract markers (`{"button", ["<UI.button"]}` …, consumed by `rendered_or_source_backed?/3` via `String.contains?`) and component_contract_test's page-shell pin (`src =~ "UI.shell"`, rewritten to `"UI.Page.shell"` in the Page commit). Each family commit rewrites exactly the markers of the components it moves to the family-qualified spelling (`"<UI.modal"` → `"<UI.Overlay.modal"`), leaving list membership, labels, and the assertion functions unchanged. A marker is a rename pin, not an output assertion.
- *Rendered-output checks* are everything in ZOC steps 1-4 that renders: the byte lock, rendered_output_contract, render assertions in component_contract_test / ui_test / pager_test / page_header_test, story rendering in `mix verify.example`, and the browser lane.
