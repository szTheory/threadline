Implement `ThreadlinePhoenix.HelpDesk` context module (move aliases from stub if needed).

**Public API:**

```elixir
@spec ticket_replied_and_closed(
  Threadline.Semantics.AuditContext.t(),
  ThreadlinePhoenix.HelpDesk.Organization.t(),
  ThreadlinePhoenix.HelpDesk.Ticket.t(),
  map(),  # reply attrs: body, internal_note_body
  map(),  # ticket attrs: status: "closed", closed_at: DateTime.utc_now() (truncate seconds)
  keyword()
) :: {:ok, %{ticket: _, reply: _, audit_transaction_id: _}} | {:error, term()}
```

**Transaction steps (single `Repo.transaction`):**
1. Require `audit_context.actor_ref` — else `{:error, :missing_actor}` (match Blog).
2. `set_config('threadline.actor_ref', ...)` with Jason-encoded `ActorRef.to_map/1`.
3. `Repo.insert!` TicketReply changeset (associate ticket_id).
4. `Repo.update!` Ticket changeset closing ticket (`status` → `"closed"`, set `closed_at`).
5. `Threadline.record_action(:ticket_replied_and_closed, repo: Repo, actor: actor_ref, correlation_id: ..., request_id: ...)`.
6. `Repo.update_all` on `AuditTransaction` where `txid == txid_current()`, set `action_id` and `meta: %{"organization_id" => to_string(organization.id)}`.
7. Return `%{ticket:, reply:, audit_transaction_id:}` like Blog returns post + audit_transaction_id.

**Optional (D-04 / discretion):** `delete_reply/2` performing hard `Repo.delete/1` with same org meta linking if delete happens in a dedicated function — may be test-only helper in Plan 03 instead.

**Private:** `audit_transaction_meta/1` — only organization UUID string key per D-01a (can inline meta without Blog's opts keyword).

Do NOT add other `record_action` atoms in this phase.
