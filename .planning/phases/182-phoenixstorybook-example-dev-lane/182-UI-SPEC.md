# Phase 182 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 182 adds a PhoenixStorybook maintainer lane inside `examples/threadline_phoenix` only. It documents and previews private Threadline operator components for design review; it does not create a public component API, a production route, an adopter install step, or a replacement for `/audit/__stress`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | PhoenixStorybook in the example app only; shadcn gate not applicable because Threadline is Phoenix LiveView, not React/Next/Vite |
| Preset | not applicable |
| Component library | Private Phoenix function components in `Threadline.OperatorSurface.UI` plus `SurfaceHeader`; PhoenixStorybook is documentation tooling, not the runtime component system |
| Icon library | Internal inline SVG icons via `Threadline.OperatorSurface.Components.Icon`; no icon package dependency |
| Font | Geist for UI text; IBM Plex Mono for refs, code, route paths, and technical anchors |

Source: `182-CONTEXT.md` D-182-01 through D-182-26; `182-RESEARCH.md` Standard Stack and Architecture Patterns; `lib/threadline/operator_surface/style.ex`; `brandbook/tokens.json`; `DESIGN-SYSTEM.md`.

Design-system contract:

- Render every Storybook preview through a shared Threadline wrapper that includes `Threadline.OperatorSurface.Style.css`, applies `class="threadline-ui"`, and sets `data-tl-theme="dark"`, `"light"`, or `"system"`.
- Use the existing `.threadline-ui` scoped CSS and `--tl-*` tokens. Do not add Tailwind, shadcn, Radix, a root UI package, or parallel Storybook-only theme tokens.
- Use PhoenixStorybook `Variation`, `VariationGroup`, templates, slots, notes, and index pages for component documentation. Do not hand-roll a custom story browser.
- Keep `/audit/__stress` as the authenticated operator-flow stress harness. Storybook documents focused component states and recurring assemblies only.
- Preserve the private component boundary. Do not add public-facing `@doc` prose to private operator components for Storybook extraction.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, dense inline offsets, compact preview annotations |
| sm | 8px | Default inline gaps, button icon gaps, cluster gaps, Storybook note spacing |
| md | 16px | Default stack gap, preview padding, panel padding, story template body padding |
| lg | 24px | Story sections, form groups, overlay preview separation |
| xl | 32px | Category pages, grouped examples, major component preview blocks |
| 2xl | 48px | Large preview breaks where the existing token scale already supports them |
| 3xl | 64px | Reserved page-level spacing from the brand token scale; do not introduce a new `style.ex` token in Phase 182 |

Exceptions: Existing `style.ex` and brand tokens `--tl-space-3` (12px), `--tl-space-5` (20px), `--tl-space-10` (40px), and brand-only `--tl-space-20` (80px) may remain where already used. New Phase 182 Storybook helper code must not create additional spacing tokens. Hit targets stay on `--tl-hit-area: 40px`; compact controls stay at `--tl-control-height-compact: 32px`; chip and badge heights stay existing.

Interaction spacing rules:

- Use `--tl-gap-inline` (8px), `--tl-gap-stack` (16px), and `--tl-gap-section` (32px) for new story wrappers, grouped variations, and pattern previews.
- Component previews must not wrap UI cards inside Storybook-created cards inside component cards. Let PhoenixStorybook provide the outer documentation frame and keep Threadline component surfaces as the preview content.
- Story source, notes, and metadata may use PhoenixStorybook chrome spacing, but rendered Threadline previews must use Threadline tokens.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | regular 400 | 1.5 |
| Label | 14px | semibold 600 | 1.4 |
| Heading | 20px | semibold 600 | 1.2 |
| Display | 32px | semibold 600 | 1.15 |

Typography rules:

- Phase 182 declares only 400 and 600 for new Threadline preview content. Existing grandfathered component use of 500 may remain, but do not introduce new standalone 500-weight text in story wrappers.
- Use mono only for refs, IDs, SQL-ish commands, route paths, fixture keys, policy names, copied technical anchors, and code snippets.
- Letter spacing is `0` for normal text. Caps labels may use existing caps tracking only where the component already does.
- Do not add hero-scale type, marketing copy, or editorial typography to Storybook. The lane is a maintainer component lab.
- Storybook notes should be short, exact, and component-oriented: state what the variation proves, fixture provenance, accessibility expectation, and theme support.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Dark: `#0B1020` / `--tl-color-bg`; Light/System light branch: `#F7F9FC` | Preview background and shell ground inside `.threadline-ui` |
| Secondary (30%) | Dark: `#141B2D` and `#1B253A`; Light/System light branch: `#FFFFFF` and `#EEF3FA` | Cards, nav, panels, tables, modals, Storybook preview surfaces |
| Accent (10%) | Dark: `#4F8CFF`; Light/System light branch: `#1557C0` | Primary commands, active/current states, deep links, selected controls, focus-adjacent borders |
| Destructive | Dark: `#FF8585`; Light/System light branch: `#A33434` | Destructive-action previews and failed/destructive status evidence only |

Accent reserved for: primary buttons, active/current state, focused/selected controls, deep links, current-view export affordances, copy affordance success where the component already uses accent, and Threadline interface links. Do not use accent as generic decoration, Storybook category tint, screenshot ornament, or arbitrary card wash.

Semantic color rules:

- Keep existing warning, success, info, signal, neutral, operation, and unavailable tokens for their current meanings.
- Use Signal Cyan only for correlation, live trace, connected flow, and positive system movement. It is not a second generic accent.
- Keep Stitch Blue `#4781E6` for the logo arc/mark role; do not substitute it for interface accent blue.
- Use destructive color only when the component state names failed, denied, deleted, pruned, destructive, or irreversible-risk behavior.
- Storybook's own color-mode chrome may be enabled, but it must not replace Threadline's `data-tl-theme` preview contract.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Open Storybook` |
| Empty state heading | `No component story selected` |
| Empty state body | `Choose a category from the Storybook sidebar to review Threadline component states.` |
| Error state | `Storybook preview could not render. Check the story fixture, then verify the full operator flow in /audit/__stress.` |
| Destructive confirmation | No live destructive action in Storybook. In the inert destructive-modal story only: `Prune retention window permanently?` plus `Type default exactly`; submit copy `Prune records permanently` |

Copy rules:

- `Open Storybook` may appear only in maintainer/dev documentation or dev-only tooling. Do not add it to normal operator navigation, production/demo pages, root README adopter setup, or host-app install guidance.
- Storybook index and notes must say: Storybook is local maintainer component documentation and design review under `examples/threadline_phoenix`; `/audit/__stress` is authenticated operator-flow stress testing.
- Use Threadline's current voice: calm, exact, plain, technically literate, and useful over impressive.
- Preserve canonical nouns: Audit Action, Audit Transaction, Audit Change, Actor, Subject, Coverage, Evidence, Redaction, Retention, Export, Timeline Entry, Diff, Snapshot, Saved View.
- Preserve canonical verbs: filter, scan, open, copy, compare, refresh, remediate, download, confirm, return.
- Hide backend implementation details unless they are necessary to understand a component contract. Storybook examples show component behavior, not capture internals.
- Do not use "powered by Storybook", "install Storybook in your app", "production component catalog", or "public UI API" framing.

## Storybook Interaction Contract

Route and exposure:

- Mount Storybook at `/dev/storybook` only inside `examples/threadline_phoenix`.
- Mount `storybook_assets` separately at `/dev/storybook/assets`.
- Use a root `scope "/"` with full `/dev/storybook` paths for PhoenixStorybook router macros.
- Gate both route and assets behind the example app's dev/test `dev_routes` boundary.
- Production/demo builds must have no Storybook route, no Storybook assets route, and no dependency requirement.
- Do not require normal operator login for local dev/test Storybook unless implementation discovers exposure beyond local/dev use. If auth is added, it must be a maintainer guard and must not imply Storybook belongs to `/audit`.

Story taxonomy:

- Primary sidebar spine: `Foundations`, `Primitives`, `Forms`, `States`, `Overlays`, `Data Display`, `Groups`.
- Add a small `Patterns` branch only for recurring operator assemblies: toolbar plus filters, detail header plus metadata, data panel plus loading/empty/pager, modal destructive action, offline/reconnect group, and permission-denied group.
- Do not put story maturity, fixture provenance, accessibility notes, theme support, or ugly-data coverage in the top-level navigation taxonomy. Put that in story notes/index metadata.
- Do not move page-level flows, auth behavior, navigation flows, full page x path matrices, or stress footguns into Storybook.

Minimum story coverage:

- Foundations: tokens, theme lanes, typography, density, radius, focus, and motion rules.
- Primitives: button, icon button, link, badge, alert, divider, spinner, avatar, card, stack, cluster, page header, pager, and stat tile where available.
- Forms: label, help, error, input, field, error summary, field group, checkbox, radio, switch, select, textarea, and combobox.
- States: empty, no-data, permission, loading, stale, generic error, unavailable/source-down, redacted, pruned, null fields, and pagination/timezone boundary.
- Overlays: modal, drawer, toast, tooltip, popover, dropdown, accordion, tabs, and segmented control.
- Data Display: ref, kv, data table, data panel, code block, detail header, and toolbar.
- Groups/Patterns: the six recurring assemblies listed above, using representative ugly data.

Theme and fixture model:

- Include fixed, named dark/light/system examples for components most likely to regress visually.
- Do not duplicate every story for every theme or create a component x theme x viewport screenshot matrix.
- Every covered category must include representative ugly data where relevant: long IDs, long strings, non-ASCII text, null fields, mixed severity, permission denied, stale/reconnecting, pagination boundary, timezone boundary, disabled, error, and empty/zero states.
- Storybook may sample from `Threadline.OperatorSurface.StressFixtures` only through explicit, read-only helper functions and allowlists.
- The design-system ledger remains the ratchet/projection source, not a Storybook navigation API.

Accessibility and motion:

- Story notes must call out keyboard/focus expectations for custom controls, overlays, tabs, segmented controls, disclosures, tooltips, popovers, dropdowns, and copy controls.
- Static overlay stories are acceptable when they document visual and focus contract; add Storybook JS only if a representative overlay cannot be reviewed statically.
- Use only existing motion tokens: fast 120ms, base 180ms, slow 240ms.
- Motion must be transform/opacity-oriented and purposeful. No decorative animation, new keyframes, `transition: all`, or new motion tokens.
- Reduced-motion behavior remains inherited from `Style.css`; Storybook must not override it.

## Verification Contract

Required verification evidence for implementation planning:

- Root `mix verify.compile_no_optional` stays green.
- Root source/dependency contracts prove `PhoenixStorybook`, `phoenix_storybook`, and `live_storybook` do not enter root `mix.exs`, root public router macro source, or root package surface.
- Example app compile/test proves the dev lane compiles where allowed.
- Route/source tests prove dev/test route presence and production route/assets absence.
- Bounded browser smoke proves the Storybook index plus representative primitive, form, state, overlay, data-display, and group stories render with assets and the Threadline theme wrapper.
- Doc-contract tests preserve the Storybook-vs-stress distinction and forbid adopter install guidance.

Browser smoke scope:

- Smoke `/dev/storybook` index.
- Smoke one representative story from each primary category.
- Assert rendered previews include `.threadline-ui` and a `data-tl-theme` value.
- Assert the Storybook route and assets are absent when `dev_routes` is false or production config is compiled.
- Do not add a full screenshot matrix or external visual-regression service.
