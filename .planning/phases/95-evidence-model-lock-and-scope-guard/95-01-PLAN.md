<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Governance runtime state -> durable evidence row | Evidence snapshots must be inserted as new records rather than mutating operational rows into historical truth. |
| Installer command -> generated migration | Adopters must get the new evidence table through the existing `mix threadline.install` path to avoid setup drift. |
| Flexible JSON payload -> public contract | `subject_ref`, `provenance`, and `detail` are maps, but the record shape itself must stay explicit and stable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-95-01 | Tampering | evidence row lifecycle | mitigate | Omit `updated_at`, test repeated inserts, and keep append-only semantics explicit in schema and migration. |
| T-95-02 | Repudiation | evidence contract | mitigate | Require subject, timestamp, status, provenance, and detail fields so later phases can prove what was recorded and when. |
| T-95-03 | Availability / drift | install path | mitigate | Keep governance setup inside `mix threadline.install` so adopters do not miss the new table. |
</threat_model>
