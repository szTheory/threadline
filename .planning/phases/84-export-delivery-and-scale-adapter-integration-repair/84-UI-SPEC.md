## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline badge padding, code-chip padding, tight text gaps |
| sm | 8px | Button gaps, compact row spacing, inline status spacing |
| md | 16px | Default page padding, table cell padding, form spacing |
| lg | 24px | Section padding, header-to-table spacing |
| xl | 32px | Major page gaps, empty-state breathing room |
| 2xl | 48px | Large section breaks |
| 3xl | 64px | Page-level spacing for future wider operator surfaces |

Exceptions: compact header badges may remain visually short, but export action buttons and inline download affordances must use at least 32px vertical tap area.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FFFFFF | Page background, table body, primary surfaces |
| Secondary (30%) | #F3F4F6 | Cards, table headers, inactive controls, code/filter cells |
| Accent (10%) | #3B82F6 | Request-export button, active download links, running-state emphasis, incident/export navigation links |
| Destructive | #EF4444 | Failed export messaging, unavailable-download errors, destructive alerts only |

Accent reserved for: `Request Background Export`, `Download Export`, `Back to Timeline`, active row links, and `running` export state emphasis. Do not use accent for every badge or every control.

## Visual Hierarchy

| Surface | Focal Point | Supporting Hierarchy |
|---------|-------------|----------------------|
| Timeline toolbar | `Request Background Export` is the primary focal action in the button cluster. | `Apply Filters` and `Clear all` remain subdued utility actions; synchronous format downloads read as secondary options. |
| Export Status page | The status badge and action cell on the most recent row carry the primary scanning weight. | The page title anchors context first, then the newest row, then error detail or download affordance. |
| Completed export row | `Download Export` is the visual anchor. | Status badge confirms completion, dates and filters provide context, and metadata stays visually quieter than the action. |
| Failed export row | The inline error message is the focal point. | The failed badge introduces state first, then the human-readable failure reason directs the next step. |

Icon-only actions: none. Every export action remains text-labeled.

## Interaction Contract

| Surface | Contract |
|---------|----------|
| Timeline toolbar | Keep the existing action order: `Clear all`, `Apply Filters`, `Request Background Export`, then synchronous format downloads. `Request Background Export` remains the only accent-filled button in the cluster. |
| Async request result | On successful enqueue, redirect to the Export Status page and show the existing info flash. On enqueue or adapter startup failure, stay on the Timeline and show a destructive flash; never redirect with a false success state. |
| Export Status page | Keep actor-scoped, newest-first jobs only. Poll every 5 seconds. Preserve sticky surface header and page header layout. |
| Export Status table | Use columns in this order: `Status`, `Filters`, `Started At`, `Completed At`, `Expires At`, `Actions`. `Filters` remains monospace/code-styled. Empty dates render as `-`. |
| Status badges | `pending` uses secondary surface + muted text. `running` uses accent emphasis. `completed` uses neutral badge treatment with the download action carrying accent. `failed` uses destructive text and shows the persisted error message directly beneath the badge. |
| Download affordance | Completed rows must render exactly one actionable control labeled `Download Export`. The control appears only when the backend can supply a valid local delivery path or adapter-backed `download_url/2`. No dead links. |
| Delivery semantics | Local storage may route through the operator-surface download endpoint. Adapter-backed storage must send the user to the adapter-issued URL. UI copy must stay storage-agnostic; never mention filesystem paths, S3 keys, or `local only` in operator-facing text. |
| Non-ready rows | `pending` and `running` rows show no download link; instead show quiet placeholder copy in the action cell: `Preparing download`. |
| Failed rows | `failed` rows show no download link. The inline error message is the primary explanation surface and must use the persisted human-readable failure reason when available. |
| Expiry visibility | Completed and failed rows must show `expires_at` so operators know the artifact retention window. If retention metadata is absent, render `-` rather than guessing. |
| Actor ownership | Export Status remains strictly actor-owned. If actor handoff is missing, render the empty state rather than exposing shared/global jobs. |
| Accessibility | Status updates use `role="status"` for passive refreshes and `role="alert"` for failures. Download links remain keyboard reachable and visually distinct from neutral table text. |
