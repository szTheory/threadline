    - .github/workflows/release.yml (workflow_dispatch inputs)
    - CONTRIBUTING.md (bootstrap dispatch example)
  </read_first>
  <action>
From a machine with `gh` authenticated:

```bash
# If a stale v0.6.0 tag exists on an older SHA, delete it first:
git push origin :refs/tags/v0.6.0

gh workflow run release.yml \
  -f tag=v0.6.0 \
  -f release_version=0.6.0 \
  -f dry_run=false \
  -f skip_distribution_sync=false
```

The workflow will:
1. Create tag `v0.6.0` on `main` HEAD if missing
2. Run `gate-ci-green` on that SHA
3. Run `mix verify.release`, idempotent `mix hex.publish`, Hex API verify
4. Open Wave 3 distribution sync PR via `distribution-sync` job

Recovery: re-dispatch the same inputs without re-tagging if publish was skipped idempotently.
  </action>
  <acceptance_criteria>
    - Release workflow run triggered with inputs `tag=v0.6.0`, `release_version=0.6.0`
    - Jobs **gate-ci-green**, **publish-hex**, and **Verify version on Hex.pm** succeed
  </acceptance_criteria>
  <verify>gh run list --workflow=release.yml --limit 1</verify>
</task>
