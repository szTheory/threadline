<objective>
Build the HYG-02 local-path guard as a standalone, tested tool: `bin/verify-repo-hygiene`, its scoped allowlist `.github/repo-hygiene-allowlist.tsv`, and an offline ExUnit behavior test. This plan does NOT wire the guard into `mix.exs`, `ci.all`, `ci.yml` or CONTRIBUTING. That wiring is plan 217-05, which lands after plan 217-04 has scrubbed the tree. The guard has to exist first because plan 217-04 uses the guard's own report as the scrub list. A single detection definition then drives both the scrub and the gate.

Purpose: HYG-02 says CI fails a PR that adds a machine-local path. The guard scans tracked text only, allowlists runner and cache paths, fails on an unused allowlist entry, and proves it goes red on runtime-built fixtures.
Output: an executable guard script, the allowlist data file and a behavior test. Before the scrub, the guard's report against the real tree is expected to be red.

<interfaces>
Guard contract (all callers rely on this, including plans 217-04 and 217-05):
- Invocation: `bin/verify-repo-hygiene` (scan) or `bin/verify-repo-hygiene --self-test`. Any other argument exits 2 with a usage line.
- Exit codes: 0 means clean. 1 means a finding: a HIT, an UNUSED allowlist entry, or an allowlist comment or reason that contains a pattern hit. 2 means usage or config error: an unknown argument, not a git work tree, a malformed or duplicate allowlist line, a missing allowlist file, or a missing git.
- Output lines, in stable order: `HIT <path>:<line>: <token>`, then `UNUSED allowlist entry <scope> <literal>`, then `ALLOWLIST <n>: <problem>`. On exit 0 the last line is `verify-repo-hygiene: <N> tracked text file(s) clean; <U> allowlist entr(y|ies) used, <I> inert (.planning/ absent)`.
- Env seams, for tests and self-test only: `REPO_HYGIENE_ROOT` sets the git work tree to scan (default: the script's repo root). `REPO_HYGIENE_ALLOWLIST` sets the allowlist file (default: `<root>/.github/repo-hygiene-allowlist.tsv`).
- Allowlist line: `<scope>\t<literal>\t<reason>`. `#` comment lines and blank lines are allowed. `<scope>` is `.` (repo-wide), a repo-relative directory ending in `/`, or a repo-relative file path. It has no leading `/` and no glob characters.
</interfaces>
