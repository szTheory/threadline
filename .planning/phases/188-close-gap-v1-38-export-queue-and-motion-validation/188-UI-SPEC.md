# Phase 188 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 188 is narrow v1.38 gap closure. It must close the queued Timeline current-view export gap and the `.tl-copy` implicit transition-all gap without redesigning the operator surface. Do not add routes, route meanings, stable `data-testid`s, public component APIs, Tailwind, shadcn, new dependencies, new motion families, new visual hierarchy, or new operator workflows.

Sources: `.planning/v1.38-MILESTONE-AUDIT.md`; `.planning/phases/188-close-gap-v1-38-export-queue-and-motion-validation/188-RESEARCH.md`; `.planning/phases/188-close-gap-v1-38-export-queue-and-motion-validation/188-VALIDATION.md`; `.planning/phases/187-accessibility-motion-docs-and-adversarial-closeout/187-UI-SPEC.md`; `.planning/phases/186-detail-governance-and-export-surfaces/186-UI-SPEC.md`; `DESIGN-SYSTEM.md`; `brandbook/tokens.css`; `lib/threadline/operator_surface/live/timeline_live.ex`; `lib/threadline/operator_surface/live/export_status_live.ex`; `lib/threadline/operator_surface/style.ex`.

## Spacing Scale

Declared values are multiples of 4 and must map to existing `--tl-*` tokens where available.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Focus offsets, icon gaps, copy-button internals, compact status spacing |
| sm | 8px | Button/icon gaps, inline metadata gaps, export status/action spacing |
| md | 16px | Default stack gap, panel padding, table/card padding, source proof target spacing |
| lg | 24px | Existing workflow section breathing room only |
| xl | 32px | Major section gaps through `--tl-gap-section` only |
| 2xl | 48px | Large page breaks only where existing `--tl-space-12` already exists |
| 3xl | 64px | Standard upper-bound scale value; do not add a Phase 188 CSS token for this value |

Exceptions: preserve inherited `--tl-space-3` (12px), `--tl-space-5` (20px), `--tl-space-10` (40px), `--tl-hit-area: 40px`, compact controls at 32px, chips at 24px/22px, and drawer width at 760px. New Phase 188 changes should not alter layout spacing unless required to keep the existing export/copy controls from wrapping incorrectly after the bug fix.

Phase 188 spacing rules:

| Surface | Contract |
|---------|----------|
| Timeline export actions | Keep the existing compact utility-group rhythm. Do not add a new export toolbar or wider action cluster. |
| Exports context panel | Keep the existing `tl-job tl-job--info` panel, `tl-job__main`, `tl-job__summary`, and `tl-job__actions` anatomy. |
| Export job list | Preserve recent-only list spacing and status captions from Phase 186. Do not add pagers or dashboard cards. |
| Copy control | `.tl-copy` keeps existing size: `min-width: var(--tl-control-height-compact)` and `min-height: var(--tl-control-height-chip)`. Motion fixes must not resize the control. |
| Validation-only hooks | If adding a test hook, it must not introduce visible spacing, new wrapping behavior, or layout shifts. |

## Typography

Use exactly these four Phase 188 text sizes and two declared weights for any touched user-facing copy. Existing private component internals that already use 12px, 13px, 15px, 32px, or weight 500 may remain, but do not create new Phase 188 text roles around those values.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label / metadata | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Title | 24px | 600 | 1.2 |

Typography rules:

- Normal letter spacing is `0`. Existing caps tracking may remain only on inherited compact labels.
- Keep current export labels and headings. Do not introduce new hero/display typography.
- Use IBM Plex Mono only for exact filter values, refs, IDs, table names, command snippets, export job metadata, exact timestamps, and copied technical values.
- Long export filters continue through `UI.ref/1` and must copy the full source value, not visible truncation.

## Color

Use the existing dark-primary palette with light/system token branches preserved.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Dark `#0B1020` via `--tl-color-bg`; light `#F7F9FC` | Shell and page background |
| Secondary (30%) | Dark `#141B2D` / `#1B253A`; light `#FFFFFF` / `#EEF3FA` | Page headers, export context panels, export job rows, tables, dialogs, drawers |
| Accent (10%) | Dark `#4F8CFF`; light `#1557C0` | Focus rings, current/selected state, Timeline route pivots, valid queue/export/download actions |
| Destructive | Dark `#FF8585`; light `#A33434` | Failed export/error states only in Phase 188; no destructive action is added |

Accent reserved for: focus-visible rings/borders, active shell nav, selected theme/filter state, `Carry to Exports`, valid `Queue export`, valid `Queue Timeline export`, valid `Download export`, `Reopen source search`, `Open timeline`, and existing copy success affordances when Signal treatment already applies. Accent is not decoration and must not color every control, metric, card title, or evidence surface.

Additional semantic colors:

| Semantic | Token | Reserved for |
|----------|-------|--------------|
| Signal | `--tl-color-signal` | Copy success and positive system flow only |
| Info | `--tl-color-info-*` | Queued/running export state and neutral context |
| Success | `--tl-color-success-*` | Completed/ready export state only |
| Warning | `--tl-color-warning-*` | Reconnect/stale/capped/expiring context |
| Danger | `--tl-color-danger-*` | Failed exports, invalid context, and parser failure surfacing |

Color never carries status alone. Status must also include text, shape/icon, chip label, role-specific copy, or accessible name.

## Copywriting Contract

Phase 188 should not introduce new operator-product copy unless the queued export parser needs to surface a failed job reason. Preserve the exact existing labels below.

| Element | Copy |
|---------|------|
| Primary CTA | Timeline toolbar: `Queue export`; Exports carried context: `Queue Timeline export` |

| Error state | Context alert: `Timeline export context could not be applied. Fix the Timeline filters, then carry them to Exports again.` |
| Destructive confirmation | No new destructive actions. Retention remains unchanged and out of scope. |

Locked export labels and messages:

| Surface | Required copy |
|---------|---------------|
| Timeline handoff link | `Carry to Exports` |
| Timeline background queue button | `Queue export` |
| Timeline queue success flash | `Background export requested. View progress on the Export Status page.` |
| Timeline invalid-filter flash | `Fix Timeline filters before exporting.` |

| Carried context chip | `Timeline export context` |

- Actions must be specific verb plus object.
- Error copy names the failed object and next action.
- Avoid hype, marketing phrasing, SIEM/compliance-suite framing, exclamation marks, and vague verbs such as `Continue`.

## Queued Export Interaction Contract

Phase 188 closes a backend replay bug while preserving the current UI surface.

| Interaction | Contract |
|-------------|----------|
| Timeline current-view queue | Existing `Queue export` button remains a native button, visible only when exports are enabled and filters are valid. It keeps `phx-click="request_background_export"` and must remain keyboard reachable by role/name. |
| Timeline carry path | Existing `Carry to Exports` link preserves current query params and existing `data-earned-flow="EF3"`, `data-persona="P3"`, and `data-jtbd="J6"` attributes. |
| Exports carried context | Existing `data-testid="timeline-export-context"` panel stays visible for valid Timeline context and shows canonical allowed filter pairs through `UI.kv`/`UI.ref`. |
| Exports context queue | Existing `Queue Timeline export` button remains a native button. It must queue only valid context and must not render for invalid context. |
| Persisted job params | Keep `ExportJob.query_params` URL-shaped/canonical for source search reopening. Do not persist a new UI-only typed shape that breaks `Reopen source search`. |
| Worker replay | Before streaming rows, queued worker replay must parse persisted params through the existing allowlisted filter parser or a small shared wrapper around it. Date-bounded `from`/`to` values must become `%DateTime{}` filters before querying. |
| Fail-closed behavior | Invalid persisted queued params must fail the export job rather than silently broadening the export. The failed job renders in the existing failed export row treatment. |
| Direct downloads | Existing CSV/JSON/NDJSON direct download links and completed job `Download export` links remain real focusable links. Phase 188 must not add LiveView-only gating as the security boundary. |
| Feature/auth gates | Existing export feature gate, export authorization plug/controller protections, unsupported view, and forged-event rejection remain unchanged. |
| Stable selectors | Preserve `timeline-export-context`, `evidence-export-context`, `export-jobs`, `export-readiness-group`, `export-job`, `timeline-row`, `transaction-link`, `timeline-row-history-link`, and `operator-nav-exports`. |

No new visible export state is required. Any implementation that changes visible labels, context-panel anatomy, or route structure is outside this UI-SPEC unless a failing existing test proves the old surface cannot satisfy the gap.

## Accessibility And Interaction Contract

| Case | Contract |
|------|----------|
| Keyboard queue path | A keyboard user must be able to reach `Queue export` on Timeline or `Queue Timeline export` in the carried Exports context and create a job shape that the worker can complete for normal date-bounded filters. |
| Invalid context | Invalid carried Timeline context uses the existing `role="alert"` error block and does not expose a queue button. |
| Progress/status | Export list captions and status hints keep `role="status"`/polite status behavior where already present. |
| Failed jobs | Failed export row keeps `role="alert"` and gives the operator `Reopen source search` plus next action copy. |
| Download links | Completed downloads are focusable links with `href`; unavailable jobs show status text instead of fake disabled download links with active `href`. |
| Copy controls | Every `.tl-copy` button keeps its object-specific accessible name and copies the full value from `data-tl-copy`. The motion fix must not remove visible focus, hover, copied state, or the static `Copied` chip. |
| Reconnect/mutating safety | Existing `[data-tl-mutating]`, disabled, `phx-disable-with`, and server-side enforcement patterns remain. CSS dimming alone is not enforcement. |
| Focus visibility | `.threadline-ui` focus styles keep `--tl-focus-ring`; Phase 188 must not weaken focus contrast or remove `:focus-visible` selectors. |

Do not role-inflate native `<button>`, `<a>`, `<input>`, `<select>`, `<details>`, `<summary>`, or form controls. Use existing role/name assertions and LiveView tests instead of adding hidden test-only controls.

## Motion Contract

Phase 188 changes motion governance, not the visual behavior of the copy affordance.

| Interaction | Contract |
|-------------|----------|
| `.tl-copy` default | Keep the existing inline-flex copy button, hover color change, copied Signal color, static `Copied` chip, and `tl-copy-pulse` copied animation. |
| `.tl-copy` transition | Replace token-only shorthand `transition: var(--tl-transition-fast);` with explicit properties. Required properties: `color`, `border-color`, `background-color`, and `box-shadow`. Required duration: `var(--tl-motion-fast)`. Required easing: `var(--tl-ease-standard)`. |
| Source prohibition | `.tl-copy` must not compute through implicit `transition-property: all`, and source guards must reject literal `transition: all` and token-only shorthand that omits a transition property list. |
| Copy success animation | `tl-copy-pulse` remains the only allowed copy animation. Do not add new keyframes or copy-specific motion tokens. |
| Reduced motion | Existing reduced-motion blanket keeps animations/transitions near-instant while preserving visible copied feedback. Do not remove the static `Copied` chip. |
| Browser proof | If browser proof is added, it must be narrow: inspect a rendered `.tl-copy` computed `transitionProperty` and assert it does not include `all`; do not add a screenshot matrix. |
| Prohibited | `transition: all`, `transition-property: all`, layout-affecting transition properties, animation libraries, decorative animation, row/card entrance churn, scroll-jacking, or per-page motion experiments. |

MOTION-01 closure requires source-contract proof. Browser computed-style proof is allowed but must stay narrowly scoped to `.tl-copy` and existing operator-motion test infrastructure.
