## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline badge spacing, compact code-chip padding, tight status gaps |
| sm | 8px | Button gaps, filter-hint spacing, fallback label-to-code spacing |
| md | 16px | Default card padding, empty-state spacing, toolbar grouping |
| lg | 24px | Page section padding, header-to-content spacing |
| xl | 32px | Empty-state breathing room, unsupported-state top/bottom padding |
| 2xl | 48px | Major separation between toolbar, table, and fallback blocks |
| 3xl | 64px | Page-level whitespace when unsupported states replace full data views |

Exceptions: unsupported-state code fallback may wrap to two lines, but the primary recovery action must retain at least 32px vertical tap area.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FFFFFF | Page background, tables, supported investigation surfaces |
| Secondary (30%) | #F3F4F6 | Empty-state cards, unsupported-state container, secondary buttons, quiet placeholders |
| Accent (10%) | #3B82F6 | Authorized export actions, active navigation links, recovery links that return to a supported flow |
| Destructive | #EF4444 | Export denial messaging, failed export copy, server-error states only |

Accent reserved for: `Request Background Export`, `Download CSV/JSON/NDJSON`, `Download Export`, active navigation links, and the supported-path recovery link back to the timeline. Do not use accent to make unsupported surfaces feel actionable.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Request Background Export |
| Secondary CTA | Back to Timeline |
| Empty state heading | "Unsupported View" |
| Empty state body | "This support-lane view is not available for the current transport or access tier." |
| Error state | "Action Denied" with body "Support-scoped operators require explicit host authorization for exports." |
| Destructive confirmation | Not applicable: this phase introduces no destructive operator action. |
| Fallback hint | "Try instead" followed by a code-formatted fallback transport such as `mix threadline.export --dry-run --table posts` |

## Visual Hierarchy

| Surface | Focal Point | Supporting Hierarchy |
|---------|-------------|----------------------|
| Timeline toolbar (authorized) | `Request Background Export` is the primary focal action within the button cluster. | `Clear all` and `Apply` remain utility actions; format download links stay secondary but visible. |
| Timeline toolbar (denied support scope) | Filter controls and results remain the primary workflow; export affordances disappear entirely. | No disabled export buttons, no hollow placeholders, and no misleading empty slot in the cluster. |
| Export denial screen (`/audit/exports`) | The `Action Denied` title and explanatory body are the focal elements. | The fallback command appears below as an operator recovery path, followed by the `Back to Timeline` secondary action. |
| Unsupported admin/global surfaces | `Unsupported View` title anchors first, then the body copy, then the exact fallback transport. | The fallback code hint reads as guidance, not as a destructive or blocking alert. |
| Export status table (authorized) | The actionable download control or current status badge on the newest row carries the strongest scan weight. | Error copy, filters, and retention metadata stay subordinate to status and next action. |

Icon-only actions: none. Every denial, fallback, and recovery action must remain text-labeled.

## Interaction Contract

| Surface | Contract |
|---------|----------|
| Timeline export affordances | When `threadline_exports_enabled` is true, keep the existing order: `Clear all`, `Apply`, `Request Background Export`, `Download CSV`, `Download JSON`, `Download NDJSON`. When false, hide the entire export action cluster rather than showing disabled controls. |
| Direct export URLs | Support-scoped denial stays server-authoritative. Direct HTTP export requests must still fail with plain-text `403` through `ExportAuthPlug`; the UI must not imply that hiding buttons is the only gate. |
| Export denial LiveView (`/audit/exports` when denied) | Render the shared unsupported-state shell with `Action Denied` title, export-specific denial body, `mix threadline.export --dry-run --table posts` fallback, and a secondary `Back to Timeline` link. |
| Coverage / policy unsupported views | Render the same unsupported-state shell with `Unsupported View` title/body, plus the surface-specific fallback transport (`mix threadline.health.coverage`, `mix threadline.policy.show`, or retention fallback). |
| Fallback hint styling | Fallback transports must render as code-formatted literals underneath the explanatory body. The label defaults to `Try instead`; do not invent surface-specific prose unless the fallback becomes ambiguous. |
| Recovery path | Unsupported and denied states must always expose a low-emphasis `Back to Timeline` control when a `base_path` exists so operators can recover without using browser history. |
| Export status table | When authorized, keep columns in this order: `Status`, `Filters`, `Started At`, `Completed At`, `Expires At`, `Actions`. Pending/running rows show `Preparing download`; completed-but-unavailable rows show the explicit unavailable copy instead of a dead link. |
| Copy boundary | Unsupported messaging must stay honest about scope: do not claim row history/as-of is unsupported in this phase, because Phase 86 closes that read-path truth boundary through scoped behavior rather than blanket removal. |
| Accessibility | Unsupported containers use `role="status"`. Failed export rows use `role="alert"`. Recovery links and fallback commands remain keyboard reachable and visually distinct from surrounding paragraph text. |
