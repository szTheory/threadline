- D-18 (new public function) is locked by the maintainer; no checkpoint.
- D-20 discretion, decided here: the public function RAISES on a cancelled probe; it does not return a sentinel. The `Postgrex.Error` (postgres code `:query_canceled`) propagates out of `repo.transaction/1` unchanged, which keeps the return type `[Finding.t()]` and adds no new public exception module. The sentence goes in the "Default or absence behavior" cell of the `trigger_capture` row (header: `Key | Purpose and accepted shape | Default or absence behavior | Primary owner`), appended after the existing text in that cell.
- Statement timeout is set with `SELECT set_config('statement_timeout', $1, true)` and a bound text parameter (transaction-local, PgBouncer-safe), never by interpolating into a SET statement.
- One probe per {schema, table}: if a table carries more than one Threadline trigger with key args, use the trigger whose name sorts first (duplicates already surface as `:duplicate_capture_trigger`).
- `details` uses string keys as D-23 specifies (TriggerFindings uses atom keys); both encode identically to JSON. The @doc names the keys.
</resolved_decisions>
