## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline badge padding, monospace chips, tiny gaps inside status rows |
| sm | 8px | Compact row gaps, table cell inset, badge spacing, filter hint separation |
| md | 16px | Default page padding, card padding, section spacing, empty-state padding |
| lg | 24px | Gap between overview summary and grouped evidence sections |
| xl | 32px | Gap between the landing overview block and secondary history drill-down block |
| 2xl | 48px | Reserved for major unsupported/error state breathing room only |
| 3xl | 64px | Do not use inside the mounted `/audit` viewport in this phase |

Exceptions: sticky header remains `36px` high to match the existing `/audit` surface; pill badges may keep `12px` radius; row-level history triggers must remain at least `44px` tall when rendered as standalone touchable rows.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 400 | 1.4 |
| Heading | 18px | 600 | 1.2 |
| Display | 18px | 600 | 1.2 |

Use only weights `400` and `600`. Keep evidence subject refs, JSON-like identifiers, and fallback commands in monospace, but do not introduce a separate display font.

---

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, sticky header, table body, primary evidence surface |
| Secondary (30%) | `#F3F4F6` | Cards, grouped section headers, empty states, metadata chips, secondary rows |
| Accent (10%) | `#3B82F6` | Subject drill-down links, active evidence filter state, primary `View history` actions, transaction/reference deep links |
| Destructive | `#EF4444` | Runtime failures, invalid filters, destructive-only warnings; never use for ordinary unsupported claims |

Accent reserved for: `View history` links, subject-ref drill-down links, active overview/history toggle state, and deep links out to related `/audit` transaction or policy surfaces.

Use amber warning styling already present on the operator surface for `unsupported` or stale-proof caution states; do not repurpose destructive red for unsupported-but-successful evidence claims.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | View history |
| Empty state heading | No evidence records yet |
| Empty state body | Threadline has not recorded evidence for this selection yet. Use `mix threadline.evidence.show` or the `Threadline.Evidence` API to confirm the current proof state, then narrow by subject or date if needed. |
| Error state | Evidence view unavailable. This mounted proof surface is not available for the current support lane or transport. Use `mix threadline.evidence.show` or the `Threadline.Evidence` API instead. |
| Destructive confirmation | none - Phase 98 is read-only and must not add mutating controls |

Additional copy rules:

- Landing title must answer the operator question directly: `What can Threadline prove right now?`
- Latest-summary rows must label `proven`, `inferred_posture`, and `unsupported` exactly as the proof contract defines them.
- Any convenience `latest` wording must state that it is a projection over append-only history, not a mutable state record.
- Unsupported mounted access must be explicit and visible; never hide the evidence route or silently collapse denied sections.
