<objective>
Close the two failed truths in 215-VERIFICATION.md for the required per-PR gate `bin/verify-deps-audit`:
CR-01 (global Hex `ignore_advisories` / `ignore_retirements` bypass) and WR-02 (plain `deps.get` can
re-resolve and audit a lock other than the committed one). Also close the test/doc holes the verifier
named: the workflow contract scan and the false moduledoc claim in ignore_advisories_contract_test.exs.

Mechanism choice (planner's discretion; there is no CONTEXT.md), with the trade-off:
- CR-01: REFUSE, not isolate. The gate asks Hex for the effective value with `mix hex.config
  ignore_advisories` and `mix hex.config ignore_retirements` and dies unless each is exactly `[]`.
  Verified during planning (Hex 2.5.1, Elixir 1.17.3): the query prints `[]` when unset and a list
  literal such as `["A-1", "B-2"]` or `[{"plug", nil}]` when set, reflects `$HEX_HOME/hex.config`,
  the default home, and the HEX_IGNORE_ADVISORIES env var alike, and costs no network. HEX_HOME
  isolation was rejected: it also isolates the package cache and registry keys, so every CI run and
  every self-test pays a cold fetch, and it silently hides a developer's misconfiguration instead of
  telling them. Refusal is source-agnostic, so it cannot be dodged by picking a different config
  location.
- The query MUST run from a directory with no mix.exs. Verified during planning: inside a project,
  `mix hex.config ignore_advisories` also returns the project's own `hex: [ignore_advisories: ...]`
  ids, so running it from a project dir would refuse a legitimate, accountable SUP-03 entry. A fresh
  `mktemp -d "$ROOT/tmp/..."` dir works: asdf still finds the repo's tool versions by walking up, and
  Mix does not walk up for mix.exs. `tmp/` is gitignored (.gitignore line 45).
- WR-02: `deps.get --check-locked`. Verified during planning: `mix help deps.get` on the pinned
  Elixir 1.17.3 lists `--check-locked` ("raises if there are pending changes to the lockfile"); all
  three real lockfiles pass it today (exit 0); the vulnerable fixture passes it (so self-test (a) still
  reaches hex.audit); a fixture copy with mix.exs changed to `~> 1.19.2` exits 1 with
  "Your mix.lock is out of date and must be updated without the --check-locked flag" and leaves the
  lock byte-identical.
- Defense in depth: both closures are also proven against real Hex in `--self-test`, which already
  runs as a step of the required `verify-deps-audit` CI job, so no network test enters `mix test`.

Purpose: SUP-02's "CI stops any PR that would introduce an advisory" and SUP-03's "every suppression is
accountable" become true for the required gate, not only for the env-var path.
Output: hardened gate script, extended offline gate tests, extended workflow contract, corrected
moduledoc, updated CONTRIBUTING gate paragraph.
</objective>
