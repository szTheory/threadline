<objective>
Build the per-PR supply-chain gate (SUP-02): `mix verify.deps_audit` → `bin/verify-deps-audit`,
a new required `verify-deps-audit` CI job, `ci.all` membership, and tests that prove the gate
goes red on a known-vulnerable lock and on an old Hex.

Design choices and the reasons for them (Claude's discretion; there is no CONTEXT.md):
- The gate logic lives in a bash script, following the `bin/verify-bump-rehearsal` precedent, not in a
  private mix.exs function. A private mix.exs function cannot be tested; a script with a MIX_BIN seam
  can be tested offline with a fake `mix`, the same way `bin/upsert-ci-issue` is tested with GH_BIN.
- The negative network proof is `bin/verify-deps-audit --self-test` run as a step in the new job. It is
  not a tagged ExUnit test excluded from `mix test`. This departs from the orchestrator's
  recommendation (a). The reason: test/test_helper.exs boots Postgres on every `mix test`, so a tagged
  ExUnit network test would force a Postgres service and a full test-env compile into the new job. That
  runs against this milestone's CI-economy goal. The self-test gives the same proof, and nothing leaves
  the default lane, so the "honest default tests" rule holds without touching test_helper.exs.
- `ci.all` includes `verify.deps_audit`, per the orchestrator's option (c). It is a per-PR required gate,
  unlike the release-lane `verify.bench` / `verify.release` / `verify.bump_rehearsal`, which stay out.
  The contract test asserts the inclusion.
- The unused-lock check runs in all three directories. It is currently green in all three (verified
  during planning).

Output: gate script, fixture, two test files, alias, CI job, doc rows.
</objective>
