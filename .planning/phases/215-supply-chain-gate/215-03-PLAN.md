<objective>
Make every Hex advisory suppression accountable (SUP-03). Hex's `ignore_advisories` is a bare list
of IDs with no metadata (`mix help hex.audit`), so this plan defines the repository convention and
enforces it with a test.

Convention (Claude's discretion, recorded here and documented in CONTRIBUTING by plan 04):
a Mix project that ignores an advisory defines a public `def hex_audit_ignores` in its MixProject
module. It returns a list of maps with keys `id` (the advisory ID string), `reason`, `reachability`,
and `review_by` (a `Date`). The project's `hex: [ignore_advisories: ...]` must be exactly those ids.
`ignore_retirements` is not permitted at all, because it suppresses retirements that SUP-03's
metadata does not cover. The test fails closed on it, and extending the convention is a deliberate edit.

Why resolved config and not a source regex: `Mix.Project.config()` sees the ids Hex actually uses,
however they are written (a literal list, a comprehension, a module attribute), so a literal-list
bypass cannot hide from the check. `Mix.Project.in_project/4` loads the nested projects' mix.exs on
Mix's project stack and pops it afterwards. Planning verified that it returns `Bench.MixProject` and
`ThreadlinePhoenix.MixProject` without compiling or fetching anything.

Output: one test file.
</objective>
