# Phase 186 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 186 applies the cleaned operator IA and private component patterns to the remaining detail, governance, and export surfaces. It is a normalization and workflow-focus pass over existing Phoenix LiveView pages. It must not add a public component API, change capture/query/auth semantics, rename routes or stable `data-testid`s without phase evidence, add Tailwind/shadcn, or rescope runtime redaction.

Sources: `.planning/REQUIREMENTS.md` DETAIL-01 and GOV-01 through GOV-03; `.planning/ROADMAP.md` Phase 186 success criteria; previous Phase 183-185 UI-SPECs; `lib/threadline/operator_surface/style.ex`; `lib/threadline/operator_surface/ui.ex`; target LiveViews for transaction, row history, actor, evidence, exports, redaction, and retention.

## Spacing Scale

Declared values are multiples of 4 and must map to existing `--tl-*` tokens where available.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, copy-button internals, compact row metadata offsets |
| sm | 8px | Button icon gaps, inline metadata gaps, chip and action spacing |
| md | 16px | Default stack gap, panel padding, table/card padding, page block spacing |
| lg | 24px | Detail-header metadata break, workflow section breathing room, modal form spacing |
| xl | 32px | Major section gaps through `--tl-gap-section`, governance workflow grouping |
| 2xl | 48px | Large page breaks only where `--tl-space-12` already exists |
| 3xl | 64px | Reserved upper bound; do not add a Phase 186 CSS token for this value |

Exceptions: existing operator CSS uses `--tl-space-3` (12px), `--tl-space-5` (20px), `--tl-space-10` (40px), `--tl-hit-area: 40px`, compact controls at 32px, and drawer width at 760px. Preserve those inherited values. New or retuned Phase 186 layout should use the declared scale and existing semantic gaps: `--tl-gap-inline` (8px), `--tl-gap-stack` (16px), and `--tl-gap-section` (32px).

Surface-specific spacing rules:

| Surface | Contract |
|---------|----------|
| Detail pages | `UI.page_header` first, then a single `UI.detail_header` or equivalent object summary with a 24px metadata break. Do not put the object summary in a card nested inside another card. |
| Row history drawer | Drawer content uses 16px stack gaps and existing `--tl-drawer-width: 760px`; at mobile it must remain `min(var(--tl-drawer-width), 100vw)`. |
| Governance workflow pages | Summary facts use `tl-summary-grid` or compact status panels, then focused workflow content. Avoid separate duplicate trust rails plus duplicate metric grids when one summary can answer the workflow state. |
| Export/retention lists | Keep recent-only captions close to the list (8px-16px), then group rows by state. Do not add a keyset pager to recent-only Exports or Retention lists. |
| Destructive modal | Use 20px existing modal padding, 16px form stack, and 8px button gaps; keep the typed-confirm input and final danger button visible without scrolling at 375px. |

## Typography

Use exactly these four Phase 186 text sizes and two declared weights for new or retuned copy. Existing private component internals that already use 12px, 13px, 15px, 32px, or weight 500 may remain, but do not create new Phase 186 text roles around those values.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label / metadata | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Title | 24px | 600 | 1.2 |

Typography rules:

- Normal letter spacing is `0`. Existing caps tracking may remain only on inherited compact labels.
- Use Title size for `UI.detail_header` titles, modal titles, and workflow group titles. Use Heading size for section headings. Use Body for explanations and consequence copy. Use Label for metadata keys, chips, table labels, and compact button text.
- Use mono only for exact refs, IDs, table names, policy name `default`, command snippets, exported file metadata, and exact timestamps.
- Long refs must use `UI.ref/1` or `Presentation` truncation and copy the full value. Never rely on CSS ellipsis for the only visible/copyable value.
- Page headers on detail/governance pages must stay compact. Do not use Home display-scale typography on these pages.

## Color

Use the existing dark-primary palette with light/system token branches preserved.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Dark `#0B1020` via `--tl-color-bg`; light `#F7F9FC` | Shell and page background |
| Secondary (30%) | Dark `#141B2D` / `#1B253A`; light `#FFFFFF` / `#EEF3FA` | Page headers, detail summaries, tables, workflow panels, modals, drawers |
| Accent (10%) | Dark `#4F8CFF`; light `#1557C0` | Primary links/actions, current/selected state, valid download/queue/export actions, focus rings, filter/segmented active state |
| Destructive | Dark `#FF8585`; light `#A33434` | Retention prune action, failed/destructive statuses, irreversible warning emphasis only |

Accent reserved for: `Open transaction`, `Open row history`, `Open timeline`, valid `Queue Timeline export`, valid `Download export`, `Review evidence`, selected actor time window, route pivots, focus-visible rings/borders, and selected/current state. Do not use accent to decorate metric cards, trust rails, or non-action headings.

Additional semantic colors:

| Semantic | Token | Reserved for |
|----------|-------|--------------|
| Signal | `--tl-color-signal` | Copy success, correlation/live trace cues, positive system flow only |
| Warning | `--tl-color-warning-*` | Redaction drift, retention destructive context, reconnect/stale states, capped/expiring export warnings |

| Danger | `--tl-color-danger-*` | Failed exports, failed retention runs, deletion/prune consequence, invalid context errors |

Color never carries status alone. Pair status colors with text, icons, chips, status stripes, or role-specific copy.

- Use Threadline nouns exactly: Timeline, transaction, row history, actor, correlation id, Evidence, Exports, Redaction, Retention, export job, retention run, policy name, audit readiness.
- Actions must be specific verb plus object: `Open transaction`, `Open row history`, `Review evidence`, `Download export`, `Run retention prune`, `Prune records permanently`.

- Destructive copy must name the object (`retention window`, policy `default`) and consequence (`permanently deletes audit records older than the retention window`; `cannot be undone`).
- Avoid hype, marketing phrasing, SIEM/compliance-suite framing, exclamation marks, and vague verbs such as `Continue` for destructive actions.

## Detail Page Contract

The Transaction, Row History, and Actor pages must align on anatomy, refs, copy, and state handling.

### Shared Detail Anatomy

| Region | Contract |
|--------|----------|
| Shell | Use `UI.shell/1` with `current={:timeline}` because these are investigation drill-downs. Preserve existing theme, coverage, feature-gate, scope, and script assigns. |
| Page header | Use `UI.page_header/1` with one H1, compact lede, and breadcrumbs back to Timeline. Breadcrumb current item must not add a second `aria-current="page"` in conflict with shell nav. |
| Object summary | Use `UI.detail_header/1` or equivalent one-object summary directly after page header. Title is the human-readable object label; metadata rows use `UI.kv/1`. |
| Metadata | Render only useful facts above the fold: actor, correlation id, table, record id, selected/as-of time, window, count, and status. Dense raw maps stay inside details, drawers, or rows. |
| Refs | Use `UI.ref/1` for transaction ids, actor ids, correlation ids, row ids, retention/export/evidence refs, and policy-like technical anchors. Copy labels must name the object (`Copy transaction id`, `Copy row id`, `Copy actor id`). |
| Row/action list | Use scan-first row/list patterns or `UI.data_table/1`; do not turn detail drill-downs into full-width metadata tables. |
| State shell | Use `UI.data_panel/1` or the named state family for loading, empty, error, permission, unavailable, redacted, pruned, and stale states. Avoid hand-rolled `<div class="tl-empty">` for new/retuned states. |
| Actions | Primary detail actions remain investigation pivots: `Open transaction`, `Open row history`, `Open timeline`, `Review evidence` when feature-enabled. Do not add generic page-level CTAs. |

## Governance Workflow Contract

Evidence, Exports, Redaction, and Retention must read as focused workflows, not dense metadata dumps.

### Shared Governance Anatomy

| Region | Contract |
|--------|----------|
| Page header | One compact `UI.page_header/1` with H1, lede, and at most one primary action in the header actions slot. |
| Workflow summary | One summary/decision unit directly below header. It answers the page's main question before rows: evidence scope, export handoff/download readiness, redaction drift, or retention health/destructive readiness. |
| Supporting actions | Coverage/Evidence/Timeline/Exports links are contextual and feature-gated. Do not repeat the same generic cross-page CTA in header, trust rail, empty state, and row actions. |
| Data body | Use `UI.data_panel/1`, `UI.data_table/1`, or card/list patterns. Collapse raw comparison details behind native `<details>` when the summary already answers the state. |
| Recent-only lists | Exports and Retention keep honest captions: `Showing the most recent N ... (newest first).` Do not imply full history or exact deep totals. |

### Evidence

| Element | Contract |
|---------|----------|
| Main question | "What proof exists for this subject/ref, and where should I go next?" |
| Summary | Show current mode (`Latest projection` or `Append-only history`), subject filter if any, and subject ref if any. |
| Records | Group by subject. Each record card shows verdict chip, proof label, subject, copyable subject ref, recorded time, and only relevant actions. |
| History | `Open proof history` appears only in latest mode. `Back to latest for {subject}` appears in history mode when a subject exists. |
| Handoff | `Carry to Exports` appears only when exports are enabled and the request shape is valid. It is not rendered as a disabled dead link. |
| Invalid request | Use `role="alert"` and copy from parser errors. Keep the operator on Evidence with recovery links to Overview/subject when possible. |

### Exports

| Element | Contract |
|---------|----------|
| Main question | "What can I download, what is still processing, and how do I reopen the source search?" |
| Context handoff | Timeline/Evidence context panels show only when query params exist. Valid context gets one primary action; invalid context gets a `role="alert"` with the fix path. |
| Jobs | Group by readiness/status. Each job shows status chip, human summary, actor ref, timestamps, filters, source search link when filters exist, and failure recovery copy when failed. |
| Completed download | A downloadable job renders a real, focusable `<a href="/exports/download/{id}">Download export</a>` styled as the primary compact button. It must not have `aria-disabled="true"` or `tabindex="-1"`. Do not mark normal HTTP downloads as `data-tl-mutating` if the controller can serve them while LiveView is reconnecting. |
| Unavailable download | Pending, running, failed, expired, unauthorized, or gated jobs render status text such as `Queued`, `Processing`, `Expired`, or `Failed`; do not render a fake disabled download link with an active `href`. |
| Queue action | `Queue Timeline export` is a native button. It is visible only for valid context and exports-enabled state; while LiveView is mutating/reconnecting it uses `data-tl-mutating`, `phx-disable-with`, and/or real `disabled` where applicable. |
| Export security | LiveView visibility is not the security boundary. Direct downloads remain protected by `ExportController`, `ExportAuthPlug`, and canonical `FilterParams`. |

### Redaction

| Element | Contract |
|---------|----------|
| Main question | "Does deployed trigger redaction match configured policy?" |
| Summary | One verdict area with drift count, introspection failure count, and deployed-matches-config count. If no drift/failures, show the all-clear copy above. |
| Sections | Use sections for `Drift detected`, `Could not introspect`, and `Deployed matches config`. Empty sections use short status copy; do not render large blank tables. |
| Row details | Native `<details>` may expose configured vs deployed `exclude`, `mask`, and placeholder values. Summary row shows table, status, hint, and contextual actions. |
| Actions | `View activity`, `Check coverage`, and `Review evidence` are feature-gated/contextual. Do not add a runtime redaction destructive button or modal. |

### Retention

| Element | Contract |
|---------|----------|
| Main question | "Is the retention window healthy, and what happens if I prune now?" |
| Summary | One retention summary with latest run, latest completed run, rows deleted, and failures. Failure count can link to the first failed run anchor. |
| Health alert | Success and warning alerts must state whether the latest run succeeded and that pruning permanently deletes older audit records by policy. |
| Run list | Use `UI.data_table/1` with run id, status, deleted rows, duration, date, and contextual row menu. Run id uses `UI.ref/1`. |
| Empty state | Use `UI.empty_state/1` with the Retention empty copy above and a danger action to open the prune modal. |
| Destructive action location | A single visible page-level destructive action is enough. Row-menu prune is allowed only if it opens the same policy-level modal and does not imply row-specific deletion. |

## Export And Feature-Gate Controls

| Control state | Required behavior |
|---------------|-------------------|
| Feature disabled route | Render `UnsupportedView` for the route and remove the nav group/link through existing shell gates. Do not render inert controls inside the disabled page. |
| Feature gated link in enabled page | If the destination feature is disabled, omit the link entirely rather than showing a disabled link, unless a visible explanation is needed. |
| Native button unavailable | Use real `disabled` plus visible disabled styling. `aria-disabled` on the container is supplemental only. |
| Native link unavailable | Prefer no link. If a link-shaped affordance must remain visible, remove `href` and add `aria-disabled="true"` plus `tabindex="-1"`; never leave an active `href` on an unavailable action. |
| Normal HTTP download | Render a real focusable link. Do not set `aria-disabled="true"`, `tabindex="-1"`, or reconnect-mutating dimming on a completed download. |
| LiveView mutating action | Use native button, `data-tl-mutating`, visible loading/disabled affordance, and server-side enforcement. Dimming alone is not enforcement. |
| Keyboard | All enabled controls are reachable in a sensible DOM order. Disabled/unavailable controls are not keyboard traps. |
| Assistive tech | `role="status"` for progress/caption/status text; `role="alert"` for invalid context, failed load, or destructive error. |

## Retention Destructive Flow

Retention prune is the only destructive action in Phase 186.

| Step | Contract |
|------|----------|
| Open | Button label `Run retention prune`; icon `trash`; opens the modal with `JS.push_focus()` before `open_prune_modal`. |
| Modal title | `Prune retention window permanently?` |
| Consequence copy | `This permanently deletes audit records older than the retention window for policy default; it cannot be undone.` |
| Type to confirm | Input label `Type the policy name default to confirm`; typed value posts under `confirm`; no client-side comparison is trusted. |
| Initial focus | Text input has `data-tl-initial-focus`; modal focuses into the dialog on open. |
| Cancel | Button label `Keep retention window`; closes modal and restores focus to the opener. |
| Submit | Button label `Prune records permanently`; danger variant; `data-tl-mutating`; no generic `Continue`. |
| Server checks | Event re-checks policy authorization, derives canonical policy name server-side, uses `Plug.Crypto.secure_compare/2`, audits the action before triggering prune, triggers backend only after audit success, and fails closed. |
| Mismatch | Close modal and flash `Could not prune - confirmation did not match.` No prune and no destructive audit action. |
| Runtime unavailable | Close modal and flash `Retention runtime is not started.` |
| Success | Close modal, schedule refresh, and flash `Retention prune started. Follow retention runs here.` |
| Reconnect safety | While the LiveView socket is loading/erroring, `[data-tl-mutating]` controls dim and ignore pointer events. Buttons still rely on server enforcement; link-shaped mutating controls must also use `aria-disabled="true"` and `tabindex="-1"`. |

## Responsive And Accessibility Contract

| Viewport | Required behavior |
|----------|-------------------|
| 320 px | No horizontal document overflow. Detail metadata, refs, copy buttons, tables, drawer, modal, and job cards wrap safely. |
| 375 px | Retention destructive modal shows title, consequence, input, `Keep retention window`, and submit without the submit button being hidden off-screen. |
| 768 px | Shell rail remains usable; detail/governance content remains the primary task area; summary grids may become two columns only if labels remain readable. |
| 1024 px | Detail pages can align summary actions trailing, but object metadata remains readable before row lists. |
| 1440 px | Wider layout may group governance cards, but pages still read top-to-bottom as workflows rather than dashboards. |

Keyboard and screen-reader rules:

- The skip link and `#tl-main` focus contract from `UI.shell/1` remains intact.
- Enabled buttons, links, details summaries, segmented controls, dropdown triggers, modal controls, drawer close controls, copy controls, and date/time inputs have visible focus rings.
- Every copy control has an object-specific accessible name and copies the full source value.
- Native `<details>/<summary>` keeps native keyboard behavior for redaction row details and any row-level disclosure.
- Dropdown menus expose `aria-haspopup="menu"`, `aria-expanded`, and `role="menu"`/`role="menuitem"` as existing `UI.dropdown/1` provides. Do not hide primary row actions inside a dropdown.
