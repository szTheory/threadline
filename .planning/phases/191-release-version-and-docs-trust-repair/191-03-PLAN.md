<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adopter -> install snippet / SSOT claim | A stranger copies the install pin and reads the "current version" claim to decide what to install and whether to trust the repo; a stale pin or false SSOT claim routes them to the wrong version and erodes trust. |
| maintainer -> drift guard | The drift-guard test itself is trusted to stay honest; if it hardcodes the version it becomes the same footgun it guards. |
| release automation -> version injection | release-please writes the full major.minor.patch; injecting a pin would born-red every patch release. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-191-02 | Spoofing/Repudiation | false "current version" SSOT claim | medium | mitigate | Correct evaluating-threadline.md line 11 to 0.9.0 + x-release-please-version marker; Family B enforces every marked line carries @version and is registered in extra-files (auto-injected, born-red-proof by identity). |
| T-191-03 | Tampering | drift-guard hardcoding the version | low | mitigate | version_truth_doc_contract_test derives from `@version` and never hardcodes; three-segment `.0` derivation keeps patch releases green by construction. |
