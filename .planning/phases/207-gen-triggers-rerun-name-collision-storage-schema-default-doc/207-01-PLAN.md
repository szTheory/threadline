<objective>
Make the SQL a rerun trigger migration emits actually apply on PostgreSQL (the deeper half of
audit item W1, found during discussion): switch the trigger DDL to `CREATE OR REPLACE TRIGGER`
(D-03), add a non-cascading drop for a leftover per-table capture function (D-05 helper), and
prove both on the real database with a new DB-tier test file (D-09). Verify catalog introspection
is untouched (D-04).

Purpose: even with a unique migration name, a rerun migration fails today at migrate time with
PostgreSQL's `trigger "threadline_audit_<t>" for relation "<t>" already exists`. This plan
removes that failure in one statement with no capture gap. PostgreSQL 14 (the documented floor,
README.md:102, CI min lane) supports OR REPLACE for triggers.

Output: edited `lib/threadline/capture/trigger_sql.ex`, one edited unit test, one new DB-tier
test file. Plan 02 consumes `drop_orphan_function_for_table/2` from the generator.
