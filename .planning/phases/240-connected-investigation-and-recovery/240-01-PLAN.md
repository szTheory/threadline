<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser URL to LiveView | Origin, filters, and as-of are untrusted navigation/display inputs. |
| Host auth to scoped reads | Host authorization/scope is authoritative and cannot be replaced by URL state. |
| Parent transaction to child history | Child reads must not proceed after parent unavailability. |

## Applicable ASVS Level 1 Controls

| Control | Planned mitigation |
|---|---|
| V4 Access Control | Re-evaluate current host authorization/scope and gate child reads on available parent transaction. |
| V5 Input Validation | Validate bounded origin/as-of and accept only supported canonical filter keys. |
| V7 Error Handling | Keep unavailable, empty, absent, pruned, and never-captured states distinct without leaking exception details. |
| V8 Data Protection | Preserve redaction and authorized-only copy eligibility; never render hidden values in attributes or feedback. |

| T-240-02 | Elevation of Privilege | Existing host-scoped reads | high | mitigate | Re-evaluate host authorization/scope on every route; never derive them from query state. |
| T-240-03 | Information Disclosure | TransactionLive child-history boundary | high | mitigate | Render/query child history only after parent availability; retain distinct evidence states. |
