<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Home form input -> LiveView navigation | User-controlled record ids, table selections, and correlation ids drive cross-surface routes. |
| schema map -> row-history target | Configured `:schemas` keys determine which tables may be selected. |
| correlation input -> Timeline filters | User-provided correlation id becomes a Timeline query param. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-140-05 | Tampering | record-first table selector | mitigate | Accept only keys present in `threadline_schemas`; reject blanks/unmapped values; never build raw SQL identifiers. |
| T-140-06 | Denial of service | correlation paste | mitigate | Trim, reject blank input, and enforce the existing 256-byte limit before navigation. |
| T-140-07 | Tampering | Timeline query construction | mitigate | Use `FilterParams.canonical_query/1` for correlation navigation and keep Timeline validation as the destination authority. |
| T-140-08 | Information disclosure | scoped Home entry | mitigate | Home only navigates to row-history/Timeline surfaces that remain under existing auth and scope; add scoped Home regression tests. |
| T-140-09 | Repudiation | earned-flow traceability | mitigate | Render EF/persona/JTBD data attributes and test them so shipped controls trace to locked IA records. |
| T-140-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs are planned; any attempted install must stop for slopcheck/package legitimacy review. |
</threat_model>
