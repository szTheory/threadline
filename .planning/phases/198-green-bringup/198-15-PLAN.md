<objective>
Close Gap 2: `test/threadline/operator_surface/stress_router_test.exs:310` shells out to
`cd examples/threadline_phoenix && MIX_ENV=test mix run --no-start -e '...'` and asserts
`status == 0`. In CI the example app's dependencies are not fetched, mix aborts with "Can't
continue due to errors on dependencies", and both `Run test suite (min)` and `Run test suite
(current)` go red.

Purpose: this test passes locally **only because** 198-13's executor happened to run
`mix deps.get` inside `examples/threadline_phoenix`. CI reports 1399 tests where local reports
1398 — this test never executed in any local verification run, which is why every local pass was
misleading. That is the same failure shape as the storage-schema defect this phase exists to kill:
a test whose outcome is decided by ambient machine state rather than by the repository.

Output: a test whose result depends only on the repo plus declared setup, with the runtime
route-mount coverage either kept in place or explicitly relocated to a named guard that runs in a
required CI check.

**The bar is not "green".** It is "cannot silently pass or fail for an environmental reason
again". A fix that makes CI green while leaving the outcome contingent on unrecorded local state
fails this plan even if every check turns green.
</objective>
