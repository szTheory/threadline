<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull request → CI runner | Contributor-authored code executes in the browser lane and the test matrix |
| restored cache → build output | A cache entry restored across lanes or across a changed lockfile can inject stale compiled artifacts into a verification run |
| scheduled workflow → issue tracker | The nightly lane writes to the repository's issues with a token |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-198-05-01 | Tampering | shared cache entry across matrix lanes | high | mitigate | The current key resolves identically for both runners, so the min lane can be verified against artifacts built for the current lane — a false green on the floor promise. Mitigated by keying on runner, OTP, Elixir and lockfile hash, removing build restore-keys, and purging the library's own build output before compiling. |
| T-198-05-02 | Denial of Service | unbounded jobs across five workflows | high | mitigate | Zero timeout bounds exist today and the concurrency rule never cancels push-to-main, so a hang bills to the six-hour ceiling. Task 3 bounds every job and adds a step-level bound inside the browser job. |
| T-198-05-03 | Repudiation | coverage silently moved to nightly | medium | mitigate | The CI Coverage table plus its contract test make the move visible and asserted; the nightly failure path opens or updates a tracking issue rather than failing silently. |
| T-198-05-04 | Elevation of Privilege | issue-writing token in the nightly workflow | medium | mitigate | Grant the workflow only the issue-write permission it needs at the job level rather than inheriting broad defaults; the workflow performs no checkout-and-execute of contributor code beyond the same suite the pull-request lane runs. |
| T-198-05-05 | Information Disclosure | failure-artifact upload | low | accept | Traces and the boot log may contain seeded demo data. Accepted: the example app's seed data is synthetic and already public in the repository. |
</threat_model>
