  <action>
    Establish availability first: run `gitleaks version` and `trufflehog --version`, recording both verbatim. If either is missing, install it; if installation is not possible, write the UNAVAILABLE record and halt the plan.

    Run four sweeps and commit each report under `.planning/audits/`:

    1. Full-history gitleaks: `gitleaks detect --source . --log-opts="--all --full-history" --report-format json --report-path .planning/audits/198-gitleaks-history.json --redact --exit-code 0`. Use `--exit-code 0` so a finding does not abort the sweep before the other scanners run; the verdict is decided in Task 2, not by an exit code here. Use `--redact` so the report itself does not publish the secret it found.
    2. Untracked working-tree gitleaks: `gitleaks detect --no-git --source . --report-format json --report-path .planning/audits/198-gitleaks-worktree.json --redact --exit-code 0`.
    3. Verified-mode trufflehog: `trufflehog git file://. --json --only-verified > .planning/audits/198-trufflehog-verified.json`. Verified mode calls the provider to test liveness — this is the one capability gitleaks lacks and the reason D-28 locks running both.
    4. Ever-added-then-removed sweep: `git log --all --full-history --diff-filter=A --name-only --pretty=format:'%H %ad' --date=short -- '*.env' '*.env.*' '*.pem' '*id_rsa*' '*credentials*' '*.netrc'` and append the raw output as a fenced section into `.planning/audits/198-credential-audit.md` under `## Ever-added credential-shaped files`.

    Record each sweep's command line verbatim, its exit status, and its finding count in the audit artifact's `## Scans run` table.

    Commit with message `docs(198): full-history credential scan reports (D-28)`.
  </action>
  <verify>

  </verify>
  <acceptance_criteria>
