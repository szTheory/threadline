<objective>
Restore the teeth that round 4's own hardening removed. REVIEW.md found that three of the changes
*sold* as anti-vacuity improvements are themselves vacuous, tautological, or a net deletion:

- **CR-02** — `assert coverage_html =~ "Covered"` / `=~ "Needs capture"` in
  `walkthrough_evidence_test.exs:88-95` carries an in-code comment claiming that "a database that is
  either all-covered or entirely empty of triggers cannot satisfy this assertion". It can.
  `coverage_live.ex:291-297` renders both strings as static `<dt>` labels in the verdict-counts block,
  independent of the counts, and `Presentation.status_label("covered")` returns `"Captured"` — so
  `"Covered"` can only ever come from the static legend. Both assertions pass with both counts at zero.
- **CR-03** — `assert record.subject_ref == subject_ref` in `demo_contract_test.exs:249-266` replaced
  the inline literal `%{"policy" => "walk-demo-redaction-policy"}`. But
  `Threadline.Evidence.list_subject_ref_history/3` puts `subject` and `subject_ref` into the SQL
  filter, so every returned record satisfies that equality by construction. The inline literal *was*
  the teeth; deleting it left `length(records) >= 1` as the block's only load-bearing assertion.
- **WR-10** — `refute timeline_html =~ "View Incident"` was deleted when the route moved to
  `~p"/audit/timeline"` and the positive `assert timeline_html =~ "No captured changes"` was added.
  The positive assertion is genuinely stronger, but the negative cost nothing to keep and guards a
  different failure: a page rendering both an empty-state banner and stale incident links satisfies
  the new assertion and would have failed the old one.

Purpose: make three assertions capable of failing again. Output: two example-app test files whose
coverage, evidence, and emptiness checks discriminate, each proven by a red-then-green perturbation.

unsatisfiable and must not be written). Row markup exists only when the corresponding set is
non-empty, which is exactly the discrimination CR-02 asks for.

is chosen, rewrite the adjacent comment so it states the property the assertion actually has. The
current comment claims a guarantee the code does not provide, and a comment that overclaims is the
mechanism by which this vacuity survived review once already.

`assert timeline_html =~ "No captured changes"`. Keep the route at `~p"/audit/timeline"` — that part
