<objective>
TRACER for the GREEN-04 closure. Prove the chosen remediation shape end-to-end on one
representative file, and land the missing D-02 enforcement guard in the same wave so the
cheap-but-forbidden shortcut becomes red instead of green.

Purpose: 79 tests across 15 files address audit tables without a `prefix:`, relying on a
database `search_path` that decision D-02 forbids. The single cheapest way to turn all 79
green is exactly the thing D-02 prohibits, and — contrary to what `198-TRIAGE.md` claims —
nothing in the suite currently detects it. This plan fixes one file so plan 198-12 can port
the other fourteen mechanically, and adds the guard that makes the forbidden shortcut fail.

Output: one green file, one new contract-test module with behavioural teeth.

**Remediation shape — DECIDED, not open.** Route every defective call site through
`Threadline.StorageSchemaCase.repo_opts/0`, passing it as the trailing opts argument of the
existing Ecto call. This is TRIAGE option 2. It is chosen over option 1 (a hardcoded
`prefix: "threadline"` literal at each site) because a literal re-pins what
`Threadline.StorageSchema` already owns, and over option 3 (a prefixed repo wrapper aliased
inside `DataCase`) because option 3 silently changes what `Repo` means inside every
`DataCase` test and reaches only 10 of the 15 defective files.

Justified from the measured distribution: all 81 defective call sites are Ecto functions that
already accept an opts list (`insert!/2`, `all/2`, `get!/3`, `delete_all/2`, `aggregate/3`);
`Threadline.DataCase` already imports `Threadline.StorageSchemaCase`, so `repo_opts/0` is in
scope unused in 10 of 15 files; and the idiom is already green in-repo at
`test/threadline/operator_surface/live/actor_live_test.exs:139-165`,
`test/threadline/export_test.exs:10,19`, `investigation_test.exs:28,37`, `query_test.exs:14,23`,
and `retention_test.exs:8,20`.

**TRIAGE correction, recorded here because 198-12 depends on it.**
`198-TRIAGE.md:147-168` rejects option 3 partly on the ground that it "does not help the raw
`Repo.query!` SQL those same tests use." That premise is false. There is no defective
audit-table raw SQL: the raw-SQL sites in the trigger tests target `public` fixture tables and
the `TriggerSQL` DDL (which resolves the storage schema internally via
`Threadline.StorageSchema.function/2`), and the one audit-table raw SQL,
`test/threadline/capture/trigger_test.exs:110`, is already schema-qualified. Option 3 is
rejected on its remaining objection alone.
</objective>
