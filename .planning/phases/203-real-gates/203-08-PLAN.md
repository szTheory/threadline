## Shared procedure (Plans 08 and 09)

Record the plan base first (Task 1 step 0): `git rev-parse HEAD > "$(git rev-parse --git-dir)/gsd-203-NN-base"` with this plan's number, and copy the SHA into the SUMMARY.

Live structural measurement: `ASDF_ERLANG_VERSION=27.3 ASDF_ELIXIR_VERSION=1.17.3-otp-27 sh -c 'mix compile >/dev/null 2>&1; mix credo --strict --config-file deps/credo/.credo.exs --format json' | jq -r '.issues[] | select(.check=="Credo.Check.Refactor.Nesting" or .check=="Credo.Check.Refactor.CyclomaticComplexity") | "\(.filename):\(.line_no) \(.check) \(.message)"'`. Plans 01-07 shifted every line number, so RESEARCH Appendix A is a cross-check only.

**Read scope (context budget):** for each site, read the enclosing function only (locate its `def`/`defp` head with grep, then Read with offset/limit through its `end`). Never read a long file whole.

For each site:

(a) Decide whether to flatten or file. Flatten in place only for a Nesting site where replacing nested `case`/`if` with `with` or an early-return clause removes the finding without creating, extracting, or splitting any function and without changing behavior. Every CyclomaticComplexity site is filed: reducing complexity below 9 needs a function split, which is Phase 204's work. Do not flatten anything in `query/scope.ex`, `operator_surface/auth.ex`, or `session_plug.ex` (auth/tenant paths); file them.

(b) To file a site, insert two comment lines directly above the reported line, at that line's indentation. First line: `# Phase 204 (STRUCT-07): ` followed by a short concrete reason, for example "cyclomatic complexity 33 — split resolve!/1 per option group" or "nested case inside reduce — extract the per-row branch". Second line: `# credo:disable-for-next-line Credo.Check.Refactor.Nesting`, or the `CyclomaticComplexity` equivalent, with nothing after the check name. For CyclomaticComplexity, the reported line is the `def`/`defp` head. For Nesting, it is the nested construct.

(c) After each file, re-run the measurement filtered to that file. Its structural count must be 0; a non-zero count means a disable is on the wrong line. Run `mix compile --warnings-as-errors` and the file's tests. Commit one file per commit: `refactor(203-NN): file structural Credo findings to Phase 204 in <path>`, with a body that lists each site as check, line, and reason. If a site was flattened, use `refactor(203-NN): flatten nested <construct> in <path>` and keep it separate from the filing commit for that file.

Keep a running tally of filed Nesting, filed CyclomaticComplexity, and flattened sites in the SUMMARY; Plan 09 builds the register from it.
