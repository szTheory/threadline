## Shared procedure (Plans 03, 04, 05)

Record the plan base first (Task 1 step 0): `git rev-parse HEAD > "$(git rev-parse --git-dir)/gsd-203-03-base"`, and copy the SHA into the SUMMARY. The file lives in the git dir, so it is never staged.

Measure per file with `ASDF_ERLANG_VERSION=27.3 ASDF_ELIXIR_VERSION=1.17.3-otp-27 sh -c 'mix compile >/dev/null 2>&1; mix credo --strict --config-file deps/credo/.credo.exs --format json' | jq -r '.issues[] | select(.check=="Credo.Check.Design.AliasUsage") | "\(.filename):\(.line_no) \(.message)"'`. Never edit `.credo.exs` to measure.

**Read scope (context budget):** for each file, read only (1) its alias block(s), located with `grep -nE '^\s*(alias|import|require|use) '`, and (2) each Credo-flagged line with about 3 lines of context (`sed -n` or Read with offset/limit). Read a whole file only if it is under about 150 lines or a flagged line sits inside a construct you cannot understand from context. For multi-module files, locate every `defmodule` line with grep so you know which module body each flagged line belongs to.

For each (file, module) pair:
- Add `alias Full.Module.Name` to the enclosing module's alias block, one alias per line and alphabetical after any `require`/`import` lines, following the `lib/threadline/query.ex` alias-block house form.
- Replace the fully-qualified call sites with the short name.
- Use `as:` only when the short name already exists in that lexical scope.
- In multi-module files, alias inside each module body that uses the name.
- Inside Phoenix `scope "...", SomeAlias do` router blocks, do not alias a route target whose resolution depends on the scope prefix. Keep module names in route-target position fully qualified if aliasing them changes resolution, and prove this with the file's own tests.

After each file, run `mix compile --warnings-as-errors`, then that file's own test (or the lib file's test counterpart), before committing. If an inserted alias triggers AliasOrder, fix the order in the same commit (D-10). Never mix any other finding's fix into these commits.

Commit message template (D-28): `refactor(203-NN): alias repeated module references in <path-or-dir>`. Body: "Mechanical Credo sweep: Design.AliasUsage (+ Readability.AliasOrder it caused). No behavior change. Verified: <commands>."

Pre-existing AliasOrder sites (11 on 2026-09-22, after Plan 01's in-place rename): lib `threadline.ex`, `operator_surface/live/coverage_live.ex`, `export_status_live.ex`, `retention_history_live.ex`, `start_live.ex`, `timeline_live.ex`; test `support/data_case.ex`, `support/storage_schema_case.ex`, `threadline/export_queue/task_adapter_test.exs`, `threadline/operator_surface/copy_contract_test.exs`, `threadline/storage_schema_integration_test.exs`. Those not absorbed by an alias plan are owned by Plan 06 (lib) and Plan 07 (test).
