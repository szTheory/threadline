## Shared procedure for every task

Measure first, per file, with `ASDF_ERLANG_VERSION=27.3 ASDF_ELIXIR_VERSION=1.17.3-otp-27 sh -c 'mix compile >/dev/null 2>&1; mix credo --strict --config-file deps/credo/.credo.exs --format json' | jq -r '.issues[] | select(.check=="Credo.Check.Design.AliasUsage") | "\(.filename):\(.line_no) \(.message)"'`. Never edit `.credo.exs` to measure.

For each (file, module) pair:
- Add `alias Full.Module.Name` to the enclosing module's alias block, one alias per line and alphabetical after any `require`/`import` lines, following the `lib/threadline/query.ex` alias-block house form.
- Replace the fully-qualified call sites with the short name.
- Use `as:` only when the short name already exists in that lexical scope.
- In multi-module files, alias inside each module body that uses the name.
- Inside Phoenix `scope "...", SomeAlias do` router blocks, do not alias a route target whose resolution depends on the scope prefix. Keep function captures that name a module in route-target position fully qualified if aliasing them changes resolution, and prove this with the file's own tests.

After each file, run `mix compile --warnings-as-errors`, then that file's own test (or the lib file's test counterpart), before committing. If an inserted alias triggers AliasOrder, fix the order in the same commit (D-10). Never mix any other finding's fix into these commits.

Commit message template (D-28): `refactor(203-03): alias repeated module references in <path-or-dir>`. Body: "Mechanical Credo sweep: Design.AliasUsage (+ Readability.AliasOrder it caused). No behavior change. Verified: <commands>."
