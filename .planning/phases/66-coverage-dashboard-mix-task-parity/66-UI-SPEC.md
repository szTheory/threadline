## Component Inventory

### New: `.threadline-ui-header` (surface header)

Position: `position: sticky; top: 0; z-index: 2` — sits above `.timeline-toolbar` (which is `z-index: 1`).
Height: exactly `var(--tl-header-height, 36px)`.
Background: `var(--tl-color-main)` (white).
Border-bottom: `1px solid var(--tl-color-secondary)`.
Layout: `display: flex; align-items: center; padding: 0 var(--tl-spacing-md); gap: var(--tl-spacing-md)`.
Contains: brand wordmark (text "Threadline" at `--tl-font-label`, weight 400) + the `.surface-badge` anchor at the right end.

### New: `.surface-badge` anchor (coverage pill)

An `<a>` anchor (not `live_patch`) linking to `"#{base_path}/coverage"`.
Font size: `--tl-font-label` (12px).
Border-radius: 12px (pill shape).
Padding: `4px 8px`.
No fill by default.

**State: `.surface-badge--ok` (zero uncovered)**
Content: `"All covered"` (exact literal — LOCKED by D-31a and D-35).
Color: `var(--tl-color-text-muted)` (`#6B7280`).
Background: transparent.
Border: `1px solid var(--tl-color-secondary)`.
**The badge is NEVER hidden in the ok state** (D-31a: explicit reassurance matters for operator trust).

**State: `.surface-badge--warn` (uncovered > 0)**
Content: `"{n} uncovered"` — where `{n}` is the integer `uncovered_count` (exact format — LOCKED by D-35).
Background: `#FEF3C7`.
Color: `#92400E`.
Border-left: `3px solid #F59E0B` (matches truncation-banner.warning treatment).

**State: stale indicator (`:threadline_coverage_error` set)**
The badge renders the previous count + a sibling `<span>` with `"stale (last checked Xs ago)"` in `--tl-color-text-muted`. No separate state class — the badge state class reflects the LAST GOOD result.

### New: `.coverage-table`

A plain HTML `<table>` inside `.threadline-ui`.
No border-collapse complexity — `border-collapse: collapse`.
Width: 100% of container.
Header row: 12px label, weight 600, `var(--tl-color-text-muted)`, border-bottom `1px solid var(--tl-color-secondary)`.
Cell padding: `var(--tl-spacing-sm) var(--tl-spacing-md)`.
Columns: TABLE | STATUS | SOURCE (source only populated for `expected` rows).

### New: `.coverage-row--covered`, `.coverage-row--uncovered`, `.coverage-row--expected`

Row background and text treatment per bucket:

| Class | Background | Text | Badge literal |
|-------|-----------|------|---------------|
| `.coverage-row--covered` | transparent | `var(--tl-color-text)` | `"covered"` (LOCKED) |
| `.coverage-row--uncovered` | `rgba(239,68,68,0.06)` (destructive tint, 6%) | `var(--tl-color-text)` | `"uncovered"` (LOCKED) |
| `.coverage-row--expected` | `var(--tl-color-secondary)` | `var(--tl-color-text-muted)` | `"expected"` (LOCKED) |

**Badge literals are case-sensitive and exact** (D-32d, D-35): `"covered"`, `"uncovered"`, `"expected"`. Not `"ok"`, `"missing"`, `"not_covered"`, `"untracked"`, or any variant. Doc-contract test pins these.

### New: on-poll-error inline strip on `CoverageLive`

An inline strip above the coverage table when `:threadline_coverage_error` is set.
Class: `truncation-banner warning` (reuses Phase 65's warning band styles — same amber palette).
Copy (LOCKED by D-30c): `"Coverage check failed at {time} — showing last successful result from {last_checked_at}."` where `{time}` is the error timestamp and `{last_checked_at}` is the last-good check time.
The strip is additive — it appears alongside the last-good table, not instead of it.

### New: schema validation error on `CoverageLive`

When `?schema=NAME` fails regex or `pg_namespace` lookup.
Class: `filter-error` (reuses Phase 64's pattern — same destructive red).
Copy (LOCKED by D-33a): `"Schema '{NAME}' not found."` — where `{NAME}` is the raw param value.
Renders instead of the coverage table (no partial results on invalid schema).

├─────────────────────────────────────────────────────────────┤
│ [on-poll-error strip — amber — only when error]              │
├─────────────────────────────────────────────────────────────┤
│ .coverage-table                                              │
│  TABLE          STATUS      SOURCE                           │
│  users          covered                                      │
│  posts          covered                                      │
│  orders         uncovered                                    │
│  schema_migr.   expected    baseline                         │
│  oban_jobs      expected    config                           │
├─────────────────────────────────────────────────────────────┤
│ Coverage: N covered, M uncovered, K expected uncovered       │
└─────────────────────────────────────────────────────────────┘

**Page header copy:** `"Coverage — schema: {name}"` — where `{name}` is the schema param (default `"public"`). Exact format (LOCKED by D-33). Renders as `<h2>` with existing `.transaction-header h2` style treatment (18px, weight 600).

**"Last checked" timestamp:** static render, updated on each 30-second poll tick (static text re-render, no 1Hz timer). Format: `"Last checked Xs ago"` — where `X` is elapsed seconds since `:last_checked_at`.

**"Refresh" affordance:** a plain text link (`<a phx-click="refresh">Refresh</a>`) beside the timestamp. Cancels pending timer, fetches immediately, reschedules. Only on `CoverageLive`; not on Timeline/Transaction/Actor (D-30b).

**Footer summary:** `"Coverage: N covered, M uncovered, K expected uncovered"` — rendered below the table as `<p class="filter-hint">`.

## Machine Surface: Mix Task Output

### `mix threadline.health.coverage` (default table format)

80-column readable. Three-section table with headers. Source: CONTEXT.md D-34.

```
TABLE                STATUS      SOURCE
users                covered
posts                covered
orders               uncovered
schema_migrations    expected    baseline
oban_jobs            expected    config

Coverage: 2 covered, 1 uncovered, 2 expected uncovered
```

Column widths: TABLE left-padded to 24 chars, STATUS 12 chars, SOURCE remainder.
Separator: single blank line before summary footer.
Exit code: 0 always (viewer, not CI gate — the CI gate is `mix threadline.verify_coverage`).

### `mix threadline.health.coverage --json`

JSON output schema (LOCKED by D-34):

```json
{
  "schema": "public",
  "covered": ["users", "posts"],
  "uncovered": ["orders"],
  "expected_uncovered": [
    {"table": "schema_migrations", "source": "baseline"},
    {"table": "oban_jobs", "source": "config"}
  ]
}
```

Keys at top level (sorted): `"covered"`, `"expected_uncovered"`, `"schema"`, `"uncovered"`.
Keys in each `expected_uncovered` entry (sorted): `"source"`, `"table"`.
`"source"` values: `"baseline"` or `"config"` — no other values.
The `"schema"` field surfaces which schema was queried (audit-trail provenance).

## Interaction Contracts

### Polling (all LVs in `live_session :threadline`)

- `Coverage.OnMount` attaches at `live_session` level; fires `Process.send_after(self(), :threadline_refresh_coverage, 30_000)` after mount when `connected?(socket)`.
- Each tick: refetch via `Threadline.Health.trigger_coverage(repo: repo, schema: "public")`, update `:threadline_coverage` assign, reschedule.
- On error: keep previous assign, set `:threadline_coverage_error`, ALWAYS reschedule (D-30c).
- Floor: `5_000` ms — raise at mount below this with a clear message.
- Config override: `config :threadline, :coverage_poll_ms, 30_000`.

### Manual Refresh (CoverageLive only)

- User clicks `"Refresh"` link.
- Handler: cancel pending timer via `Process.cancel_timer(socket.assigns.threadline_timer_ref)`, fetch immediately, reschedule.
- No spinner — the re-render on assign update is sufficient feedback at human UI latency.

### Surface header badge click

- Plain `<a href={…}>` link (not `live_patch`) to `"#{base_path}/coverage"`.
- Full page navigate — correct because destination is a different LiveView module.

### Schema scope on `CoverageLive`

- Param: `?schema=NAME`.
- Absent → `"public"`.
- Present: two-layer validation (regex `~r/\A[a-z_][a-z0-9_]{0,62}\z/` then `pg_namespace` lookup).
- Invalid → render `filter-error` div with `"Schema '{NAME}' not found."` copy; no coverage table rendered.

### No LV state in URL (CoverageLive)

URL carries `?schema=NAME` only. Poll state, timer refs, last-checked timestamps are socket-only — never in URL params.
