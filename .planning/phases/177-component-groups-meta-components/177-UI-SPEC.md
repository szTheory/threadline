# Phase 177 — UI Design Contract

> Visual and interaction contract for the component-groups / meta-components phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Stack note:** Threadline is Elixir / Phoenix / LiveView with an internal, zero-dependency `--tl-*` token design system (`brandbook/tokens.css` + `lib/threadline/operator_surface/style.ex`). There is NO React / Tailwind / shadcn — the shadcn gate and registry-safety automation are **not applicable**. All tokens below are the project's already-shipped `--tl-*` truth, not new proposals, except the three semantic gap tokens called out as additive (D-09).
>
> **Phase shape:** This is *compose-and-audit*, not greenfield (mirrors 173–176). The constituent primitives already exist in `OperatorSurface.UI`. A "group" is the **assembly rule** between them. This contract therefore governs spacing rhythm, hierarchy, cross-child state coordination, and group motion — the things a group locks — rather than re-specifying primitive-level color/typography (settled in 172/173).

## Spacing Scale

The numeric scale is the **already-shipped** `--tl-space-*` ladder (`tokens.css` L6–16). All values are multiples of 4. Groups consume it; they do not invent per-call-site spacing.

> **Inherited / pre-locked primitive (documented exception).** The `--tl-space-*` ladder is the existing `brandbook/tokens.css` truth — settled and shipped (parity-tested by `brandbook_token_parity_test`), **not** new per-phase spacing introduced by Phase 177 (which is compose-and-audit, not new spacing design — see CONTEXT D-09 / D-14). Every step is a multiple of 4 (the spacing sub-rule passes). Some steps fall *outside* the enumerated standard set {4, 8, 16, 24, 32, 48, 64}: `--tl-space-3` (12px) and `--tl-space-5` (20px) are **in active use** by groups (12px = toolbar control gap + `kv` row gap; 20px in use), so they are kept as inherited truth and recorded as a **justified exception** rather than a new declaration. The unused reserved off-set steps `--tl-space-10` (40px) and `--tl-space-20` (80px) are **dropped from this phase's declared group scale** to shrink the surface — they remain in `tokens.css` but no group consumes them.

| Token | Value | Group usage |
|-------|-------|-------------|
| `--tl-space-1` | 4px | Icon↔label gaps, inline chip padding |
| `--tl-space-2` | 8px | Compact control spacing inside a cluster |
| `--tl-space-3` | 12px | Toolbar control gap; metadata `kv` row gap (inherited off-set step, in active use — see exception note) |
| `--tl-space-4` | 16px | Default element gap; data_panel inner padding |
| `--tl-space-5` | 20px | In use (inherited off-set step — see exception note) |
| `--tl-space-6` | 24px | Detail-header title↔metadata block gap |
| `--tl-space-8` | 32px | Section break between page-stack siblings |
| `--tl-space-12` | 48px | Major page-section break |
| `--tl-space-16` | 64px | Page-level top/bottom rhythm |

### Semantic gap tokens (D-09 — ADDITIVE, the only new tokens this phase)

`stack`/`cluster` consume *semantic* gap aliases layered over the numeric scale, so "intentional spacing" is named, not class-soup. Names below are a documented assumption per D-09/D-14 (final names match the `--tl-*` BEM idiom; lock at plan time). **Must land in `brandbook/tokens.{json,css}` first and keep `brandbook_token_parity_test` green** (DS-05 rule).

| Proposed token | Maps to | Semantic meaning |
|----------------|---------|------------------|
| `--tl-gap-inline` | `--tl-space-2` (8px) | Horizontal gap between related controls in a `cluster` (search + filter + sort) |
| `--tl-gap-stack` | `--tl-space-4` (16px) | Vertical rhythm between sibling blocks in a `stack` |
| `--tl-gap-section` | `--tl-space-8` (32px) | Vertical break between top-level page-stack sections |

Exceptions: touch targets follow A11Y comfort sizing (built-to here, formally audited Phase 180) — interactive controls keep their existing ≥ comfortable hit area from 173/174; no new spacing exception introduced. No fractional or off-scale values permitted.

## Typography

Type scale is the **already-shipped** `--tl-font-size-*` / `--tl-line-*` / `--tl-weight-*` ladder. Groups do not introduce new sizes or weights — they assign hierarchy from this set. The four roles a group actually uses:

> **Inherited / pre-locked primitive (documented exception).** Three font-weight tokens are referenced — `--tl-weight-regular` (400), `--tl-weight-medium` (500), `--tl-weight-strong` (600). These are **inherited, pre-locked `--tl-weight-*` primitive tokens settled in phases 172/173** (parity-tested by `brandbook_token_parity_test`), **not** introduced or redesigned by Phase 177, which is compose-and-audit, not new type design (see CONTEXT D-14 — exact tokens match the existing `ui.ex` `--tl-*` idioms). All three are kept because they are shipped truth, not new declarations; the standard 2-weight cap is therefore recorded as a **justified exception** for these inherited primitives rather than a new typographic decision.

| Role | Token (size) | Weight | Line height |
|------|--------------|--------|-------------|
| Body / cell text | `--tl-font-size-body` (16px) | `--tl-weight-regular` (400) | `--tl-line-body` (1.5) |
| Label / metadata key | `--tl-font-size-label` (14px) | `--tl-weight-medium` (500) | `--tl-line-label` (1.4) |
| Group / panel heading | `--tl-font-size-heading` (20px) | `--tl-weight-strong` (600) | `--tl-line-heading` (1.2) |
| Detail-header title | `--tl-font-size-title` (24px) | `--tl-weight-strong` (600) | `--tl-line-heading` (1.2) |

Hierarchy rule for groups: exactly one `<h1>` per page (page_header owns it, D-175-03); group/panel headings step down to `<h2>`/heading-size. Mono (`--tl-font-mono`) only for machine-readable values (IDs, ARNs, hashes) inside `ref`/`kv` cells, never for prose.

## Color

Dark is the brand-default lane; light/system are supported via `data-tl-theme` (165-01). The 60/30/10 split below describes the dark lane (light lane mirrors it token-for-token via the parity test). Groups inherit these surfaces — they introduce no new color.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--tl-color-threadline-black` (#0B1020) / `--tl-color-graphite` (#141B2D) | Page background, app shell |
| Secondary (30%) | `--tl-color-surface-raised-raw` (#1B253A), `--tl-color-slate-line` (#23304A) borders | Panels, cards (one boundary per logical unit, D-176-11), detail-header surface |
| Accent (10%) | `--tl-color-thread-blue` (#4F8CFF) | See reserved-for list below |
| Destructive | `--tl-color-danger` (#F06A6A) | Destructive-action affordance + confirm (T3 prune), separated & last-in-kebab (D-176-04) |
| Status (non-accent) | `--tl-color-warning` (#F3B94C) stale; `--tl-color-success` (#3FD08F); `--tl-color-steel` (#73819C) muted | State coordination signals (below); never color-alone — always paired with icon SHAPE + text |

**Accent (`--tl-color-thread-blue`) reserved for:** the single primary action in a group (page-header primary CTA, data_panel primary action), active tab/segment indicator, focus ring (`--tl-focus-color`), and in-flow links. NOT used for: every interactive element, default control borders, table chrome, or decorative emphasis. Stitch-blue (#4781E6) stays exclusive to the logo arc and is never a UI element color.

**Cross-child state colors do not rely on color alone (brand rule, A11Y-02):** loading = neutral + spinner shape + text; error = danger tint + distinct icon shape + heading; stale = `--tl-color-warning` banner + warning icon + `as_of` text; permission vs no-data vs unavailable each carry a **distinct icon shape** (`lock` / `funnel` / `cloud_off`) so the forensic distinction survives even when a panel collapses to one message (D-176-16).

## Group Spacing & Hierarchy Contract (GROUP-01)

The 12 configurations are audited as units on `/audit/__stress` at 320/375/768/1024/1440. Assembly rules:

- **stack** owns vertical rhythm (`--tl-gap-stack` between blocks, `--tl-gap-section` between top-level sections). No raw margins on children.
- **cluster** owns horizontal grouping with wrap (`--tl-gap-inline`), used for action bars, toolbars, breadcrumbs.
- **page_header + actions + breadcrumbs** → one canonical header; `:breadcrumbs` slot added alongside `:actions` (D-04). No second header component.
- **data_panel** (table + state family + pager) → table flush to panel edge, pager de-emphasized below (D-175-04 hide-at-zero / disable-not-hide), state region occupies the table's box.
- **toolbar** (search + filters + sort) → single `cluster`, consistent wrap, disabled-coordination baked in.
- **detail_header** (title + `kv` metadata + actions) → title (24px) → metadata block (`--tl-space-6` below) → actions cluster; recurs on transaction / actor / row-history.
- **Card discipline:** one card boundary per logical repeated unit only — never page-sections-inside-cards (brand L347, D-176-11). Groups compose flat page-stack `<section>` siblings.

## State Coordination Contract (GROUP-02 — "states aligned across children")

Scoped-by-state-kind; siblings react by state *kind*, not uniformly (D-06). The data_panel owns focus-move on transition (D-06c); branching to the right state stays the page author's job (D-06d).

| State kind | Data region | page_header (+breadcrumbs) | toolbar (filter/sort) | Focus move |
|------------|-------------|----------------------------|------------------------|------------|
| Loading | swap to `loading_state` (`role="status"`, `aria-busy`) | stays (orientation) | **disabled** (no filtering a loading table) | `role=status` announce |
| Empty (first-run) | `empty_state variant=never` + CTA | stays | enabled | `role=status` |
| No-data (filters active) | `empty_state variant=no_data` (distinct `funnel` icon) | stays | enabled (so user can clear filters) | `role=status` |
| Error (hard) | `error_state` (danger icon + heading) | stays | **disabled** | error focuses `tabindex=-1` heading |
| Permission / unavailable | **panel body collapses to one message** (`lock` vs `cloud_off` shape) | stays (you still know where you are) | disabled/hidden with body | focus rescue element |
| Stale | `role="status"` warning banner **ABOVE still-rendered data** — never replaces it (D-176-14) | stays | stays enabled | banner announced, data untouched |

Forensic invariant: permission ("exists, you can't see it") vs no-data ("filter excluded it") vs unavailable ("down / redacted / pruned") stay unmistakable via distinct icon shape + heading even when collapsed to one message.

## Motion Contract (GROUP-02 — "motion clarifies state transitions")

GPU-only (transform/opacity), motion tokens only, mount-fired, via `Phoenix.LiveView.JS` (CSP-clean). Reduced-motion is already handled system-wide by the `prefers-reduced-motion` blanket (`style.ex` ~L3868 → ~1ms) — no per-component handling needed (D-12).

| What earns motion | Token | Property |
|-------------------|-------|----------|
| Overlay enter/exit (modal fade+scale, drawer slide-from-edge, toast fade-up, dropdown fade+offset) | `--tl-motion-base` (180ms) `--tl-ease-standard` | transform + opacity |
| Data-region state swap (happy↔loading↔empty↔error) — animates the **container**, not rows | `--tl-motion-fast` (120ms) | opacity cross-fade |
| Stale banner appear | `--tl-motion-fast` | opacity + small slide |
| Tab / segmented switch | `--tl-motion-fast` | active-indicator move + subview crossfade |

**Never animate:** high-frequency timeline stream per-row inserts (snappy paging wins); layout reflow at breakpoints; anything not in the list above is **instant**. Never animate from `scale(0)` (MOTION-01).

## Reconnect / Offline Group Contract (D-08)

Rides Phoenix LiveView's built-in connection body classes — **zero new JS, zero deps, CSP-clean**. Catches a *dropped* socket mid-session (unlike a mount-time `connected?/1` assign).

- Driver classes: `.phx-loading`, `.phx-disconnected`, `.phx-error` / `.phx-client-error` / `.phx-server-error`.
- Reconnect banner: `role="status"` strip, warning-tinted, icon + text (not color alone).
- Disabled actions: mutating controls disabled purely in CSS via descendant `pointer-events` / `opacity` / `aria-disabled` while disconnected.
- New CSS lives in `style.ex` keyed off the `.phx-*` classes; reuses motion + reduced-motion blanket.

## Copywriting Contract

Brand voice: calm senior engineer — plainspoken, active voice, short sentences, **sentence case, no exclamation marks**, no blame, no buzzwords (`brand-book.md` L110–148, L396–419). Per CONTEXT, the *systematic* microcopy/IA sweep is **Phase 179** (COPY-01..03); group copy here is decided alongside each group. The patterns below are the contract the group states must follow.

| Element | Copy pattern (brand-anchored) |
|---------|-------------------------------|
| Primary CTA | Specific verb + domain noun, sentence case (e.g. "Run coverage check", "Export timeline", "Prune now"). Never "Submit"/"OK". |
| Empty state (first-run) | Plain statement of nothing-yet + the one action to start. Pattern: "{No domain-noun yet}. {Single next step}." |
| No-data (filters active) | Distinguish from first-run: name the filter as the cause + how to widen. Brand example: "No audit changes match these filters. Clear the table filter or widen the time range." |
| Error state | What failed + why-if-known + next action, no blame. Brand example: "Could not verify trigger coverage for `ticket_replies`. Threadline could not introspect the deployed trigger SQL. Rerun `mix threadline.gen.triggers --tables ticket_replies`, migrate, then check coverage again." |
| Stale banner | State staleness + as-of time + retry. Pattern: "Showing last-good data from {as_of}. Refresh to retry." |
| Permission denied | "Exists, you can't see it" — never conflate with no-data. Pattern: "You don't have access to this {object}." |
| Unavailable | Explicitly NOT a permissions issue: down / redacted / pruned. Pattern names the cause. |
| Reconnect banner | Calm, transient. Pattern: "Reconnecting…" (status, not error). |
| Destructive confirmation (T3 prune) | Name the object + the consequence; require typing the canonical name (server-enforced `secure_compare`, D-176-05). Pattern: "Prune {policy name}? This permanently deletes {N} change records and cannot be undone." |

Domain language enforced everywhere: AuditTransaction, AuditChange, AuditAction, ActorRef, Correlation; covered/uncovered, drift detected, redaction policy, retention window, evidence, row history / as-of.
