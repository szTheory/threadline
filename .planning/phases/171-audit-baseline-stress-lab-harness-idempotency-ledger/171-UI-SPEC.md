# Phase 171 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - manual Phoenix/LiveView inline CSS token system |
| Preset | not applicable |
| Component library | none - internal Phoenix function components only |
| Icon library | internal `Threadline.OperatorSurface.Components.Icon` SVG paths |
| Font | Geist for UI/prose; IBM Plex Mono for IDs, code, ledger keys, fixture names, and machine-readable state |

Source: `REQUIREMENTS.md` locks zero new runtime dependencies, no Tailwind, no PhoenixStorybook, no public component API, and inline assets only. `style.ex`, `brandbook/tokens.json`, and `brandbook/brand-book.md` are the current visual authorities.

Phase 171 must make `/audit/__stress` feel like a precise internal operator lab, not a marketing page, demo gallery, or generic Storybook clone. Use the real operator shell, dark/light/system theme path, auth path, fonts, tokens, navigation density, and existing `.threadline-ui` scope. The stress surface may expose harness metadata, story IDs, fixture IDs, score states, and screenshot coverage, but it must not introduce a separate visual language.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline metadata separators, dense ledger glyph spacing |
| sm | 8px | Compact element spacing, badge/chip gaps, table-cell internal gaps |
| md | 16px | Default element spacing, panel padding, form/control groups, story card body padding |
| lg | 24px | Stress section padding, story matrix row gaps, page-fixture grouping |
| xl | 32px | Layout gaps between lab nav, filters, preview, and ledger regions |
| 2xl | 48px | Major breaks between registry categories or page fixture families |
| 3xl | 64px | Top-level page breathing room only on wide desktop lab views |

Exceptions: Existing operator tokens `12px`, `20px`, and `40px` remain allowed where already encoded in `style.ex` for row padding, control rhythm, and hit-area-adjacent layout. Interactive controls keep the existing `--tl-control-height: 40px`; icon-only or touch-critical targets must expose at least a 40px hit area now and be ledger-flagged for the Phase 180 comfortable-target audit if below 44px. Do not create new spacing values outside the existing `--tl-space-*` contract in Phase 171.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 32px | 600 | 1.15 |

Use only these two weights for new Phase 171 UI: regular `400` and semibold `600`. Existing source may still contain `--tl-weight-medium: 500`; do not expand its use in the stress-lab UI. Normal text letter spacing is `0`; uppercase metadata labels may use the existing caps tracking only for short machine labels. Use monospace for story IDs, ledger IDs, route fragments, fixture names, table names, request IDs, and JSON snippets; do not use mono for long explanations.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | dark `#0B1020`; light `#F7F9FC` | Stress page background, real shell background, full-page canvas |
| Secondary (30%) | dark `#141B2D` / `#1B253A`; light `#FFFFFF` / `#EEF3FA` | Panels, story containers, ledger tables, registry category bands, preview wells |
| Accent (10%) | dark `#4F8CFF`; light `#1557C0` | Primary CTA, selected story, active tab/filter, links, focus-visible ring, screenshot-ratchet highlight |
| Destructive | dark `#FF8585`; light `#A33434` | Destructive actions only; Phase 171 should have no destructive runtime actions |

Accent reserved for: primary action buttons, text links, selected/current story state, active filters/tabs, focus-visible rings, "score raised" or "new coverage added" indicators, and the currently previewed stress cell. Do not use accent as general decoration, card glow, chart filler, or a replacement for severity colors.

Semantic color rules:

- Success means a guard passed, coverage exists, or score increased: dark `#5AE0A2`, light `#136C47`.
- Warning means incomplete coverage, known baseline debt, stale data, or future-phase reserved slot: dark `#F6C86B`, light `#8A5512`.
- Error means render failure, route/auth gate failure, schema invalidity, or ratchet violation: dark `#FF8585`, light `#A33434`.
- Info means neutral harness explanation or currently inspected metadata: dark `#9AB9FF`, light `#1557C0`.
- Never rely on color alone. Every status must include text and/or an icon/shape, and machine-readable status must appear in the ledger row.
- Stitch Blue `#4781E6` remains logo-arc only. Do not use it as the product UI accent.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Run stress audit |
| Empty state heading | No stress stories registered |
| Empty state body | Add a fixture-backed story to the stress registry so this category can be audited. |
| Error state | Stress story could not render. Check the fixture shape, story assigns, and route gate, then rerun the audit. |
| Destructive confirmation | None in Phase 171. If a reset/debug action is added for local dev, keep it dev/test-only and require explicit object naming: `Reset stress baselines for {story_id}`. |

Additional required microcopy:

- Ledger regression: `Score regression blocked. {story_id} was {previous_score}; this run reported {new_score}. Keep the prior score or document an explicit reset.`
- Missing screenshot baseline: `No screenshot baseline is attached to this stress cell yet. Add it to the bounded allowlist before claiming pixel coverage.`
- Future-phase reserved case: `Reserved for Phase {phase}. This baseline records the current issue; do not fix it in Phase 171.`
- Permission-denied fixture: `Permission denied. This state proves the operator can distinguish restricted data from empty data.`
- Stale/reconnecting fixture: `Data may be stale. Reconnect or refresh before treating this audit state as current.`

Voice: calm, exact, active, and domain-specific. Use Threadline nouns: stress story, fixture, ledger item, ratchet, audit coverage, operator surface, route gate, screenshot baseline, dark/light/system. Avoid exclamation marks and vague words such as powerful, seamless, robust, next-generation, compliance suite, immutable ledger, or generic observability.

## Phase 171 Interaction Contract

The stress lab must support these views and states without changing the public operator-surface API:

| Area | Contract |
|------|----------|
| Route chrome | Use the real authenticated operator shell where practical. Header, skip link, nav grouping, active/current state, and `data-tl-theme` behavior must match `/audit`. |
| Lab navigation | Provide clear categories for foundations, existing components, page fixtures, known footguns, and future reserved cases. Categories must be keyboard-reachable and expose current state with `aria-current` or equivalent semantics. |
| Story matrix | Each story row/cell must show stable story ID, category, fixture key, state, theme coverage, viewport coverage, current score, target score, screenshot status, and owner/phase metadata where available. |
| Preview behavior | Selecting a story must keep the URL shareable and stable. Do not trap focus in previews. Preview wells must not resize unpredictably when long IDs, non-ASCII, empty data, or error fixtures render. |
| Filters | Filters for category, status, score, state, theme, viewport, screenshot coverage, and future-phase reserved cases should be compact and reversible. Provide an obvious clear-filter action when filters produce no results. |
| Ledger feedback | Score increases read as success; blocked score decreases read as error; unchanged debt reads as warning/neutral depending on severity. Always show the previous and current score in text. |
| Theme behavior | Dark, light, and system must be represented in the stress metadata from the start. The lab itself must render correctly under `data-tl-theme="dark"`, `"light"`, and `"system"` without JS or FOUC. |
| Viewport behavior | The lab must be usable at 320, 375, 768, 1024, and 1440 widths. Wide desktop may use split registry/preview layout; narrow viewports must collapse to stacked navigation, filters, ledger, then preview without horizontal page scroll. |
| Motion | Use existing `120ms`, `180ms`, and `240ms` tokens only for state continuity, selection feedback, disclosure, and loading. Respect `prefers-reduced-motion`; screenshot paths should run with reduced motion. |
| Focus | Focus-visible must use the existing ring token and never be clipped by sticky headers, preview wells, or scroll containers. Hover states are allowed only on interactive elements. |
| Loading | Loading states must be visibly distinct from empty/error. Use skeleton/progress patterns already present or ledger-register them as primitive debt for Phase 173. |
| Error and auth states | Route gate, production omission, unauthorized access, fixture schema failure, story render failure, and stale/reconnecting states must be distinct in copy and visual treatment. |

Do not fix the folded todos in this phase. Represent `theme-picker-idiomatic-ui`, `coverage-schema-card-declutter`, and `transaction-page-left-push-desktop` as baseline ledger/stress cases with clear future-phase ownership only.

## Accessibility Contract

- The stress route must be keyboard-operable from first render: skip link, header/nav, filters, story list, preview controls, and ledger table.
- Use semantic headings in order: page title, lab sections, category groups, story detail headings.
- Use real buttons for actions, links for navigation, and tables only for tabular ledger data. Do not add hover/focus styling to non-interactive panels.
- Every status chip must include visible text. Icons are supplemental and must be `aria-hidden` unless they carry unique meaning.
- Ledger tables need captions or `aria-label`s, stable column headers, and no hidden critical data on mobile; switch to stacked rows if columns become unreadable.
- Long IDs and strings must middle-truncate visually but preserve copyable full values via title, accessible label, or explicit copy action.
- Dialogs, drawers, popovers, and menus are not required in Phase 171 unless already present. If introduced, they must follow focus trap/restore and Escape semantics immediately; otherwise ledger-register them for Phase 173.
- Do not rely on screenshot-only quality. Computed/semantic checks for route gating, theme attributes, roles, labels, stable IDs, and reduced-motion assumptions are part of the baseline contract.
