<objective>
Close the REL-04 gap in 244-VERIFICATION.md. The phase pinned Hex 2.6.0 on the premise that Hex version drift caused the 1.1.0 `--check-locked` red run. 244-07's isolated reproduction falsified that premise: both Hex 2.5.1 and 2.6.0 reject the a3301bed `[]` manager lock when deps/ is cold, and both accept it when deps/ already holds plug_crypto 2.2.1. The discriminator is deps/ state. So a contributor with a warm deps/ passes the local gate and CI (cold deps/) goes red, which is the failure the phase goal says must not recur.

This plan (a) adds a static lock-hygiene check that rejects an empty manager list on any `:hex` lock entry regardless of deps/ state, wired into `bin/verify-deps-audit` so it runs in `mix ci.all` and in the CI `verify-deps-audit` job, and (b) rewrites the recorded cause to the observed mechanism, keeping the Hex pin as toolchain determinism.

Purpose: the 1.1.0 failure mode now fails locally first, and the documented cause matches the evidence.
Output: `bin/verify-lock-hygiene`, its wiring in `bin/verify-deps-audit`, tests in `deps_audit_gate_test.exs`, corrected prose in CONTRIBUTING.md, the hex_pin_contract_test.exs moduledoc and the ci.yml pin comment.
</objective>
