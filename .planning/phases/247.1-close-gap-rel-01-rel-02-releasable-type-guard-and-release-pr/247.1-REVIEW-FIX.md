## Fixed Issues

### WR-01: PR template says the PR title is always the squash subject

**Files modified:** `.github/pull_request_template.md`, `test/threadline/changelog_contract_test.exs`
**Commit:** d6f54de8
**Applied fix:** The Release impact lead now reads: "The squash subject's type
decides whether merging cuts a release. The squash subject is the PR title, or
the commit subject when the PR has a single commit, so set both." The D-09 test
pins `"single commit"` in the template.

### WR-02: CONTRIBUTING contradicts itself on what Release Please parses

**Files modified:** `CONTRIBUTING.md`
**Commit:** 25c2098c
**Applied fix:**
- The squash-title paragraph now says Release Please parses the squash body
  (the PR's commit messages). A paragraph that starts with a type counts as a
  commit of its own, so a `fix:` paragraph makes even a `ci:` squash
  releasable. A `BREAKING CHANGE` footer makes it a major release. The PR body
  matters only through `BEGIN_COMMIT_OVERRIDE`.
- In the pinned Security/Fixed paragraph, "Release Please only parses the
  squash subject" became "Release Please reads the squash commit, not
  `CHANGELOG.md`". The pinned substrings "must merge under a releasable squash
  subject" and `` `BEGIN_COMMIT_OVERRIDE` `` are unchanged.
- IN-01 is folded in: the residue sentence now also names "files sitting
  directly in a directory that also ships files (such as `brandbook/`)".

### WR-03: PR template classifies docs as "Ships nothing to adopters"

**Files modified:** `.github/pull_request_template.md`, `CONTRIBUTING.md`
**Commit:** cb707c9a
**Applied fix:**
- The first checkbox and bullet are now "Ships no code to adopters (CI, tests,
  tooling[, planning]) or changes documentation only".
- The second is now "Changes the library code or dependency requirements".
- The CONTRIBUTING bullet adds that documentation ships with the package, so
  a `docs:` change reaches adopters in the next release without cutting one.
- IN-02 is folded in: "Never `fix(ci):`: unless every file it touches is under
  `exclude-paths`, it opens a Release PR with no release prose to date."

### WR-04: The Unreleased lead sentence becomes false when the next releasable change rolls in

**Files modified:** `CHANGELOG.md`
**Commit:** a7bdbdc6 (CHANGELOG-only, `docs(changelog):`)
**Applied fix:** The lead paragraph no longer makes a whole-release
"unchanged since 1.1.0" claim. It now describes the listed changes: "The
documentation that ships with the package is updated, and the maintainer-only
Mix aliases changed. Neither change touches the library code or its dependency
requirements." That stays true when later changes join the same release. The
order is still prose, then `### Breaking changes`, `### Required action` and
`### Changed`, and the prose contains no planning vocabulary.
