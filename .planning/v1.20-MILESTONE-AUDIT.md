## Critical Blockers

1. Async exports are not runnable by default. [task_adapter.ex](/Users/jon/projects/threadline/lib/threadline/export_queue/task_adapter.ex:21), [timeline_live.ex](/Users/jon/projects/threadline/lib/threadline/operator_surface/live/timeline_live.ex:227), and [mix.exs](/Users/jon/projects/threadline/mix.exs:40) do not provide a started `Threadline.Export.TaskSupervisor`, and enqueue failures are not surfaced.
2. Export cleanup is not wired into runtime lifecycle. [cleanup_task.ex](/Users/jon/projects/threadline/lib/threadline/export/cleanup_task.ex:67) expects expiring jobs, but [orchestrator.ex](/Users/jon/projects/threadline/lib/threadline/export/orchestrator.ex:70) does not record `started_at` or `expires_at`, and no supervisor starts the cleanup worker.
3. Saved views are not reliably actor-owned in the normal host path. [session_plug.ex](/Users/jon/projects/threadline/lib/threadline/operator_surface/session_plug.ex:33) writes `threadline_actor_ref`, [auth.ex](/Users/jon/projects/threadline/lib/threadline/operator_surface/auth.ex:69) reads it, but [router.ex](/Users/jon/projects/threadline/lib/threadline/operator_surface/router.ex:73) never installs the plug.
4. S3-backed exports cannot be downloaded through the operator surface. [storage.ex](/Users/jon/projects/threadline/lib/threadline/storage.ex:49) exposes `download_url/2`, but [export_controller.ex](/Users/jon/projects/threadline/lib/threadline/operator_surface/controllers/export_controller.ex:71) only handles `path/1`, while [s3.ex](/Users/jon/projects/threadline/lib/threadline/storage/s3.ex:53) returns `{:error, :not_local}` for `path/1`.
5. Milestone evidence is still incomplete for closeout. Phase 81 closed retention evidence, but Phases 77-78 still need verification/validation closure and the later runtime repair phases 82-84 remain open.
