| Option | Pros | Cons | Complexity | Recommendation |
|--------|------|------|------------|----------------|
| Source-bound, risk-selected acceptance through mounted LiveView jobs | Exercises actual names, keyboard order, focused targets and return; combines narrow/embed geometry with measured 200% tab zoom; checks both themes, touch and reduced motion; keeps route, data and visual claims separate | Current coverage has no forced-colors assertion or intended embedded-container measurement; automation and bounded copy review do not establish adopter comprehension or blanket accessibility | Five existing E2E owners plus route/evidence inventory and zoom helper; no new dependency or CI job -- Risk: stale Retention entry selectors and broad cross-products create false freshness and duplicate cost | Rec for ADM-26–28 and related ADM-31/32; reconcile all existing jobs, then select cross-cutting cases by risk |

**Rationale:** Keep the complete route/job ledger in `test/fixtures/operator_surface/route-inventory.json` and `examples/threadline_phoenix/e2e/support/operator-journey-inventory.json`; prove work through the host-mounted `/audit` LiveViews (`/`, `/timeline`, `/transactions/:id`, `/transactions/:id/history/:table/:record_id`, `/rows/:table/:record_id`, `/actors/:kind/:id`, `/coverage`, `/evidence`, `/exports`, `/policy/redaction`, `/policy/retention`), not fixed Storybook stories. The five closest owners are `operator-accessibility.spec.ts`, `operator-responsive-mobile-first.spec.ts`, `operator-zoom-proof.spec.ts`, `operator-route-states.spec.ts`, and `operator-motion.spec.ts` under `examples/threadline_phoenix/e2e/tests/`; supporting owners are `operator-tab-zoom.ts`, `operator-evidence-manifest.ts`, and `operator-investigation-pair.ts` under `e2e/support/`. Fail first with `mix verify.example_browser operator-route-states.spec.ts --grep "Retention confirmation focus and cancel preserve state; Chromium touch navigation works" --project=desktop-chromium --project=mobile-chromium` and `mix verify.example_browser_light operator-accessibility.spec.ts --grep "inspection routes retain context and reachable controls in Light"`; follow with the existing matrix title “keeps every operator route usable without root horizontal overflow” and zoom/reduced-motion titles above. A bounded ordinary batch follows Home → Timeline query → transaction/diff → row history → full-ID copy → return query; a separate high-risk batch checks Retention preview → “Review and confirm” → cancel/confirmation and the existing Export status/download path. Keep one matched before/after pair per changed visual batch, recording route/state/fixture clock/theme/browser/viewport/DPR/zoom and distinct before/after source plus served CSS/font identities; independently re-review actual current copy and rerun affected behavior/captures after any copy, asset or source change. The 252 pair helper labels browser zoom `unverified`, so use the existing isolated headless Chromium extension helper (`tabs.setZoom/getZoom`, owned loopback tab, temporary profile) for actual zoom; add intended host-container geometry because current zoom observations measure the document root. Add one selected `forcedColors: "active"` state for focused controls and operation/status meaning; Playwright supports this emulation and W3C Reflow guidance explains the container-width boundary ([Playwright extension docs](https://playwright.dev/docs/chrome-extensions), [Playwright media emulation](https://playwright.dev/docs/api/class-page), [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)). Migrate stale direct-entry “Prune now” selectors in accessibility, motion, responsive, zoom, route-state, screenshot-regression, phase-173/178 UAT and prove-mobile specs to `Preview retention` then `Review and confirm`; keep “Prune now” as the final confirmed-dialog action. Coordinate the positive owned-Pruner path with the CI researcher: start only after the host Repo is ready, keep the existing disabled default and isolated fixture, preserve no-replay/no-automatic-prune controls, and do not use shared `5432`. Screenshots/stories do not prove LiveView lifecycle, authorization or database outcomes. No new dependency, job, public API, foreground/native clipboard authority, or maintainer decision is needed.
