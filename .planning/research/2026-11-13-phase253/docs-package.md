# Phase 253 docs, brand assets, package, and migration research

**Scope:** ADM-29–30, ADM-34; documentation/capture evidence alignment for ADM-31–32. Phase 252 is accepted at source `74fe8df2b2520868d464eca93054492fc93a2cad`. This report uses the imported, approved `brand/` sources and current checkout contracts. It does not authorize a package-version change, publication, or new workflow.

## Documentation, brand assets, package, and migration strategy

| Option | Pros | Cons | Complexity | Recommendation |
|---|---|---|---|---|
| Coordinated current-source migration; keep `brandbook/` and `priv/fonts/` as clearly marked, unshipped historical material | Maintains existing source links and provenance, keeps runtime/UI tokens and brand data in their separate current owners, reuses exact package and docs contracts, avoids deleting reference material | Leaves old files in the checkout, so their historical status must be explicit and automated checks must stop treating them as current | Six sequential batches, at most five files each; no dependency or package-file expansion. Risk: a surviving current doc or contract still cites retired vocabulary or old token ownership | Rec if repo-link stability and provenance matter; this matches current AGENTS policy and existing archive tests |
| Move/remove the old brandbook and duplicate font tree while migrating current docs | Reduces visible historical clutter and can make the approved source easier to locate | Breaks existing source paths and the AGENTS handoff path, discards useful design history, increases ownership/test churn without reducing the Hex archive | More paths and link/fixture changes; no runtime/package benefit because these files are already excluded. Risk: accidental history loss or a broken local reference | Rec only if maintainers later choose a separate archival cleanup with a complete link inventory |

**Rationale:** The runtime already reads the approved WOFF2 files in `brand/assets/fonts/web`, ExDoc and the README already use the approved logos, and the root package contract already admits only the needed logo/favicon/font/license files. The mismatch is primarily stale source prose and a test that still treats `brandbook/` tokens as authoritative. A coordinated in-place migration can finish the current docs and test claims while retaining the old directory as history; there is no package or architecture reason to remove it. This also fits Hex’s explicit package allowlist/exclusion and unpack inspection model, plus ExDoc’s extras and image asset configuration ([Hex `mix hex.build`](https://hex.hexdocs.pm/Mix.Tasks.Hex.Build.html), [ExDoc configuration](https://ex-doc.hexdocs.pm/ExDoc.html)).

## Current versus historical disposition

- **Current source of brand facts:** `brand/BRAND.md`, `brand/brand.json`, `brand/tokens.json`, and `brand/assets/README.md`. The approved role assignments include Familjen Grotesk headings, Geist text, IBM Plex Mono identifiers/code, distinct dark/light logo variants, and SIL OFL 1.1 licensing. `lib/threadline/operator_surface/fonts.ex` embeds four Latin-subset WOFF2 files from `brand/assets/fonts/web` at compile time.
- **Current ExDoc contract:** `main: "readme"`, all on-disk guides as extras, and two version-pinned repository links for the example README and internal design system. ExDoc uses the dark lockup and theme-aware favicon, copies both light/dark lockups for its sidebar switch, and leaves ExDoc’s code colors alone. Keep these stable entrypoints and the `Operator Surface` module group; its name is a compatible technical label. The existing asset browser case verifies the generated/served variants.
- **Current UI-token owner:** the scoped functional stylesheet, including `lib/threadline/operator_surface/style/01_tokens.css`; brand palette parity is data-driven from `brand/brand.json`. `brandbook/tokens.css/json` are not runtime token sources. The existing parity test mixes valid current palette checks with old brandbook/spacing and obsolete prose checks: preserve the valid color/contrast assertions, move or retain gap assertions only at the UI-style boundary, and remove the old “dark-primary” / deferred-toggle assumptions.
- **Current Hex archive contents:** `mix.exs` and `@brand_asset_paths` in `release_artifact_contract_test.exs` agree on ten brand files: light/dark lockup SVGs, theme-aware favicon SVG, four WOFF2 subsets and three OFL text files. The full TTF/source bundle, brand book, source artwork, `brandbook/`, `priv/fonts/`, Storybook and example docs are not package files. The per-font license texts are necessary; the package-level MIT metadata does not replace them. The exact archive test already rejects missing, changed or extra brand files.
- **Historical repository material:** `brandbook/`, `prompts/Threadline Brand Book.txt`, and `priv/fonts/` remain available as historical provenance but must not be cited as active authority. In particular, the existing `brandbook/README.md` incorrectly describes itself as authoritative and `priv/fonts/README.md` describes pre-migration families; label these clearly. Do not rewrite `CHANGELOG.md` or historical release/upgrade statements merely to erase old terminology.
- **Stable compatibility names:** retain `Threadline.OperatorSurface`, `threadline_operator_surface/2`, `operator_surface_*` config/telemetry, `/audit`, `guides/operator-surface.md`, and ExDoc/module group headings. Where a visible README section must be renamed from retired wording, retain the old fragment as a small explicit HTML anchor and test it. The current README’s `Evidence plane` heading is asserted/split in `readme_doc_contract_test.exs`, `code_walkthrough_doc_contract_test.exs`, and `persona_routing_doc_contract_test.exs`; migrate those contracts together instead of breaking the incoming fragment. Likewise keep the guide’s existing `# Operator Surface` path/heading while its opening copy makes Admin the product name.
- **248 mount migration:** docs must say a supported mount requires a usable `authorize_fn` or the exact explicit unauthenticated acknowledgement. A Phoenix pipeline alone does not satisfy authorization. Keep host sign-in and tenancy, export/theme HTTP authorization, existing routes/options, and actionable upgrade guidance. No login or logo-replacement API is implied.
- **252 Retention migration note:** describe previews as transient server-held, sequential dry-run estimates with a generation time—not an atomic snapshot, guaranteed deletion count, or persisted run. Only persisted run rows give actual outcomes; failed history shows its last recorded checkpoint and incomplete warning, while nil/active/completed states stay distinct. Confirmation refuses mounted/worker PID, repo, schema, or sleep mismatches and never falls back to a replacement worker; the existing `Pruner.trigger/0` contract remains unchanged. This is documentation of accepted behavior, not a new public configuration/endpoint.
- **Older domain-model language:** `prompts/audit-lib-domain-model-reference.md` is explicitly a working design brief and predates the signed-off brand. Keep its layer and noun distinctions (especially action/change/transaction/request/actor/evidence), but use the newer approved brand for current prose and package metadata.
