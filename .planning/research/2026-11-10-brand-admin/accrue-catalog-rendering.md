## Owner feedback and unresolved issues

- Owner review found that production rendering and a full inventory did not make the default customer sample representative or the catalog quick to use. Accrue corrected its default sample and moved direct Screen/Flow links ahead of collapsed source detail; those are narrow fixes, not proof the full hierarchy works for every task (`accrue:.planning/notes/2026-11-10-customer-list-review-and-sample-data.md:1-40`; `accrue:.planning/phases/256.1-comprehensive-jtbd-led-admin-inventory-and-phoenix-storybook/256.1-11-SUMMARY.md:11-29`).
- A first width matrix measured 226 embedded cases against shrink-wrapped state children, not the containing preview. The helper was corrected to constrain and measure the intended parent. The later retained matrix still has 1,524 layout/keyboard finding rows; compact 320/321 CSS px detail-header cases fail. UAT still records a visual issue and pending maintainer comprehension. Passing evidence reconciliation does not mean the UI is usable (`accrue:.planning/phases/256.1-comprehensive-jtbd-led-admin-inventory-and-phoenix-storybook/256.1-10-SUMMARY.md:13-41`; `accrue:.planning/phases/256.1-comprehensive-jtbd-led-admin-inventory-and-phoenix-storybook/256.1-UI-REVIEW.md:114-128`; `accrue:.planning/phases/256.1-comprehensive-jtbd-led-admin-inventory-and-phoenix-storybook/256.1-UAT.md:27-33,49-61`).
- Owner direction currently keeps PhoenixStorybook's shell visually native and brands Accrue content. Treat that as a useful boundary to check against Threadline's signed-off brand and current host shell, not a blanket rule that Threadline's own Admin shell should be unbranded (`accrue:.planning/notes/2026-11-09-admin-storybook-systematic-review.md:7-18`; `accrue:.planning/phases/256.1-comprehensive-jtbd-led-admin-inventory-and-phoenix-storybook/256.1-LEARNINGS.md:37-43`).
