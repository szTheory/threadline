**Rationale:** The current catalog covers Foundations, Primitives, Forms, States, Overlays, Data Display, Groups, and Patterns, but lacks Export/Retention screen entries. Add `storybook/operations/index.exs`, `operations/exports.story.exs` (`/dev/storybook/operations/exports`), `operations/retention.story.exs` (`/dev/storybook/operations/retention`), and one root index entry. Retention can compose `UI.Page.page_header`, `UI.Data.data_table`, `UI.Display.ref`, and `UI.Overlay.modal`; `RetentionHistoryLive.run_history/1` is private, so label that scene as a static projection unless exact markup reuse justifies extracting it. Use the Acme #4521 ordinary correlation (`scenario.acme-4521-investigation`, `Demo.Seed.Exports`) and the completed-small 14-row fixture (`Demo.Seed.RetentionRuns`) in `examples/threadline_phoenix/lib/threadline_phoenix_web/storybook/fixtures.ex`; keep failed, denied, huge-count, and Offboarded Co cases in stress/boundary lanes. Story docs should cite existing `route.exports` / `route.retention`, `source-exports-6` / `source-retention-6`, and `proof-exports-1/2` / `proof-retention-1/2`; extend `storybook_stories_test.exs` to check those IDs in the existing journey inventory, and add the two pages to `operator-storybook.spec.ts` using `.threadline-ui[data-tl-theme]` and the existing 320/375/768 smoke. `proof-retention-1` currently covers focus/cancel and `proof-retention-2` seeded history, so Phase252 still needs mounted proof for preview, successful confirmation, persisted result, and reconnect safety; the catalog proves static rendering only. Compare production `/audit/exports` and `/audit/policy/retention` under matched ordinary/seeded conditions before and after source edits, with mutation outcomes as separate named states. Keep the locked 1.2.0 package and `/dev/storybook` dev/test boundary unchanged; installed 1.2.0 source and the [official Story docs](https://phoenix-storybook.hexdocs.pm/PhoenixStorybook.Story.html) confirm child examples cannot implement `handle_params/3`. This fits [Phoenix's HEEx component model](https://hexdocs.pm/phoenix_live_view/Phoenix.Component.html) and leaves auth/scope, semver, persistence, and production routes with their owners; no engine, adapter, dependency, public API, React, second registry, broad UI matrix, Phase253 docs/package acceptance, or manual UAT is needed.
