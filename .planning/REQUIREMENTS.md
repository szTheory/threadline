## Constraints and deferred scope

- PhoenixStorybook stays in the Phoenix example dev/test boundary and reuses production components. Real LiveView host routes own URL lifecycle, authorization, downloads and mutations. No React rewrite or speculative Fablebook adapter.
- The prior fail-closed mount policy is an explicit intentional access/default correction with migration proof. Other public host/API/route/config/telemetry contracts remain stable.
- Broader Safe by default work (transaction-ID restore behavior, SQL/CSV/PgBouncer hardening and the separately proposed support-floor change), then specs/performance/dependency-tree candidates, remains a separate queue. Baseline triage must identify any directly blocking dependency; it cannot waive one by calling it deferred.
- No new login/SSO provider, white-label/logo option, public component package, all-schema default, composite-key UI navigation, backend capability, second demo application, paid critic, generic catalog engine, exhaustive screenshot matrix, logo animation/sound or avatar project.
- Routine UAT is automated. Synthetic data and agent review do not establish real adopter needs or observed human comprehension. Existing explicit resource/no-retry/authorization limits remain.
- Executor isolation must be negotiated and checked before dispatch. Preserve configured worktree policy; do not silently fall back to unisolated concurrent execution.
