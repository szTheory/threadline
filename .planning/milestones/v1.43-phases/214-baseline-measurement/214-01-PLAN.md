Per BASE-01, create the three tools and a first doc slice.

collect-ci-runs.sh (bash, `set -euo pipefail`): flags `--workflow <file>`, `--event <pull_request|push|schedule|workflow_dispatch>`, `--target N` (default 20), `--min N` (default 10), `--head-sha <sha>` (alternative selector: all runs for one SHA, any workflow), `--refresh`. It runs `gh run list --repo szTheory/threadline --workflow <file> --event <event> --status success --limit 200 --json databaseId,headSha,createdAt,event,attempt,conclusion,displayTitle`, keeps the most recent `--target` runs, and for each fetches `gh api repos/szTheory/threadline/actions/runs/<id>/jobs?per_page=100` (paginated; this returns the latest attempt). It trims each response with jq to: run id, attempt, head_sha, event, created_at, and per job: id, name, status, conclusion, started_at, completed_at, labels, and steps (name, conclusion, started_at, completed_at). It writes raw/ci/runs/<run id>.json (skipped if present unless `--refresh`) and appends/merges an entry into raw/ci/manifest.json (keyed by workflow and event) recording workflow, event, the selected run IDs under the key `run_ids`, the exact gh list command, and fetch time in UTC. It exits non-zero if fewer than `--min` runs were found. It must contain no write-capable gh subcommand and no HTTP method override.

summarize-ci.py (python3 stdlib, deterministic): reads raw/ci/manifest.json and raw/ci/runs/. Subcommand `jobs --workflow ci.yml --event <e> [--job NAME] [--min 10] --format md|json`: for every job name, n = number of successful job samples; duration = integer seconds; sort samples by (duration, run id) ascending; p50 and p95 by nearest rank (rank = ceil(q*n), 1-indexed); report n, p50, p95, min, max and the run ID of the p50 sample and of the p95 sample. Rows are ordered by the ci.yml job id (map name to id by reading ci.yml `name:` lines, matrix names map to verify-test) then by name. A job with zero samples prints `n=0 — not measured`. Exit 2 when any reported job has n below `--min`. The md row format is: `| <job id> | <job name> | <event> | n=<n> | p50 <s> s (run <id>) | p95 <s> s (run <id>) | min–max <a>–<b> s | ` followed by the backticked command that regenerates that row, then ` |`. Output must be byte-identical across repeated runs on the same raw data.

check-citations.py (python3 stdlib): usage `check-citations.py <file.md>` and `check-citations.py --self-test`. For each line outside fenced code blocks that is not a heading and not blank: first remove exempt tokens — ISO dates (YYYY-MM-DD and MM-DD), the tokens p50/p95, requirement IDs matching [A-Z]+-\d\d, phase/plan numbers of the form 214 or 214-0N, 7-40 char hex SHAs, and version strings like 0.11.0 / 1.43. If any digit remains, the line must contain either `run ` followed by an 8+ digit run ID, or a backticked span that starts with one of: gh, mix, MIX_ENV=, git, python3, bash, jq, psql, elixir. Otherwise report `<file>:<line>: uncited figure: <text>` and exit 1 at the end. Lines that contain [inference] still need a citation of their inputs (same rule). `--self-test` runs the checker on tools/fixtures/cited.md (must exit 0) and tools/fixtures/uncited.md (must exit 1) and exits 0 only if both behave. uncited.md contains at least: a table row `| verify-format | p50 17 s |` and a prose line `Flake Detection costs about 3,000 runner-min per month.` cited.md contains the same figures with `(run 36258719902)` and a backticked `gh run view` command respectively.
