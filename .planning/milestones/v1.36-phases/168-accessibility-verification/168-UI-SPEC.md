# Phase 168 — UI Design Contract

> Visual and interaction contract for the accessibility-verification phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase goal:** The light lane is provably accessible — contrast and interaction affordances hold in BOTH dark and light modes, enforced by the style contract (tests) rather than by eyeball. (Requirements A11Y-01, A11Y-02.)
>
> **Nature of this phase:** This is a *verification / enforcement* phase, not a design phase. The 45-token dual-lane system already exists (Phase 166, `style.ex:19–290`) and was retuned + human-reviewed in Phase 167 (`167-UI-SPEC.md`, `LIGHT-REVIEW.md`). This contract does **not** invent new tokens, colors, type, or layout. It locks the *measurable accessibility contracts* the planner will turn into tests: which token pairs must clear which thresholds, in which mode, parsed how. Every value below is anchored to existing `style.ex` line ranges. The deliverable of this phase is **proof** (test assertions + e2e re-runs), not pixels.

---

## Hard Constraints (carry into every plan/task)

1. **Source-first contract.** The accessibility guarantees are enforced by `test/threadline/operator_surface/style_contract_test.exs` reading `style.ex` directly (the established pattern — see `phase 143 accessibility tokens` test at line 653). New assertions extend that file; they do not introduce a runtime axe dependency into the library.
2. **Dark byte-stability.** Do not touch dark token values or base rules. The existing dark AA test (`phase 143`, line 653) must continue to pass unchanged. The seven theme-aware assertions and the `theme-toggle` ban (test lines 11–29) stay intact.
3. **Additive light lane only.** If a contrast or focus assertion *fails*, the fix is an additive `.threadline-ui[data-tl-theme="light"]` (+ mirrored `@media (prefers-color-scheme: light) [data-tl-theme="system"]`) token-alpha or value tune — never a base-rule rewrite, never a dark-token edit. Any new value not derivable from the existing 45-token lane is FLAGGED, not invented.
4. **No new theme UI.** No toggle, segmented control, or settings surface for theme selection (carried from Phases 166/167).
5. **Do not touch the uncommitted nav-overhaul lane** (~29 files under `lib/`, `examples/`, `test/`, incl. its 3 pre-existing test failures).
6. **WCAG version + level:** WCAG 2.1. Text/icon-text contrast target **AA 4.5:1** (normal text). Non-text (focus ring, UI component boundaries) target **3:1** (SC 1.4.11). These thresholds are the literals the planner encodes; do not relax them.

## Accessibility Verification Contract (A11Y-01) — the AA contrast mirror

The dark surface already has a contrast test (`style_contract_test.exs:653`, `phase 143 accessibility tokens`). Phase 168 adds the **light mirror** plus the **alpha-aware parsing** that makes tint backgrounds and the focus ring measurable. This is the keystone of the phase.

### The parsing gap to close (the technical heart of A11Y-01)

The existing helper `color_tokens/1` (`style_contract_test.exs:1058–1062`) matches **only 6-digit hex**:

```elixir
~r/(--tl-color-[a-z-]+):\s*(#[0-9a-fA-F]{6});/
```

Every `rgba(...)` token — every status-tint **background** (`--tl-color-*-bg`), the accent washes, and the **focus ring** alpha layers — is silently dropped. Status text therefore is never actually measured against the surface it paints on, because the *real* background a status pill's text sits over is `surface composited with the tint-bg rgba`, not the raw page hex. The contract requires `color_tokens/1` (or a sibling parser) to become **alpha-aware**:

1. Parse both `#RRGGBB` and `rgba(r, g, b, a)` token values (and `#RRGGBBAA` if any appear).
2. For contrast math, **composite** any translucent token over a named opaque base before computing luminance: `effective = src.rgb * a + base.rgb * (1 - a)`. Tint backgrounds composite over the **mode's page/surface** (`--tl-color-surface` for panels, `--tl-color-bg` for page). Translucent *text* is not used in this system (all text tokens are opaque hex) — if any appears, composite it over its background and FLAG it.
3. The composite base must be chosen **per mode** (dark text-on-dark-tint over `#141B2D`; light text-on-light-tint over `#FFFFFF`). The planner names the base for each tinted pair; do not assume a single base across modes.

### Token pairs the mirror MUST assert (each in BOTH dark and light)

Mirrors the dark set at `style_contract_test.exs:668–685`, extended to cover the composited tint backgrounds that the current test cannot see.

| Text token | Background token(s) | Threshold | Notes |
|------------|--------------------|-----------|-------|
| `--tl-color-text` | bg, surface, surface-raised, surface-hover | 4.5:1 | primary text on every chrome layer |
| `--tl-color-muted` | bg, surface, surface-raised, surface-hover | 4.5:1 | secondary text — most likely to fail on hover surfaces |
| `--tl-color-muted-soft` | surface, surface-raised | 4.5:1 | disabled text (see disabled exception below) |
| `--tl-color-info-text` | surface, surface-raised, **info-bg composited** | 4.5:1 | status text on its own tint, not just on plain surface |
| `--tl-color-warning-text` | surface, surface-raised, **warning-bg composited** | 4.5:1 | warning text on warning tint — flagged weak on white in `LIGHT-REVIEW.md` item A |
| `--tl-color-success-text` | surface, surface-raised, **success-bg composited** | 4.5:1 | |
| `--tl-color-danger` | surface, surface-raised, **danger-bg composited** | 4.5:1 | danger text on danger tint — flagged weak on white in `LIGHT-REVIEW.md` item A |
| `--tl-color-accent-strong` | surface, surface-raised, surface-hover | 4.5:1 | active-nav text, link-hover |
| `--tl-color-accent` | surface-raised, **accent-soft composited** | 4.5:1 | base link on raised surface + on its own soft tint |

> The composited-tint rows (`*-text` over `*-bg`) are the rows the **current** dark test cannot evaluate. They are the reason alpha-aware parsing is mandatory, not optional. If any composited pair fails, the fix is a shared light-lane token-alpha tune at the lane root (the `LIGHT-REVIEW.md` item-A pattern: strengthen `*-bg`/`*-border` alpha uniformly, never per-component, never a hue change — a hue change is a halt).

### Disabled-text exception (named, bounded)

`--tl-color-muted-soft` is the **disabled** control/text token (`.tl-button:disabled` `style.ex:1383`; `.tl-toolbar__control:disabled` `style.ex:1170`). WCAG 1.4.3 exempts *inactive* (disabled) controls from the 4.5:1 minimum. The contract still asserts `muted-soft` against `surface`/`surface-raised` at the 4.5:1 bar (Threadline holds disabled text legible-by-default), but if a future tune cannot reach 4.5:1 without breaking the "disabled looks disabled" read, the planner may downgrade *only the disabled-token rows* to "exempt — documented" with an explicit code comment. No other row may be exempted.

## Focus-Ring Non-Text Contrast Contract (A11Y-02, part 1)

The focus ring is a **non-text** UI affordance → WCAG 2.1 SC 1.4.11, **3:1** threshold (not 4.5:1).

| Property | Dark | Light | Threshold |
|----------|------|-------|-----------|
| Ring token | `--tl-focus-ring 0 0 0 3px rgba(127,169,255,0.42), 0 0 0 1px var(--tl-color-border-focus)` (`style.ex:157`) | `0 0 0 3px rgba(21,87,192,0.22), 0 0 0 1px #1557C0` (`style.ex:236`) | — |
| 1px solid edge color | `--tl-color-border-focus #7FA9FF` | `#1557C0` | **3:1** vs the surface the control sits on |
| 3px halo (composited) | `rgba(127,169,255,0.42)` over surface | `rgba(21,87,192,0.22)` over surface | reported; the **solid 1px edge** is the load-bearing 3:1 contributor |

**Assertion:** in each mode, the solid 1px `border-focus` edge meets **3:1** against the relevant focusable-control backgrounds (`surface`, `surface-raised` — controls sit on both). The 3px translucent halo is composited and **reported** for visibility, but the contract's pass/fail hinges on the opaque 1px edge so a low-alpha halo cannot mask a failure. This is the same alpha-aware compositing as A11Y-01, applied to the ring.

**Behavioral guard (kept from `phase 143`, `style_contract_test.exs:688`):** the blanket `outline: none` removal is forbidden; `:focus-visible` must restore `box-shadow: var(--tl-focus-ring)` on `button`, `[role="button"]`, `input`, `select`, `a`, `summary` (`style.ex:350–356`). This stays asserted, now understood to hold per mode (the ring token is theme-swapped, the selector list is shared).

## Interaction-State Contract (A11Y-02, part 2) — verified per mode

Every interaction state must be **defined and perceptible in both modes**. The states already exist as token-backed rules in the base block; this phase asserts they resolve to a perceptible delta in each lane and re-runs the e2e affordance checks under the light lane.

| State | Selector(s) | Source anchor | Per-mode contract |
|-------|-------------|---------------|-------------------|
| Hover | `.tl-button:hover`, `.tl-toolbar__control:hover:not(:disabled)`, `.tl-shell-nav__item:hover`, `.tl-segmented__item:hover` | `style.ex:1367,1179,609,982` | Hover changes background to `surface-hover` (and/or border to `border-focus`); the hover surface must differ perceptibly from the rest state in each mode. **Coverage-table hover polarity** was fixed in Phase 167 (light/system flip white-default → tinted-hover, `style.ex:299–315`); assert that flip holds (don't regress to white-on-white). |
| Active / pressed | `.tl-button:active` (`transform: scale(0.96)`), `.tl-segmented__item[aria-pressed="true"]`, `.tl-shell-nav__item--active` / `[aria-current="page"]` | `style.ex:1375,988,616` | Pressed/selected uses `accent-soft` bg + `accent-border` + `accent-inset` inset; the selected state must be unambiguous in both modes (active-nav text `accent-strong` meets the A11Y-01 4.5:1 row). |
| Disabled | `.tl-button:disabled / [disabled] / [aria-disabled="true"]`, `.tl-toolbar__control:disabled` | `style.ex:1379,1170` | Disabled reads as not-actionable (`not-allowed` cursor, `muted-soft` text, flattened surface) in both modes; covered by the disabled exception above for contrast. |
| Selected | `.tl-shell-nav__item--active`, `.tl-segmented__item[aria-pressed="true"]`, `.tl-target-row:target` | `style.ex:616,988` | Selected/current state distinguishable by tint **AND** a non-color cue (border/inset/aria-current), per Brand Book §10 "never color alone". |
| Focus-visible | shared `:focus-visible` rule | `style.ex:350` | Covered by the focus-ring contract above; verified per mode. |

### e2e affordance re-run under the light lane (the second deliverable)

`examples/threadline_phoenix/e2e/tests/operator-accessibility.spec.ts` already verifies, in the default (dark) lane: keyboard focus produces a non-`none` `box-shadow` (`expectFocused`, line 18–24); skip-link → `#tl-main` focus; nav `aria-current="page"`; named form controls; segmented `aria-pressed`; the retention danger `data-confirm`; row-history `role="dialog"` + `aria-modal`; status/verdict chips carry a non-`0px`, non-`none` border (non-color shape); and no horizontal overflow.

**Contract:** these affordance checks are **re-run under the light lane** so the affordances are proven mode-independent. The planner chooses the lowest-friction mechanism (preferred order):
1. Mount the example operator surface (or a test route) with `theme: :light` and run the same spec against it — reuses the existing assertions verbatim.
2. If a dedicated light route is impractical, drive `theme: :system` under an emulated `prefers-color-scheme: light` (Playwright `colorScheme: "light"`) so the `[data-tl-theme="system"]` light branch resolves.

The re-run must assert the *same* affordance set (focus `box-shadow` non-`none`, chip border non-`0px`/non-`none`, `aria-current`, `aria-pressed`, dialog semantics, no horizontal overflow) — proving they hold when the focus-ring and chip tokens swap to their light values. EVID-01's `__light__` screenshot lane (Phase 169) is **out of scope here**; this phase proves *behavior/affordance*, Phase 169 proves *appearance*.

## Verification Outcomes (what "provably accessible" means at closeout)

1. `style_contract_test.exs` carries a **light-lane AA contrast mirror** with **alpha-aware** parsing in/around `color_tokens/1`; every text-bearing token clears 4.5:1 in **both** modes, including status text composited over its own tint background; `mix test` proves it. (A11Y-01)
