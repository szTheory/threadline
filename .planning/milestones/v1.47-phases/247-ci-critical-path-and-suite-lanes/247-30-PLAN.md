<objective>
Implement D-27: a runtime tail queue in `bin/ci-test-partitions`. It absorbs the mean offset, which no static weight refresh removes, as measured in 247-B6-REMEDY-RESEARCH.md: every static rule replays at 1.12–1.28 leave-one-cohort-out, while a tail queue at K=12 replays at about 1.02–1.06.

The design is fixed by the maintainer, and every point is binding:
- the greedy assignment stays unchanged;
- K=12 heaviest ungrouped `async: false` files are lifted;
- colocation groups stay static;
- partitions claim queued files largest-first under an atomic `mkdir` lock;
- each claim is one `mix test <file>` on the same partition DB;
- TSVs merge into the existing schema;
- a claim map goes to the log and the step summary;
- exactly-once covers static plus claimed files;
- one watchdog deadline spans every invocation;
- the change applies to all lanes, with N=4 and no test-semantic change (D-09).

Purpose: CI-03 on the current lane, without disturbing min and latest (both already pass) or the CI-04 hang guarantees.
Output: the runner change with self-test cases that pin each property. Contracts, docs and local lane runs follow in Plan 31.

**Binding design details.** These are the planner's resolution of D-27's open points. Record any deviation in the SUMMARY with a reason; never deviate silently.
- `TAIL_QUEUE_K=12`: a top-level constant next to `ASYNC_FACTOR_PERMILLE`, with a comment citing D-27 and 247-B6-REMEDY-RESEARCH.md (K=4 replays at 1.31).
- Test-only seam `CI_TEST_PARTITIONS_TAIL_K`: a non-negative integer, defaulting to `TAIL_QUEUE_K`, validated like `seconds_env`. Document it in the Seams list. ci.yml never sets it; Plan 31 contract-pins that.
- Eligibility: the file's async flag is 0 under the runner's async regex, and it does not appear on any non-comment line of the colocation file. Rank by the assignment's effective weight, descending, then by path ascending with `LC_ALL=C`. Take the first K. `tail-queue.tsv` rows are `<seq>\t<file>\t<weight>`, with seq 1..q.
- `partition-<i>.files` = the assignment's rows for partition i minus the queued files. `assignment.tsv` and the existing per-partition printed lines stay exactly as today. Add `ci-test-partitions: tail queue: <q> files lifted (K=<k>), weight <w> ms` and `ci-test-partitions: partition <i>: static <n> files, weight <w> ms`. Write all of these BEFORE the serial compile, so `MIX_BIN=false` callers see them.
- Lock: `mkdir "$log_dir/tail-queue.lock"`, then write `owner` = the partition index inside it. The holder reads `tail-queue.next` (starting at 1), takes that row of `tail-queue.tsv` (empty means exhausted), writes next+1, and appends `claim\t<seq>\t<file>\t<start_ms>` to `partition-<i>.claims`. Then `rm -f owner` and `rmdir` the lock.
  - Contenders poll every 0.1 s.
  - A lock whose `owner` partition already has a `partition-<owner>.status` file is stale. Break it by renaming it atomically to `tail-queue.lock.stale.<i>.<n>` and removing that.
  - Waiting longer than `CI_TEST_PARTITIONS_LOCK_WAIT_S` (test-only seam, default 30, validated by `seconds_env`) logs `ci-test-partitions: partition <i>: tail-queue lock timeout`, sets the partition's status to 1 and stops claiming.
  - `stop_over_budget` and `kill_all` release a lock whose owner is the partition they stopped.
  - Bash 3.2 has no `BASHPID`, so ownership is by partition index, never by PID.
- Invocation: a single function or code block per partition subshell runs one `mix test` over a `files` array, for the static set first (k=0) and then once per claim (k=1..). It uses the exact existing invocation line.
  - Before each invocation, record the byte offset of `partition-<i>.log`. Static output is written with `>` as today; claims append with `>>`. After `wait`, copy the new bytes into `invocations/p<i>-<k>.log` with `tail -c +<offset+1>`.
  - Each invocation gets `THREADLINE_PARTITION_TIMINGS_FILE="$log_dir/invocations/p<i>-<k>.tsv"`.
  - Each invocation gets `THREADLINE_TEST_DEADLINE_MS` = `deadline_ms − 1000 × (now − p_start)`. When `deadline_ms` ≤ 0 (disarmed), pass it through unchanged. Otherwise pass at least 1.
  - Rewrite `partition-<i>.beam.pid` before each `wait`.
- `now_ms`: use `date +%s%3N` when the output is all digits (GNU), otherwise `$(date +%s)000` (BSD/macOS).
- After each claim invocation, append `done\t<seq>\t<end_ms>\t<exit>\t<file_wall_ms>\t<overhead_ms>` to `partition-<i>.claims`. `file_wall_ms` is the file's wall_ms row in `invocations/p<i>-<k>.tsv`, or 0 when absent. `overhead_ms` = (end − start) − file_wall_ms.
  - Print `ci-test-partitions: claim partition=<i> seq=<seq> file=<file> start_ms=<n> end_ms=<n> exit=<n> file_wall_ms=<n> overhead_ms=<n>` to stdout, as one printf line.
- Status: `p_status` = the first non-zero invocation exit. Keep claiming after a failure.
  - The subshell's TERM handler becomes `trap 'stop_claims=1' TERM`. It stays a handler, never `trap ''`.
  - Stop claiming when `stop_claims` is set or `partition-<i>.budget` exists. A budget file still exits 124 as today.
  - A partition with an empty static set skips the static invocation (never a bare `mix test`) and still claims.
- `merge_partition_timings <i>` runs in the subshell after its last invocation, when at least one `invocations/p<i>-*.tsv` exists.
  - Every invocation header must share the same `partition=` and `lane=`. On a mismatch, log it and set status 1.
  - Write `partition-timings-<i>.tsv`: header `boot_ms` = the first invocation's (lowest k) boot_ms; `wall_ms` = the sum of all invocations' header wall_ms. Then all rows concatenated, each file once (a duplicate is an error).
  - Write atomically: write a temp file in `$log_dir`, then `mv`.
- `verify_tail_queue` (before compile): the static files plus the queue files, sorted, `cmp` equal to `$enumerated`, with no file in both. On failure, print the difference and exit 1, like `verify_assignment`.
- `verify_claims` (after the wait loop, before `report`): the union of `claim` rows across `partition-*.claims` sorted equals the `tail-queue.tsv` file column sorted, with no duplicates. Otherwise print `ci-test-partitions: tail queue claims do not cover the queue exactly once` plus the diff, and set `fail=1`. Keep the `watch_partitions` → `local fail=0` → per-PID wait sequence textually intact.
