## 1. Claim under test

The REL-01 clause that phase 247.1 could not meet: "the release PR's first CI run is green and no separate CHANGELOG-dating PR is needed."

The rest of REL-01 is proven. The contract half lives in the release-shape and version-truth contract tests (phase 244). The dating mechanism was observed live on #101 in this phase (section 6). This file covers only the next-release clause.

## 2. Trigger condition

All three must hold, in this order:

1. Phase 247.1 has landed on `main` (the `exclude-paths` guard is live; PR B, see `247.1-LANDING.md` § PR B).
2. A `feat:`, `fix:`, `perf:` or `deps:` commit that touches shipped files lands on `main`.
3. That same merge carries its release prose under `## Unreleased — highlights` in CHANGELOG.md.

No throwaway release, `fix:` commit, push, merge, branch delete or workflow dispatch is made to produce this condition. It arises from normal work only.

## 3. Read-only commands

Run from the repository root with an authenticated `gh`. None of these mutate anything. Do not wrap them in retry or wait loops.

```bash
# a. The open release PR and its current head
gh pr list --head release-please--branches--main --state open --json number,headRefOid,createdAt,updatedAt

# b. The release.yml push run for the trigger merge, then its jobs
gh run list --workflow release.yml --branch main --commit <trigger-merge-sha> --json databaseId,conclusion
gh run view <release-run-id> --json jobs --jq '.jobs[] | {name, conclusion}'

# c. pull_request ci.yml runs on the release branch (oldest last); find the run on the PR's final head
gh run list --workflow ci.yml --branch release-please--branches--main --event pull_request --limit 10 --json databaseId,headSha,conclusion,createdAt

# d. Merged PRs on main between the trigger merge and the release PR's final head; none may be a dating PR
gh pr list --base main --state merged --limit 30 --json number,title,mergedAt --jq '.[] | select(.title | test("^docs\\(changelog\\)"))'
```

## 4. Pass conditions

REL-01's next-release clause is observed when, for the trigger merge:

- command b shows `Sync install pins on Release PR` with conclusion `success` (it ran and dated the CHANGELOG);
- the first `pull_request` ci.yml run on the release PR's final head (command c) has conclusion `success`;
- command d lists no `docs(changelog)` PR merged between the trigger merge and that head;
- the trigger merge itself adds prose to `## Unreleased — highlights`: `git show <trigger-merge-sha> -- CHANGELOG.md` has at least one added line inside that block. Without this check the observation could pass on carry-over prose alone. Main's Unreleased block already holds #102's documentation-only prose, and that prose would date any release PR even if its landing PR forgot its own (integration re-audit 2026-10-29, W-3);
- command a shows a release PR opened fresh on the kept `release-please--branches--main` branch. This also checks assumption A3: closing #101 unmerged and removing its `autorelease: pending` label lets release-please open a new PR on the same branch.

If A3 fails (release-please does not open a PR, or it errors on the old branch), record that here and route it as a follow-up. It is recoverable at that point and is not patched inside the observation.

## 5. Concurrency note

ci.yml cancels in-progress runs per concurrency group. The release-please push and the pin-sync push can each produce a head, so the first CI run on an intermediate head may show `cancelled`. Only the run on the release PR's final head counts. A cancelled run on an earlier head is not a failure (244-REL02-EVIDENCE.md §5).

## 6. What this phase observed

The mechanism works live, on release PR #101:

- PR A #102 (`docs(changelog):`, CHANGELOG.md only) merged as bcc191d66c9444e9e2cfa970779c5247f6936930.
- Its release run 40816123990 (`success`) refreshed #101 from dbd2f72f3b5feac8232aa1b95c35215bf4b105e0 to H1 2c5fd6a7329a90fb02dcb008cd014b27ad8835d2. The sync job ran and wrote `## [1.1.1] - 2026-10-29`.
- CI run 40816299568 (`pull_request`) on H1 is `success`, and all 17 checks on H1 are green, including `CHANGELOG matches version`.

Why the clause could not be met here:

- PR A was itself a prose PR. It is the very kind of separate dating PR the clause rules out, so #101 cannot serve as the evidence.
- No releasable package change is pending. The shipped package differs from 1.1.0 only in documentation, so #101 was closed unmerged (D-16; see `247.1-LANDING.md` § #101 closure). A throwaway release to produce the trigger is ruled out.
