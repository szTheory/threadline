<objective>
Fix the proven mechanism behind the `CriticTrustTest` intermittent, and stop the unbounded
scratch-tree leak that causes it.

Purpose: `critic_trust_test.exs:1142` names its scratch directory with
`System.unique_integer([:positive])`. That counter is unique per BEAM instance and restarts on
every `mix test`. `_build/critic-trust-path-tests/` is never cleaned — 542 directories, oldest
dated Sep 13. When a run draws an integer a previous run already used, the scratch directory
already contains `output-alias` and `File.ln_s!` raises `File.LinkError`.

This was proven, not inferred: `root-overlap-132290` (mtime Sep 22 09:50) and
`interrupted-measure-132290` (mtime Sep 22 06:18) share integer 132290 across two runs and two
different labels. Collision probability rises monotonically with every run until `_build` is
cleaned, which is why the suite can read green four times and then fail.

Output: a test whose fixture names are unique across runs, which cleans up after itself, and a
`_build` tree that stops growing.
</objective>
