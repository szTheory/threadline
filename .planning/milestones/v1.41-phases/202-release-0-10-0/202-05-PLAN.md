<objective>
Publish 0.10.0, once, from a tree that is green by construction, with every irreversible step
behind an explicit human confirmation.

Purpose: everything upstream of this plan removed a reason the release pull request is red and
a reason the pipeline proves less than it claims. This plan does the part that cannot be undone.
hex.pm has no unpublish beyond a short window and published documentation is permanent, so the
ordering here is the safety mechanism: prove locally, dispatch CI deliberately, confirm, merge,
confirm again, publish, then verify what actually landed.

Output: 0.10.0 live on hex.pm with clean grouped documentation, a green post-publish smoke, a
written attestation, and a record of what was confirmed and when.
</objective>

  <reversibility rating="one-way">Publishing to hex.pm can be reverted only within a short window; after that the tarball can be retired but not removed, and the published documentation is permanent regardless.</reversibility>
  <read_first>
    - CONTRIBUTING.md, the environment-approval and recovery subsections added by Plan 04 — the maintainer must have read the recovery procedure before this decision, not during a failure

  <decision>
    Merge the regenerated release pull request and allow the publish to proceed through the
    environment approval.

    **What this buys:** 0.10.0 reaches adopters, carrying the storage-schema default that makes
    it non-breaking for the existing population, a readable changelog, and a corrected upgrade
    path.

    **What this costs:** irreversibility. Within a short window the release can be reverted;
    beyond it, retirement warns but does not remove the tarball, does not break existing
    lockfiles, and does not move anyone already pinned, so the real fix becomes a same-day patch.
    Removal beyond retirement is unavailable.

    **The environment approval that follows is a confirmation, not peer review.** With a single
    maintainer and self-review permitted it answers one question: is this the release intended,
    from this commit. Every gate above it already answered whether the artifact is well-formed.

    **Ask the maintainer to confirm explicitly** that they have read the recovery procedure, that
    the release commit is the intended one, and that they approve the publish. Do not infer this
    from the previous confirmation.
  </decision>

    - Hold entirely: do not merge.
