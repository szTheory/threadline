<objective>
Make a version bump require no hand edits, and stop shipping maintainer tooling to adopters.

Purpose: PR #26 is born red because six install pins read the previous minor and the bump
derives a new one. The obvious fix — release-please markers on the pin lines — is measured
wrong: the generic updater writes the full version, so a patch release would emit a pin one
patch ahead of what the contract derives, and component markers replace the leading digit
inside the compound requirement string producing a nonsense major. D-04 resolves it with a
derivation task; D-06 promotes "release-please must never own a pin line" from a code
comment to an enforced invariant. D-20 stops the critic tooling and stress harness from
appearing in every adopter's `mix help`.

Output: `mix release.pins`, a strengthened version-truth contract, tarball exclusions proven
against the real archive, and a written classification of the version literals that remain
outside the pin regex.
</objective>
