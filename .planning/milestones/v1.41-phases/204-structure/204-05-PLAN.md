**Source-text pins vs rendered output.** Two kinds of check fail when a component moves, and they are handled differently:
- *Source-text pins* match call-site spelling, not HTML: the storybook_stories_test contract markers (`{"button", ["<UI.button"]}` …, consumed by `rendered_or_source_backed?/3` via `String.contains?`) and component_contract_test's page-shell pin (`src =~ "UI.shell"`, moved in 204-06). Each family commit rewrites exactly the markers of the components it moves to the family-qualified spelling (`"<UI.button"` → `"<UI.Actions.button"`), leaving list membership, labels, and the assertion functions unchanged. A marker is a rename pin, not an output assertion.
- *Rendered-output checks* are everything in ZOC steps 1-4 that renders: the byte lock, rendered_output_contract, render assertions in component_contract_test / ui_test / pager_test / page_header_test, story rendering in `mix verify.example`, and the browser lane.

**HALT clause:** a red byte lock, a changed rendered-output contract, a failing render assertion, a story that no longer renders, a 9th browser failure, or a newly passing member of the known 8 means the move changed output: revert the commit and retry. A failing storybook marker for a component moved in THIS commit is fixed by the rename rewrite above; a failing marker for any other component, or any edit to `rendered_or_source_backed?/3` or the contract lists' membership, is a HALT. Never regenerate screenshots, Tier A scorecards, or fixtures; never edit a contract assertion to match new HTML; never add a size exception; never add `defdelegate` facades; never bypass hooks. Never `git add .planning/`.

Conventions (D-00): `refactor(204-05): move <family> components out of the UI module`, one family per commit. Each family module copies the ui.ex header: `if Code.ensure_loaded?(Phoenix.Component) do`, `@moduledoc false`, `use Phoenix.Component`, and only the aliases it uses (`Phoenix.LiveView.JS`, `Components.Icon`, `Presentation`, `Script`), or `--warnings-as-errors` fails on an unused alias. Only the module defining `link/1` needs `import Phoenix.Component, except: [link: 1]`. Keep `@doc false` on each component as in ui.ex. Call sites keep `alias Threadline.OperatorSurface.UI` and call `UI.<Family>.<fn>` (HEEx: `<UI.Actions.button …>`); if Credo AliasUsage flags a nested call in plain Elixir code, add an explicit family alias in that module instead. Find call sites with `grep -rn 'UI\.<fn>\b' lib examples/threadline_phoenix test` and pins with `grep -n '"<UI\.<fn>"' examples/threadline_phoenix/test/threadline_phoenix_web/storybook_stories_test.exs` before each commit.
