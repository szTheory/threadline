# Plan 136-01: Dark Token and Interaction Contrast Foundation

## Objective

Make the existing dark-only operator surface more readable, polished, and brand-faithful by hardening shared design tokens and interaction states in `Threadline.OperatorSurface.Style`. This is a Phase 136 foundation slice, not the entire design-system phase.

## Scope

- Keep the surface dark-only: no light mode, no system mode, no theme toggle.
- Lift dark-mode contrast for muted text, status text, semantic borders, and focus affordances.
- Add shared hover/selected/focus tokens for surfaces and controls.
- Improve buttons, nav items, segmented controls, inputs, chips, alerts, and empty/error states through shared CSS.
- Add a contract test that locks the dark-only decision and the key token seams.

## Tasks

1. Update dark theme tokens:
   - add `--tl-color-surface-hover`, `--tl-color-surface-selected`, `--tl-color-border-focus`, `--tl-color-muted-soft`, and `--tl-color-accent-border`
   - lift muted/status semantic colors to AA-friendly dark values
   - add explicit danger border token
   - keep letter spacing at `0` for tight display text

2. Harden shared interactions:
   - nav active/hover states get explicit borders and selected background
   - segmented active state uses Thread Blue active treatment
   - form controls get readable hover/focus/disabled states
   - disabled buttons use explicit muted surface/border/text rather than opacity-only
   - chips and alerts get visible semantic borders

3. Add contract coverage:
   - assert `color-scheme: dark`
   - assert no `prefers-color-scheme` or light color-scheme
   - assert dark hover/focus/status token seams exist
