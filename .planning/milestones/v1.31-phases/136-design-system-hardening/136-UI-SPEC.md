## Visual Hierarchy

Primary focal point: the operator's current evidence signal, not the chrome. Status, verdict, operation, and as-of primitives must lead with a readable label plus border/shape treatment, then supporting metadata follows in muted text.

Hierarchy rules:

| Layer | Contract |
|-------|----------|
| First scan | Screen title, one owned status/verdict badge, and primary action slot |
| Second scan | Table/card row labels, operation chips, timestamp/as-of context, and trust-rail links |
| Background | Nav, repeated counts, helper text, and raw JSON/KV detail |
| Data detail | Mono values stay compact and secondary unless the screen is explicitly a diff/KV detail surface |

Do not double-encode a single state with both a row stripe and an equally strong badge unless the row itself is the selected/focal item. Pick one owner per surface for repeated counts such as "need capture".

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, segmented-control internal gaps |
| sm | 8px | Compact element spacing, chip/button gaps |
| md | 16px | Default element spacing, row groups, standard panel padding |
| lg | 24px | Section padding, toolbar-to-content separation |
| xl | 32px | Layout gaps, major card groups |
| 2xl | 48px | Major section breaks and compact hero spacing |
| 3xl | 64px | Page-level spacing only |

Exceptions: none. Existing intermediate spacing tokens must be consolidated into the declared scale before the token freeze.

Control-size contract:

| Token | Value | Usage |
|-------|-------|-------|
| control | 40px | Inputs, primary/secondary buttons, nav hit targets |
| compact-control | 32px | Dense table actions, compact filters |
| chip | 24px | Status, verdict, operation, and filter chips |
| badge | 22px | Deprecated; consolidate into `chip` unless a legacy table requires it during migration |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.4 |
| Heading | 18px | 600 | 1.2 |
| Display | 28px | 400 | 1.15 |

Typography rules:

| Element | Contract |
|---------|----------|
| Uppercase labels | Use only for compact system labels and chip metadata; keep letter spacing from the existing caps token |
| Display text | Letter spacing remains `0`; do not tighten below zero |
| IDs, UUIDs, table names, values | Use mono font, middle truncate long identifiers, expose full value via title and copy affordance where interactive |
| Raw JSON/payload blocks | Secondary visual weight; never outrank verdict/status labels |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B1020` | Page background and dark-only brand base |
| Secondary (30%) | `#141B2D` / `#1B253A` | Cards, panels, drawers, toolbars, rows, and raised surfaces |
| Accent (10%) | `#4F8CFF` | Links, primary action slot, active nav/segmented state, focus affordance |
| Destructive | `#FF8585` | Destructive actions, failed/error states, and danger borders only |

Accent reserved for: primary action slot, text links, active nav item, active segmented item, focus ring, and explicit Thread Blue action states.

Signal Cyan (`#4EDFD1`) is not a second accent for generic interaction. It is reserved for correlation/as-of/thread-path emphasis and positive system-flow traces. Inferred or expected statuses may use a cyan or neutral outline treatment only when the treatment cannot be mistaken for a link or action.

Semantic status map:

| Concept | Canonical Treatment |
|---------|---------------------|
| Success / completed / covered / proven | Success text, success border, soft success background |
| Warning / expected gap / queued | Warning or neutral-muted outline, never link blue |
| Danger / failed / uncovered / unsupported / invalid | Danger text, danger border, soft danger background |
| Info / running / processing | Info text and border only for process state; do not use for proof verdicts |
| Neutral / pending / not started | Muted text, neutral border, explicit pending label |

Status, verdict, operation, and danger tokens must include visible borders and readable text contrast. Disabled controls must use explicit muted surface, border, and text tokens rather than opacity alone.

## Primitive Contract

| Primitive | Contract |
|-----------|----------|
| Status badge | Create one canonical `.tl-status-badge` family keyed from a status enum; deprecate ad-hoc `.tl-chip--*`, `.tl-badge`, and per-screen status pills as status owners |
| Verdict badge | Use a non-interactive color scale for `proven`, `inferred`, `unsupported`, `covered`, `uncovered`, and `expected-gap`; never collide with Thread Blue links/actions |
| Operation chip | INSERT, UPDATE, and DELETE use one shared op-chip modifier everywhere, including Timeline, Transaction, Row history drawer, and Actor rows |
| KV / diff value | Factor one shared mono value/KV/diff primitive for snapshots, before/after diffs, actor rows, and row-history details |
| Chip roles | Name roles separately: toggle, assertion, verdict filter, nav link, and metadata chip |
| Card accent | Signal-line top accent marks the current front-door or thread-path focal card only; other cards use standard surface/border hierarchy |
| Button | One primary action slot per card/surface; secondary and ghost buttons remain visually distinct from disabled controls |
| Empty state | Diagnostic copy plus next action; include CLI/API verification hints where the screen owns operational setup |
| Table | Dense, readable rows with one status owner and consistent responsive stacked-card behavior |
| Drawer | Dark-only raised surface with as-of context, focus containment, and Signal Cyan reserved for time/thread emphasis |
| Toast/alert | Status border plus message text; errors include a next step |
| Copy affordance | Clear secondary affordance, never disabled-grey styling for clickable copy |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Freeze design tokens |
| Empty state heading | No design-system drift found |
| Empty state body | All audited primitives match the frozen `.tl-*` contract. Continue with the next per-screen polish phase. |
| Error state | Design-system contract could not be verified. Re-run the style contract test and inspect the listed `.tl-*` primitive before planning dependent polish work. |
| Destructive confirmation | Run prune now: Confirm retention prune |

Copy rules:

| Situation | Contract |
|-----------|----------|
| Status labels | Use explicit nouns: `Captured`, `Needs capture`, `Expected gap`, `Completed`, `Failed`, `Pending`, `Running` |
| Empty states | Explain whether the cause is filters, time window, missing setup, unsupported feature, or genuinely no history |
| Error states | State the problem and the recovery path in the same message |
| Destructive controls | Use secondary/outline danger styling, place context before the control, and require confirmation copy before execution |
