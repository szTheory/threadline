## Visual Hierarchy

Primary focal point: the operator's proof/readiness signal for each Prove surface, not raw payload or operational chrome.

| Surface | Focal Point | Secondary Scan | Background |
|---------|-------------|----------------|------------|
| Evidence | Proof verdict and subject label | Subject ref, recorded-at time, proof-history action | Raw JSON payload and support links |
| Exports | Download-ready job card and status owner | Source Timeline search, actor ref, expiration | Query parameter chips and unavailable hints |
| Policy Redaction | Drift / introspection / match section status | Table name, mismatch cells, remediation links | Expanded configured-vs-deployed detail |
| Retention | Latest completed retention outcome and destructive-action context | Failure count, deleted rows, run table | Historical run metadata |

Hierarchy rules:

| Rule | Contract |
|------|----------|
| One status owner | Each card/row gets exactly one status/verdict badge as the semantic owner. Avoid row stripe plus equally strong chip unless the stripe only anchors selected/focal state. |
| Ready signal | Exports reserve the solid primary action for one state only: a completed, unexpired, downloadable job. Expired, failed, pending, and running jobs must not use the same weight. |
| Payload weight | Evidence raw JSON and subject refs use mono text at secondary weight, with middle truncation and full value available by title/copy affordance when interactive. |
| Destructive context | Retention status, latest completion, and warning copy must visually precede the destructive prune control on desktop and mobile. |
| Redaction model | Redaction is the baseline pattern for this cluster: grouped sections, explicit drift language, details disclosure, and real remediation links. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps if icons already exist, inline padding, table-cell micro gaps |
| sm | 8px | Compact element spacing, chip/button gaps, alert internal rhythm |
| md | 16px | Default element spacing, record-card groups, panel padding |
| lg | 24px | Section padding, toolbar-to-content separation |
| xl | 32px | Layout gaps, summary-to-list separation |
| 2xl | 48px | Major section breaks and compact hero spacing |
| 3xl | 64px | Page-level spacing only |

Exceptions: none. Existing intermediate tokens such as 12px, 20px, and 40px may remain as legacy token values in `style.ex`, but Phase 137 layout decisions must map to the declared 4/8/16/24/32/48/64 contract unless preserving an existing control-size token.

Control-size contract:

| Token | Value | Usage |
|-------|-------|-------|
| control | 40px | Inputs, primary/secondary buttons, nav hit targets |
| compact-control | 32px | Dense table actions, compact filters, source-search actions |
| chip | 24px | Status, verdict, operation, filter, and assertion chips |
| row-status | max-content | Mobile stacked badges; never stretch status chips to full width |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.4 |
| Heading | 18px | 600 | 1.2 |
| Display | 28px | 400 | 1.15 |

Typography rules:

| Element | Contract |
|---------|----------|
| Page titles | Use question-form titles where the audit requested them: Exports `What's ready to hand off?`; Retention `What was purged, and did it succeed?`. Keep Evidence's proof question and Redaction's assurance framing. |
| CTA labels | Use verb+noun copy. Single-word `Download` is allowed only as the export card's readiness signal when paired with the export summary title; otherwise use `Download export`, `Reopen source search`, `Review retention evidence`, `Run retention prune`. |
| IDs and refs | Use mono font, middle truncate actor refs / UUIDs / subject refs, expose full value via `title` and copy affordance where interactive. |
| Empty and error text | Use body size and regular weight. Empty/error states must not compete with current proof/status badges. |
| Raw payload | Evidence JSON and query-param values remain mono and muted; never outrank verdict/status labels. |

Only the four sizes above may be introduced during this phase. Existing `--tl-font-size-xs`, `--tl-font-size-ui`, and `--tl-font-size-title` may remain in the legacy stylesheet but must not be used to create new hierarchy.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B1020` | Page background and dark-only brand base |
| Secondary (30%) | `#141B2D` / `#1B253A` | Cards, panels, tables, toolbars, rows, and raised surfaces |
| Accent (10%) | `#4F8CFF` | Text links, the single ready export/download action, active nav/segmented state, focus affordance |
| Destructive | `#FF8585` | Retention prune, failed/error states, failed export cards, and danger borders only |

Accent reserved for: text links, focus ring, active nav item, active segmented item, the single primary export-ready action, and non-destructive primary action slots. Never use Thread Blue for `inferred`, `expected gap`, `queued`, or generic proof/status state.

Signal Cyan (`#4EDFD1`) remains reserved for correlation/as-of/thread-path emphasis and positive system-flow traces. Do not use it as a generic second accent or for every proof chip.

Semantic status map:

| Concept | Canonical Treatment |
|---------|---------------------|
| Downloadable / completed / proven / config matches | Success text, success border, soft success background |
| Queued / running / expected gap / introspection warning | Warning or neutral-muted outline with explicit label; never link blue |
| Failed / unsupported / drift detected / destructive | Danger text, danger border, soft danger background |
| Expired / unavailable / no action | Muted neutral treatment, not danger unless the job failed |
| Pending / not started / no expiration | Explicit muted label such as `Pending`, `Not started`, or `No expiration`; avoid bare `-` placeholders |

## Primitive Contract

| Primitive | Contract |
|-----------|----------|
| Status badge | Use the canonical status/verdict badge family from Phase 136; status labels must be text plus border/shape, not color alone. |
| Verdict badge | Evidence verdicts `Proven`, `Inferred`, `Unsupported`, `Expected gap`, and evidence-of-failure must use non-interactive semantic colors; `Unsupported` must not silently stand in for a failed export job. |
| Export job card | One primary slot per job. Completed+unexpired gets `Download export`; pending/running gets a neutral `Preparing download`; completed+expired gets muted `Export expired`; failed gets danger alert plus `Reopen source search`. |
| Source search action | `Reopen source search` stays secondary, always present when query params exist, and never competes with the ready download action. |
| Actor/subject refs | Use shared mono value treatment with middle truncation, full `title`, and copy affordance if clickable. At 375px, actor refs must not wrap into the card title as the visual lead. |
| Alert | Error/failure alert uses `tl-alert` spacing inside card padding; no flush-to-edge failure banners. Message includes the recovery path. |
| Empty state | Diagnostic heading plus next action. No `No data found`, `No results`, or `Nothing here`. Include CLI/API hint when the surface owns operational setup. |
| Table | Dense readable rows with one status owner and responsive stacked-card behavior; mobile status chips stay max-content. |
| Destructive button | Retention prune uses secondary/outline danger styling, not solid primary red. Require confirmation copy and visible context before the control. |
| Disclosure | Redaction detail rows keep the `details` pattern; summary row must state the status and table before exposing configured/deployed detail. |
| Count owner | Retention failure count appears once as a metric and links/scrolls to the failed run where feasible. Do not echo the same count in multiple first-scan elements. |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Run retention prune |
| Empty state heading | No Prove records need review yet |
| Empty state body | This surface has no matching evidence, export jobs, redaction drift, or retention runs for the current setup. Confirm the operator seed path, then use the linked Timeline, Evidence, or CLI command shown on this screen to generate proof. |
| Error state | Prove status could not be loaded. Keep the current view open, re-run the linked CLI verification command, and inspect the highlighted status or export job before taking action. |
| Destructive confirmation | Run retention prune: Confirm retention prune. This permanently deletes older audit records; review the latest completed run and failure count first. |

Surface-specific copy:

| Surface | Title | Empty Heading | Empty Body | Error / Recovery |
|---------|-------|---------------|------------|------------------|
| Evidence | What can Threadline prove right now? | No evidence records yet | Threadline has not recorded proof for this selection. Use `mix threadline.evidence.show` or narrow by subject/history to confirm the current proof state. | Invalid evidence filters must name the bad subject or JSON shape and show the exact recovery path. |
| Exports | What's ready to hand off? | No export jobs queued | Queue an export from Timeline, then return here to download the completed packet or reopen the source search. | Export failed. Reopen the source search, adjust filters if needed, and queue a new export. |
| Policy Redaction | Redaction assurance | No redaction drift detected | Configured redaction matches deployed trigger policy for every introspected table. Continue to Evidence for the latest proof record. | Policy redaction drift could not be loaded. Run `mix threadline.policy.show` and review coverage before trusting sensitive Timeline captures. |
| Retention | What was purged, and did it succeed? | No retention runs yet | Configure retention, run a dry-run first, then trigger a prune to record evidence here. | Retention runtime is not started. Start the retention supervisor or use `mix threadline.retention.purge --dry-run` before retrying. |

Destructive actions in scope:

| Action | Confirmation Approach |
|--------|-----------------------|
| Run retention prune | Secondary/outline danger button, visible latest-run context first, `data-confirm` text includes permanent delete warning and asks the operator to confirm retention prune. |

## Audit Finding Closure Contract

| Finding | Required UI Decision |
|---------|----------------------|
| F-503 | Evidence payloads are muted mono detail; verdict and subject lead each card. |
| F-506 | Failed export evidence is labeled as evidence-of-failure or failed export context, not generic `Unsupported` proof posture. |
| F-601(style) | `Run prune now` becomes outline/secondary danger with confirmation and latest-completed-run context. |
| F-602(style) | Exports group/sort or visually prioritize downloadable jobs; expired and failed jobs are muted/danger and cannot resemble ready downloads. |
| F-603 | Actor refs and UUID-like values are middle-truncated with full title/copy affordance and secondary weight. |
| F-604 | Each export card has one primary action slot. Missing actions render as unavailable state, not absent controls. |
| F-605 | Failed export alert is inset inside card padding using the alert primitive. |
| F-606 | Retention failure count points to the offending failed run where feasible. |
| F-607 | Exports and Retention use question-form titles; Redaction keeps its strong assurance lede. |
| F-608 | `Not started`, `Pending`, `No expiration`, and unavailable placeholders use explicit muted labels, not bare dashes. |
