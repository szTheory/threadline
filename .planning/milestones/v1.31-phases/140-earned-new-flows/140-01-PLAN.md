<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL params -> schema map | Untrusted `table`, `record_id`, and `as_of` values enter a LiveView route and select a mapped Ecto schema. |
| scoped operator -> row-history query | Authorized operator scope must constrain history and snapshot queries. |
| component paths -> LiveView patches | User-controlled route params are embedded in patch paths. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-140-01 | Elevation of privilege | `RowHistoryLive` / `RowHistoryComponent` | mitigate | Mount under existing `threadline_operator_surface/2` live session and pass `scope` / `scope_query_fn` through to the existing `surface: :row_history` query path. |
| T-140-02 | Denial of service | schema table lookup | mitigate | Remove untrusted `String.to_atom/1`; validate route `table` against configured schema-map keys. |
| T-140-03 | Tampering | route and patch params | mitigate | Encode path/query values through LiveView path construction and parse `as_of` with `DateTime.from_iso8601`, falling back safely on invalid input. |
| T-140-04 | Information disclosure | unmapped or out-of-scope row history | mitigate | Render mapped-schema error without querying and add scoped tests proving hidden rows do not render. |
| T-140-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs are planned; any attempted package install must stop for slopcheck/package legitimacy review. |
</threat_model>
