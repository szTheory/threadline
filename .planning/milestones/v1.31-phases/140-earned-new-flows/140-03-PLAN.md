<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Timeline query params -> Exports LiveView | User-controlled allowed filters are carried across surfaces. |
| Exports LiveView -> ExportJob | Carried filters become persisted background export parameters. |
| Browser -> HTTP export endpoints | Direct downloads remain controller requests with separate auth and validation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-140-10 | Tampering | carried Timeline params | mitigate | Parse through `FilterParams`, drop unknown keys, canonicalize output, and validate before rendering queue behavior. |
| T-140-11 | Elevation of privilege | Exports queue action | mitigate | Keep `ExportStatusLive` behind existing export authorization and create actor-owned `ExportJob` rows only for the current actor. |
| T-140-12 | Information disclosure | scoped export context | mitigate | Queue only filter params; row access is enforced later by existing export `surface: :export` scope. |
| T-140-13 | Repudiation | export provenance | mitigate | Persist `query_params` exactly from canonical carried context and render it in Exports so source search is reopenable. |
| T-140-14 | Tampering | HTTP direct downloads | mitigate | Leave controller routes under `ExportAuthPlug` and keep invalid-filter tests green. |
| T-140-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs are planned; any attempted install must stop for slopcheck/package legitimacy review. |
</threat_model>
