<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Evidence URL params -> Exports proof context | User-controlled proof params are carried between LiveViews. |
| Evidence proof context -> export surface | Proof params are displayed in Exports but must not become Timeline file-export filters. |
| feature/auth flags -> cross-surface controls | Evidence and Exports access gates determine whether the handoff is available. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-140-15 | Tampering | Evidence proof params | mitigate | Allowlist `source`, `subject`, `subject_ref_json`, and `mode`; reject malformed JSON and unsupported modes/subjects visibly. |
| T-140-16 | Information disclosure | proof context display | mitigate | Show only context already visible to the authorized Evidence viewer and provide a reopen link back through Evidence auth. |
| T-140-17 | Elevation of privilege | export file filters | mitigate | Keep Evidence params separate from `FilterParams` and direct download URLs; do not queue Timeline export jobs from proof params unless they map to existing allowed filters. |
| T-140-18 | Spoofing | Evidence handoff copy | mitigate | Label the banner as Evidence proof context, not a generated Timeline export, so the UI cannot imply unsupported file semantics. |
| T-140-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs are planned; any attempted install must stop for slopcheck/package legitimacy review. |
</threat_model>
