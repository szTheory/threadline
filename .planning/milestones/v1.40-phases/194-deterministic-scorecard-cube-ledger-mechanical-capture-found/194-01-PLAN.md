1. Entry count is **130** (RESEARCH said ~133; the real ledger has 130). All 130 have `current_score == ratchet_score` today (verified) — so migration claims NO gain and evidence-on-gain never fires at rest.

3. **legacy_score** = each entry's v1 `current_score` (frozen provenance; identical number at migration).
4. **scores cube (per entry, all 130):** exactly 14 cells, keys sorted:
   `P1.hierarchy, P1.density, P2.hierarchy, P2.density, P3.hierarchy, P3.density, P4.hierarchy, P4.density, P5.hierarchy, P5.density, all.rhythm, all.typography, all.color_contrast, all.brand_fidelity` (sorted alphabetically in the JSON). Every cell is born `{"current": null, "floor": 0, "status": "unrated"}`. The old opaque score is NEVER copied into any cell floor.
5. **evidence_ref** is OPTIONAL and OMITTED at migration (no gains). Its shape when present (Phase 195+) is a cell-keyed map `{cell_id: repo_relative_path}`; the guard File.exists?-checks every value.
6. **mechanical_floors** top-level block is seeded EMPTY `{}` at migration (Plan 03 populates it from first capture).
7. **ratchet.signoffs** is seeded EMPTY `[]`, appended into the existing `ratchet` block (which keeps `locked_ids`, `minimum_scores`, `resets`).
8. **Rollup-integrity rule** (guard, Task 2): rated cells = cells with non-null `current`. If an entry has ≥1 rated cell, assert `current_score == min(rated cell currents)`. If 0 rated cells, assert `current_score == ratchet_score` (no unearned gain; scalar is the watermark). This is vacuously green at migration.
9. **Cube projection scope:** the `scores` map lives on all 130 entries in the JSON, but the DESIGN-SYSTEM `## Scorecard Cube` per-persona projection covers **page-kind entries only** (the surfaces personas navigate). Non-page entries keep their existing inventory-section freshness rows unchanged.
