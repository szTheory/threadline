<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config to generated SQL | `config :threadline, storage_schema: ...` crosses into generated PostgreSQL DDL. |
| generated migration to PostgreSQL | Host migration applies schema/table/function/index SQL. |
| docs to adopter action | Public docs instruct when to set storage_schema before generation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-190-01 | Tampering | `Threadline.StorageSchema.validate!/1` and generated migrations | mitigate | Validate one identifier segment and quote with `StorageSchema.quote_ident/1` before interpolation per D-190-11 through D-190-13. |
| T-190-02 | Elevation of Privilege | PostgreSQL search_path lookup | mitigate | Qualify Threadline-owned table and function references; generated SQL must not depend on search_path per D-190-12. |
| T-190-03 | Information Disclosure | Mixed quoted/unquoted case handling | mitigate | Contract tests cover mixed-case `AuditLog` so generated SQL cannot silently target lower-cased objects. |
| T-190-04 | Repudiation | Generated migration provenance | mitigate | Docs and tests state that generated files freeze the configured schema at creation time per D-190-14. |
| T-190-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install tasks exist in this plan. |
</threat_model>
