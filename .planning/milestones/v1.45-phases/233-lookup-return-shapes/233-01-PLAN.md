<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller id -> lookup | a raw id (often a URL segment) reaches the row query |
| adopter scope fn -> row query | host-owned tenancy predicate decides row visibility |
| exception message -> logs / error pages | NotFoundError text can reach logs and Plug error rendering |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-233-01 | Information disclosure | TransactionLookup.fetch_row/2 | high | mitigate | row is scoped with a hardcoded :transaction_header surface (single [at] binding, never caller-relabelled — :surface is rejected by the allowlist); scope rejection returns the same :not_found as a missing row (transaction_lookup_test) |
| T-233-02 | Information disclosure | Threadline.NotFoundError.message/1 | high | mitigate | message is built only from resource and inspect(caller id); byte-equality test between scope-rejected and missing rows and a negative assertion on a distinctive row value |
| T-233-03 | Denial of service | malformed id input | medium | mitigate | binary non-UUID ids return :not_found instead of raising (no 500 on garbage URLs); non-binaries still raise ArgumentError as a programmer error |
| T-233-04 | Repudiation / Tampering | storage_schema misconfiguration | medium | mitigate | no rescue in the fetch; invalid identifier and undefined_table stay loud (tests) |
| T-233-SC | Tampering | hex/npm installs | low | accept | this plan installs no packages |
</threat_model>
