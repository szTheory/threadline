## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, compact command/copy internals |
| sm | 8px | Control gaps, row action gaps, verdict metadata gaps |
| md | 16px | Default element spacing, page header action wrapping, table/card padding |
| lg | 24px | Section padding and compact page-block breathing room |
| xl | 32px | Major stack gaps using existing `--tl-gap-section` |
| 2xl | 48px | Largest existing `style.ex` token; only for major vertical breaks already present |
| 3xl | 64px | Standard scale value only; do not introduce a new CSS token or use in Phase 185 unless already expressible without token churn |

Exceptions: existing `style.ex` intermediate tokens `12px`, `20px`, and `40px` may remain where already used by table rows, controls, or shell layout. New Phase 185 CSS should prefer `4`, `8`, `16`, `24`, and `32`; preserve `--tl-hit-area: 40px` as the minimum interactive target and do not reduce row disclosure/button hit areas.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 24px | 600 | 1.2 |

Use exactly these four sizes in the changed Coverage surface. The consolidated readiness verdict title uses the Display row, the page `h1` keeps the Heading row through `UI.page_header`, body/remediation text uses Body, and chips/table labels/schema metadata use Label. Commands, schema names, and table names use IBM Plex Mono at the Label size with `overflow-wrap: anywhere`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--tl-color-bg`: dark `#0B1020`, light `#F7F9FC` | Page background and surrounding shell |
| Secondary (30%) | `--tl-color-surface` / `--tl-color-surface-raised`: dark `#141B2D` / `#1B253A`, light `#FFFFFF` / `#EEF3FA` | Header, verdict unit, table wrapper, row disclosure body, alerts |
| Accent (10%) | `--tl-color-accent`: dark `#4F8CFF`, light `#1557C0` | Refresh, Apply schema, Use public schema, covered-row `View activity`, focus rings, selected/link affordances |
| Destructive | `--tl-color-danger`: dark `#FF8585`, light `#A33434` | Destructive actions only; no destructive actions exist in Phase 185 |

Accent reserved for: schema form submit, refresh, invalid-schema recovery link/button, row-level `View activity`, links, and focus/selected affordances. Do not use accent to decorate metrics, non-action labels, or the verdict background.

Status colors for Coverage:

| Status | Token | Required non-color cue |
|--------|-------|------------------------|
| Not ready / Needs capture | `--tl-color-danger`, `--tl-color-danger-bg`, `--tl-color-danger-border` | Copy says "Not ready" and chip says `Needs capture`; warning icon allowed |
| Ready for tracked tables / Covered | `--tl-color-success-text`, `--tl-color-success-bg`, `--tl-color-success-border` | Copy says "Ready for tracked tables" or `Covered` |
| Expected gap | `--tl-color-warning-text`, `--tl-color-warning-bg`, `--tl-color-warning-border` | Chip says `Expected gap`; row action says `Excluded from readiness` |
| Stale last-good data | `--tl-color-warning-*` through `UI.stale_banner` or equivalent alert | Copy says refresh failed and last-good data remains |
| Invalid schema / page error | `--tl-color-danger-*` through `UI.alert variant="error"` or equivalent | Copy states the invalid schema and the recovery action |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Add capture` - row-level disclosure only for rows marked `Needs capture`; no page-level generic Timeline CTA |
| Empty state heading | `No audited tables found` |
| Empty state body | `No audited tables were found for schema SCHEMA. Generate trigger migrations for the tables that should be tracked, apply them, then refresh audit readiness.` |
| Error state | Invalid schema: `Schema SCHEMA was not found. Choose a schema from the list or use public schema.` Refresh failure: `Could not refresh coverage for SCHEMA; showing last known results from CHECKED_AT. Retry refresh.` |
| Destructive confirmation | None; Phase 185 has no destructive actions |

Additional locked labels:

| Surface | Required Copy |
|---------|---------------|
| Page heading | `Audit coverage` |
| Header lede | `Selected-schema audit readiness and table-level capture gaps.` |
| Schema label | `Schema` |
| Schema submit | `Apply schema` |
| Invalid-schema recovery | `Use public schema` |
| Refresh | `Refresh` |
| Verdict not ready | `Not ready for SCHEMA: N tables need capture.` |
| Verdict ready with expected gaps | `Ready for tracked tables in SCHEMA: N covered, M expected gaps excluded.` |
| Verdict ready without expected gaps | `Ready for SCHEMA: all tracked tables covered.` |
| Verdict next step when not ready | `Fix rows marked Needs capture, apply the migration, run mix threadline.verify_coverage --schema=SCHEMA, then refresh.` |
| Public-schema verifier copy | `Run mix threadline.verify_coverage, then refresh.` |
| Expected-gap row action | `Excluded from readiness` |
| Covered-row action | `View activity` |
| Unsafe/non-public remediation fallback | `Generate a trigger migration for SCHEMA.TABLE after confirming the identifier; do not paste an auto-built shell command for this table.` |

Copy rules: use `Coverage`, `audit readiness`, `selected schema`, `checked`, `tracked tables`, `covered`, `needs capture`, `expected gap`, `Add capture`, `verify coverage`, `Refresh`, `View activity`, `Timeline`, `public schema`, and `non-public schema`. Do not use `capture is complete`, `complete timeline answers`, or generic `Open Timeline` page-level copy.

## Coverage Layout Contract

1. The page order is fixed: `UI.page_header`, page-level alert/stale banner if present, one consolidated readiness verdict, then the row comparison table.
2. The readiness verdict is the only page-level readiness summary. Remove the competing `tl-trust-rail`, separate metric grid, and standalone remediation section from the normal success branch.
3. The verdict must include selected schema, checked-at metadata, covered count, needs-capture count, expected-gap count, and one next action in a single scannable unit.
4. The verdict unit should render as one section labelled `Selected schema readiness` or with an equivalent `aria-labelledby` heading. It may use a new private function component/helper and a `tl-coverage-verdict` class family.
5. The verdict uses a status stripe or compact status chip plus text. Color never carries status alone.
6. The row table remains below the verdict and preserves `data-testid="coverage-table"` plus the table headers `TABLE`, `STATUS`, `SOURCE`, and `Actions`.
7. The table is the comparison/action surface only. It must not be the only place where readiness is answered.
8. Repeated "needs capture" language is limited to the verdict, row chips, and the row disclosure label. Do not repeat the same remediation sentence in a separate page block.

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Schema selection | Use a native `<select name="schema" id="coverage-schema">` populated from available non-system schemas. Include `public` and the current valid selected schema. Submit through the existing `select-schema` event and preserve `/audit/coverage?schema=NAME`. Do not use tabs, custom comboboxes, localStorage, or route changes. |
| Invalid schema URL | Preserve the rejected URL value in visible copy, show an error alert, keep the schema picker usable, provide `Use public schema`, and do not render stale `public` coverage as if it belonged to the invalid schema. |
| Refresh | Refresh only the selected schema. If refresh succeeds, update the selected-schema checked-at timestamp. If refresh fails after prior success, keep last-good data visible, show a warning/stale banner above the verdict, and do not overwrite the last successful timestamp with a failed-check timestamp. |
| Needs-capture row | Render `Add capture` as a native `<details>` disclosure. For safe public identifiers, show `mix threadline.gen.triggers --tables TABLE` with a copy button bound to the full command. For non-public or unsafe identifiers, show the conservative fallback copy and no fabricated copyable command. |
| Expected-gap row | Render `Expected gap`, source (`baseline` or `config`), and `Excluded from readiness`. Do not render `Add capture` or command copy. |
| Covered row | Render `View activity` only on covered rows. Public schema links may omit `table_schema`; non-public links must include `table_schema=SCHEMA&table=TABLE`. |
| Generic Timeline CTA | Do not render any page-level Timeline CTA from Coverage. Timeline handoff is contextual to covered rows only. |
| Empty schema | Use the empty state copy above; keep schema selector and Refresh available; do not show readiness as ready. |
| Unsupported coverage lane | Keep existing unsupported view semantics: state this support lane cannot show Coverage, name `mix threadline.health.coverage`, and do not imply a permissions problem. |

## Responsive And Accessibility Contract

- At 320px and 375px, the verdict, schema picker, table rows, row disclosure, command text, and copy button must fit without horizontal page overflow.
- On mobile, schema select, Apply schema, Refresh, and Use public schema wrap instead of shrinking text below the declared type scale.
- Command/copy layouts must not overlap. If the command and copy button cannot share a row, stack the copy button below or beside a wrapped command using existing 8px/16px gaps.
- Interactive controls keep at least the existing `--tl-hit-area: 40px`; do not reduce disclosure summary or button target size.
- Focus states use the existing focus ring and must be visible on schema select, buttons, links, details summary, and copy controls.
- Native controls keep native keyboard behavior. Do not introduce custom select/listbox behavior in Phase 185.
- Alerts use `role="alert"` for invalid schema/page errors and `role="status"` for stale last-good warnings.
- The verdict section heading is reachable by screen-reader users and appears before table navigation in DOM order.
