## Deviations from Plan

**1. [Rule 3 - blocking issue] Fixed the literal Task 1 regenerate command to export `MIX_ENV=test` for the whole wrapped shell, not just the generator invocation**
- **Found during:** Task 1
- **Issue:** The plan's literal command (`... && printf "n\n" | mix deps.get && MIX_ENV=test mix threadline.gen.triggers ...`) prefixes `MIX_ENV=test` only on the `gen.triggers` call. Running it as written failed both `mix deps.get` and `mix threadline.gen.triggers` with `** (File.Error) could not read file ".../config/dev.exs"`, because the evaluator's `config/config.exs` always does `import_config "#{config_env()}.exs"` and only `config/test.exs` exists (no `config/dev.exs`) — so any step defaulting to `:dev` (the Mix default) dies immediately, before ever reaching the generator.
- **Fix:** Wrapped the whole `bash -lc` body with `export MIX_ENV=test` at the top, covering `deps.unlock`, `deps.get`, and `threadline.gen.triggers` uniformly. This is the same approach `mix verify.hex_evaluator` itself already uses (`Mix.shell().cmd(cmd, env: [{"MIX_ENV", "test"}])`), so it is consistent with the project's existing pattern for this fixture, not a new one.
- **Files modified:** none (command-only; no source file needed changing) — recorded in the contract test's `@regenerate_hint` for future reproducibility.
- **Commit:** `fc514bc8`

**2. [Rule 1 - bug] Fixed a config/config.exs comment that accidentally embedded the literal string "storage_schema", tripping the plan's own acceptance gate**
- **Found during:** Task 2 (acceptance-criteria check)
- **Issue:** `config/config.exs`'s explanatory comment above the new `:trigger_capture` key originally read "...This key never gains :storage_schema — the evaluator's legacy-public proof...", which is prose about the *absence* of a key but still matched `grep -c 'storage_schema'` > 0, failing the plan's own gate (`grep -c 'storage_schema' priv/ci/hex_evaluator/config/config.exs` must equal `0`).
- **Fix:** Reworded the comment to convey the same constraint ("Do not add a dedicated schema key here...") without the literal substring `storage_schema`.
- **Files modified:** `priv/ci/hex_evaluator/config/config.exs`
- **Commit:** `4e3b4cc1`

No other deviations. Both are Rule 1/3 (bug fix / blocking-issue fix), auto-applied per the executor's deviation rules; no architectural change and no `:storage_schema` was ever added.
