The loader exposes the override for the read side (CONF-01 capture and validation half, CAP-05 config half; D-11, D-12, D-13, D-14, D-15, D-16, D-17, D-18).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host config primary_key: -> generated SQL | adopter-controlled column names become a literal text[] in frozen migration SQL and trigger arguments |
| host config -> runtime loader | the operator surface calls TriggerCaptureConfig.load/0 at runtime; a malformed entry raises there as well |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-210-12 | Tampering | validate_primary_key!/3 -> declared text[] literal | high | mitigate | Each name passes StorageSchema.validate_identifier!(:primary_key_column) (identifier regex, at most 63 bytes, no NUL, no whitespace) on the raw value before it is written; literals use sql_string_literal/1; trigger arguments are built with quote_literal inside the DO block |
| T-210-13 | Tampering, Repudiation | override matched to a non-unique or nullable column set | high | mitigate | DO block requires a unique, valid, ready, immediate, non-partial, non-expression index whose key set equals the declared set, every column NOT NULL; real-PG tests for each disqualifier |
| T-210-14 | Tampering | override column also masked or excluded | high | mitigate | Rejected at config load (overlap with normalized mask/exclude) and again by the DO-block redaction check on keys |
| T-210-15 | Denial of Service | runtime config load raising on a malformed entry | low | accept | Same behavior as existing RedactionPolicy validation; a malformed config fails at gen time first, so it is caught before deploy |
</threat_model>
