<objective>
Prove on real PostgreSQL that triggers written by 0.10.x keep capturing exactly as before once the global function carries the new body, that any unresolvable key stores `{}` without failing the host write, and that regenerating a 0.10.x trigger swaps in arguments under the same name (CAP-04; D-01, D-02, D-03, D-04).

Purpose: the new body is one-way and ships inside every adopter's next trigger migration. This plan pins its compatibility with frozen historical SQL before any refusal or override logic is layered on.
Output: a frozen 0.10.2 function-body fixture and `legacy_trigger_pk_fallback_test.exs`.
</objective>

## Trust Boundaries

|----------|-------------|
| host write -> capture trigger | the capture body runs inside the adopter's transaction; any raise aborts their write |
| frozen historical SQL -> current function | 0.10.x triggers in adopters' databases call whatever global body the latest migration installed |
