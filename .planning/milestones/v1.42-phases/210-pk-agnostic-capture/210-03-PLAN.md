<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host config (mask, exclude) -> DO-block text[] literal | adopter-controlled column names are written into frozen SQL |
| catalog facts at migrate time -> error text | index and column names from the adopter's schema flow into RAISE messages |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-210-08 | Tampering | redacted_columns literal array | high | mitigate | Columns come from RedactionPolicy-validated config and are written with sql_string_literal/1 (single quotes doubled); they are compared as data, never executed |
| T-210-09 | Tampering, Repudiation | detected key column in mask or exclude | high | mitigate | DO block raises before the trigger is created; real-PG tests for mask and exclude; the array is pinned to the function's rules so the two cannot drift |
| T-210-10 | Denial of Service | refusal of a PK-less or unsupported-type table | medium | accept | Refusal happens in the migration transaction, never on a host write; the legacy trigger (if any) stays in place and keeps capturing, proven by the parted_events test |
| T-210-11 | Information Disclosure | HINT text with table and column names | low | accept | Only schema metadata already visible to the migrating role appears in the error; no row data |
</threat_model>
