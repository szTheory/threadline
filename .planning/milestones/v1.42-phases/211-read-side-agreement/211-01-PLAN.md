<design_decisions>
These settle the orchestrator corrections and RESEARCH open questions for the executor. Do not reopen them.

1. **Queries stay Ecto (orchestrator correction 1).** Raw parameterized SQL is used ONLY inside RowKey to (a) read key-column types from the catalog and (b) render the comparison map. `history/3`, `row_history_query/3` and `as_of/4` remain Ecto queries using `where([ac], ac.table_pk == type(^table_pk, :map))`. `row_history_query/3` keeps its `:: Ecto.Query.t()` spec.
2. **Why two raw statements, not one.** A `CAST(expr AS type)` target is a SQL grammar token; PostgreSQL cannot take it from a subquery or a bind parameter (RESEARCH Pitfall 3, reproduced). So the catalog lookup and the render cannot be one statement. RowKey issues the catalog lookup, then the render. Record this reason in a code comment on `render!/3` (no planning IDs in the comment).
3. **No cross-call cache (D-05 discretion).** The catalog lookup runs on every call. A `:persistent_term` cache would serve stale types after an adopter retypes a key column, and the test suite drops and recreates same-named tables with different key types. One indexed catalog read per history call is cheap.
4. **Catalog query is fully parameterized.** `SELECT a.attname, format_type(a.atttypid, a.atttypmod), <base type name following typbasetype through domains> FROM pg_attribute a ... WHERE a.attrelid = to_regclass($1) AND a.attname = ANY($2) AND a.attnum > 0 AND NOT a.attisdropped`. `$1` is the quoted qualified host table text from `StorageSchema.qualified_host_table/1` (the same builder PrimaryKeySQL uses). `$2` is the column list. Nothing is interpolated.
5. **Render SQL interpolates only the catalog type text.** `SELECT jsonb_build_object($1::text, to_jsonb(CAST($2 AS <type>)) #>> '{}', $3::text, to_jsonb(CAST($4 AS <type>)) #>> '{}', ...)`. Column names are bind parameters, so no escaping is needed. The type text comes only from `format_type` and is interpolated verbatim and unquoted (RESEARCH Pitfall 4: `character(8)` must not be re-quoted). Defense in depth: refuse, with ArgumentError, any type text containing `;`, a NUL byte, `--` or `/*`.
6. **Value binding goes through the schema field's Ecto type (orchestrator correction 3).** For each key field, run `Ecto.Type.cast(schema_module.__schema__(:type, field), value)` and then `Ecto.Type.dump/2` on the result. This turns a route-supplied `"42"` into `42` for an `:id` field, a UUID string into 16 bytes for `:binary_id`/`Ecto.UUID`, and an `Ecto.Enum` atom into its string. If the catalog base type is `uuid` and the dumped value is still a 36-character string, apply `Ecto.UUID.dump/1`. A cast or dump `:error` raises ArgumentError naming the field, the schema and the value's inspect form.
7. **Dropped or renamed tables and columns stay readable (fallback type map).** Audit rows outlive the host table, so a missing catalog entry must not block reads. When `to_regclass($1)` is NULL, or a key column has no live `pg_attribute` row, take the PostgreSQL cast type for that column from the field's Ecto type (`schema_module.__schema__(:type, field)`) through a fixed module-attribute map:
   - `:id`, `:integer` → `bigint`
   - `:binary_id`, `Ecto.UUID` → `uuid`
   - `:string` → `text`
   - `:date` → `date`
   - `:naive_datetime`, `:naive_datetime_usec` → `timestamp`
   - `Ecto.Enum` → `text`. Match the parameterized type shape `{:parameterized, {Ecto.Enum, _}}`, plus the older `{:parameterized, Ecto.Enum, _}` shape.
   Render through PostgreSQL exactly as in design decision 5, using `to_jsonb(CAST($n AS <mapped type>)) #>> '{}'`.
   - The map is exact for every integer width (bigint renders the same digits), for text/varchar/citext, and for enum labels.
   - The one known inexact case is a `char(n)` key: the fallback renders it as `text`, which drops the stored blank-padding. Record this in a code comment here; 211-04 documents it in the history/as_of `@doc` and in `guides/audit-indexing.md`.
   - For the uuid dump rule in decision 6, the fallback's base type is the mapped type.
   Raise `ArgumentError` only when the catalog cannot type the column AND the Ecto type is not in the map. The message names the field, its Ecto type (inspect) and the qualified table, for example `cannot determine the key type of :code (MyApp.Money) for public.invoices: the table or column is not in the database and the Ecto type has no built-in mapping`. Uncastable values, nil values and key-set mismatches still raise as in decisions 6 and 8.
8. **Error style.** Bare `ArgumentError` messages with no `threadline:` prefix, matching the existing `Threadline.Query` validators. This plan implements only the scalar and nil messages. 211-02 adds the full D-03 key-set matrix.
9. **`scope_query_fn` params.** `row_history_scope_opts/2` keeps forwarding the raw caller-supplied `id` unchanged (RESEARCH Open Question 1).
10. **`row_history_query/3` gets its repo from filters.** `repo = timeline_repo!(filters, [])`. `row_history/4` and `row_history_page/4` pass `Keyword.put(filters, :repo, repo)` so a repo given only in opts still reaches it. `:repo` is already an allowed row-history filter key.
11. **Size caps.** `lib/threadline/query.ex` is 745 lines and the cap is 800 (`test/threadline/source_size_contract_test.exs`). Put all key logic in RowKey and add ONE private `where_row/2` in query.ex that applies the three `where`s (table_schema, table_name, table_pk). Functions stay at 120 lines or fewer.
</design_decisions>
