<objective>
Emit a distinct per-table capture function for every table, derived from the (schema, table) pair, and replace every cascading or unconditional function drop with the orphan-safe DO block, proven on real PostgreSQL through Ecto.Migrator (roadmap SC1 fresh-install half and SC3; NAME-02, NAME-04; D-01, D-02, D-03, D-04, D-07).

Purpose: this is the core of the security fix. After this plan no fresh install can put two tables on one capture function, and no generated drop can remove or disable another table's trigger. Upgrade-specific protection (the post-condition guard over 0.10.x shared functions) is plan 04.
Output: TriggerSQL on Naming, the DO drop builder, reordered migration assembly, a reusable real-PG migration harness, fresh-install SC1 and rollback SC3 tests. The adopter-facing moduledoc and CHANGELOG rewrite for these behaviors is plan 05 (split out to keep this plan inside the context budget); the TriggerSQL function docs that describe name shapes are updated here, in Task 1, alongside the code.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| --tables / trigger_capture config -> generated DDL | table names and redaction rules become frozen SQL that runs with DDL privileges in the adopter's database |
| generated migration -> live catalog | at migrate time the DO blocks read pg_trigger to decide whether a function is still in use |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-209-09 | Information disclosure | per-table function shared across tables (public.a_b vs a.b, 36-byte prefixes): one table's rows captured under another's redaction rules | critical | mitigate | Naming.function_name/1 for every per-table function (Task 1); real-PG own-mask tests for both collision shapes |
