## Copywriting Contract

Use concise, exact language. Name the selected host schema and table wherever a coverage result or remediation is shown. Keep the wording clear about what a successful read establishes and what remains unknown.

| Element | Copy |
|---------|------|
| Coverage primary CTA | `Refresh coverage` |
| Evidence primary CTA | `View proof history` |
| Policy primary CTA | `Refresh policy inspection` |
| Confirmed empty coverage heading | `No audited tables found` |
| Confirmed empty coverage body | `No tables were found in schema {schema} during this inspection.` |
| No matching evidence heading | `No Threadline evidence for this selection` |
| No matching evidence body | `No evidence was recorded for this subject and reference. This does not establish whether other activity occurred.` |
| Empty policy body | `No configured redaction policies were found for this inspection.` |
| Error state | `Coverage could not be read for schema {schema}. Retry the inspection. No coverage result is confirmed.` / `Evidence is unavailable for this selection. Retry the read; no empty result is implied.` / `Deployed policy could not be inspected. Retry before treating policy as matched.` |
| Stale state | `Showing last successful inspection from {timestamp}. The current refresh failed; these rows may be stale.` |
| Destructive confirmation | None. These routes remain read-only. Trigger migration generation and application stay in the host-owned workflow; the UI never applies a migration. |

For evidence records, label `summary_status` and proof assessment separately. Use the existing assessment terms `proven`, `inferred posture`, and `unsupported`, and state that `proven` applies only to the recorded snapshot. State that latest projection and append-only history describe recorded Threadline evidence and do not prove overall capture completeness or absence of unrecorded activity. Label any existing time window or result cap and its completeness limit. Do not render or copy arbitrary `detail`, `provenance`, raw maps, raw trigger SQL, audit sample values, or redacted values. Copy controls may contain only allowlisted references, safe policy text, and validated remediation commands.

Coverage remediation must show the exact selected schema and table. Offer `mix threadline.gen.triggers --tables SCHEMA.TABLE` only when both identifiers pass the conservative generator-safe check; otherwise show the exact identifiers and a manual host-migration path without a shell command. Then direct the operator to the schema-specific coverage verifier. A known missing trigger is labeled drift even when the configured policy is empty; unreadable or unrecognized deployed policy is labeled `Could not inspect` and never appears as a match. Policy comparison describes current trigger definitions only, not historical rows or downstream exports.

## UI Considerations

Applicable shape-rooted state considerations resolved: 32 total (19 explicit, 13 backstop), 0 unresolved, 0 unclassified.

### Screen anchors and hierarchy

Preserve the existing routes and route-specific representations. Keep the shared page header and selected context first, then make each screen's primary task anchor visually dominant:

| Screen | Primary visual anchor | Hierarchy |
|--------|-----------------------|-----------|
| Coverage | Schema-scoped coverage table, with uncovered/drift rows easiest to scan | Page title and selected schema → coverage verdict and refresh action → table grouped with the selected schema → row-level safe migration remediation and schema-specific verifier → empty, unavailable, or stale status adjacent to the result it qualifies |
| Evidence | Latest subject-record evidence card with its proof assessment | Page title and selected subject/reference → latest record summary with `summary_status` and proof assessment clearly separated → bounded evidence fields → proof-history navigation and records → unavailable, disabled-access, or no-match status associated with the selection |
| Policy Redaction | Per-table configured-versus-deployed comparison table, with actionable drift first | Page title and inspection action → drift summary → per-table comparison rows with drift before matches → unreadable/unrecognized trigger state clearly separate from matches → row-level normalized policy details and safe remediation disclosure |

Use the existing table representation for Coverage and Policy Redaction and evidence cards for Evidence, as specified in D-10. Do not merge the three screen anchors into a generic dashboard or change route structure.
