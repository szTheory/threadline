<resolved_decisions>
- D-17 reversibility is one-way and was ALREADY decided by the maintainer during discuss-phase on 2026-10-01 ("Strip now"). No checkpoint:decision is inserted; implement as specified.
- D-17 asks the planner to check `scope_keys`: every emitter computes it as `Map.keys(scope) |> Enum.sort()`, i.e. the host scope map's KEYS, never values; every scope shape in this repo's tests is identity-free in its keys. `scope_keys` stays. The guide (plan 05) notes that a host that uses identity values as map keys would leak them.
- D-03 vs kept `path`: `path` is a binary today (theme plug sends the mounted theme route, e.g. `/audit/theme`; the LiveView and export plug send `""`). D-17 keeps `path`. Resolution: the authorize helper is the one helper that takes `%Plug.Conn{} | nil` and the scope; it derives `path` from `conn.request_path` (route path only, no query string) and `scope_keys` from `Map.keys/1`, so no call site passes a binary and no scope value is ever forwarded. Every other helper uses D-03's integer/boolean/atom/exception guards.
</resolved_decisions>
