<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public caller -> evidence context | Callers must supply explicit meaning while the library supplies only mechanical defaults. |
| Evidence context -> append-only schema | The public write boundary must preserve append-only insert semantics and not expose schema internals as the contract. |
| Runtime environment -> provenance capture | Evidence provenance must not depend on ambient process or web runtime state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-96-01 | Tampering | write-path semantics | mitigate | Use subject-focused public helpers and private insert plumbing so callers cannot smuggle arbitrary evidence meaning through the supported API. |
| T-96-02 | Repudiation | provenance capture | mitigate | Require explicit semantic fields and persist a narrow deterministic provenance envelope with recorded timestamp and schema version. |
| T-96-03 | Elevation of scope | public boundary | mitigate | Reject ambient Phoenix/process-derived provenance and avoid a broad public write-anything API. |
</threat_model>
