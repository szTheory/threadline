# v1.31 — Operator Surface: Personas, JTBD & Information Architecture

Foundational design artifact for milestone v1.31. **Phase 135 (Seed Enrichment & IA Lock-In) consumes and locks this**; per-screen phases (137–140) reference it. Scope: the `/audit` operator surface (adopter-mounted admin UI), NOT the demo app.

Grounded in the 10 shipped LiveViews under `lib/threadline/operator_surface/live/` and the nav in `components/surface_header.ex`. The surface is already mature (GDS-style Home in `start_live.ex`, cross-screen "trust rail" links, consistent `tl-empty` states, feature-flag-aware nav). Recommendations are deliberate — flagged **keep** / **rename** / **restructure** — no churn for its own sake.

## 1. Personas

The defining tension is **arrival context** (what just happened to bring you here), not job title. The same person can wear two hats in a week. Orient by arrival, don't force everyone through Timeline first.

### P1 — Incident Responder (on-call engineer)
- Senior, high schema fluency, shallow patience; rare but high-stakes (2am, minutes matter).
- Arrives **with a handle** (record id, correlation_id, table, time window). Wants *"what changed, when, who did it"* fast, then to pivot — not browse.
- Lives in Timeline → Transaction → Row history → Actor. Does not care about coverage %, retention, proof vocabulary.

### P2 — Support Agent (verifying a customer claim) — *most easily overwhelmed*
- Non-engineer / junior, low schema fluency; daily-to-weekly, short narrow sessions.
- Has a customer/record id, NOT a correlation_id. Needs **plain-language, actor-attributed** history for one record, and an exit (copy/export to a ticket).
- **Today has no cordoned path** — Timeline's first affordance is a table-name filter datalist they can't populate. Strongest case for progressive disclosure (UK.gov GDS "start page" philosophy).

### P3 — Compliance / Security Reviewer (proving a control)
- GRC analyst / auditor / security engineer; medium fluency, high rigor; periodic, long deliberate sessions, produces artifacts for third parties.
- Wants the **Prove** cluster: Evidence (proven | inferred_posture | unsupported), Redaction drift, Retention, Exports. The proof vocabulary is a feature, not jargon. Export is a first-class deliverable.

### P4 — Audit Operator / SRE (keeping the system healthy)
- Platform/SRE owner of the audit pipeline; high fluency in Threadline's mechanics; periodic + reactive.
- Wants *"is the audit system itself healthy and complete?"* — coverage gaps, redaction drift, failed retention/exports. The Home health row is built for them. Only persona who treats Coverage/Policy as a destination.

### P5 — Adopter Developer (first wiring it in) — *secondary*
- Mounts `threadline_operator_surface/2`, configures flags + `authorize_fn`; once, then rarely.
- Reads empty states as diagnostics and the `Scoped view` chip as confirmation. A **microcopy constituency**, not a navigation target.

**Design consequence:** P1 (speed-to-actor) and P3 (defensible-proof) pull opposite directions; P2 needs a guard rail neither needs; P4 needs the meta-health view. This is why one undifferentiated page overwhelms. The existing `Find / Verify / Prove` grouping is a good first cut at this divergence — keep the bones, sharpen the entry points.

## 3. Ideal Information Architecture

**Verdict on `Find / Verify / Prove`: keep the three groups, optionally rename one (card-level only), re-cordon entries.** The triad maps cleanly onto persona divergence (P1→Find, P4→Verify, P3→Prove). Renaming the *grouping* would be churn.

- **Optional card-level rename Verify → "Trust"** (Home cards only, NOT nav, to avoid churn): "Verify" reads as an action on a record; the cluster is really "is the audit system trustworthy/complete?" If the team prefers zero divergence, keep "Verify" everywhere — this is the one optional rename.
- **Prove is overloaded** (4 screens behind one nav group). Order by proof-narrative — Evidence (verdict) → Redaction/Retention (supports) → Exports (deliverable) — and add a subtle divider/label before **Exports** so it reads as "take it with you," not a sibling proof.

**Home as orientation hub (GDS start page) — mostly keep, add one cordoned path.** Current Home is already strong (headline "Follow what happened," three job-framed cards, health row for P4, saved-view resume). Surgical additions:
- **Record-first entry for P2 (NEW):** a single plain-language prompt — *"Look up one record's history"* — taking a record/customer id → routes to a **pre-filtered Timeline scoped to that record** (or directly into Row history if table is known). Highest-value IA addition.
- **Keep the health row a quiet affirmation** when healthy ("All systems healthy"); P1/P2/P3 should be able to ignore it, P4 should be able to scan it.

**Screen-level moves (minimal, deliberate):**
- **No merges, no splits.** (Tempting: Redaction+Retention under one "Policy" screen — but they serve different *moments*, trust-before-capture vs confirm-after-purge, and already share `/policy/*`. Leave split.)
- **Clearer affordances (the real work):** first-class Row-history entry (J2/J4); Timeline↔Exports threading (J6 — "queue a full export" with the active filter); Coverage→Timeline is already the model pattern to copy.

**Recommended nav (keep structure, tighten):**
```
Threadline  [ Find: Timeline ]  [ Verify/Trust: Coverage ]  [ Prove: Evidence · Redaction · Retention | Exports ]   [scope chip] [coverage badge]
```
Keep brand-link-to-Home, skip-link, scope chip, coverage badge — all correct and accessible. Only nav change: thin separator before Exports.

**Recommended Home layout (top→bottom):** 1) Hero "Follow what happened." 2) Health row (quiet when healthy). 3) **Record-first prompt (NEW)**. 4) Three job cards (What changed? / Is everything captured? / Prove and export). 5) "Pick up where you left off" saved views.

## 4. Cross-Screen Flows

- **Flow A — Incident attribution (P1):** Home → Timeline (filter) → Transaction → Row history → Actor → export. Middle is clean; *sharpen the on-ramp* — let Home accept a correlation_id/record paste and deep-link into the filtered Timeline.
- **Flow B — Support record lookup (P2) — the priority build:** Home (record-first prompt) → Timeline scoped to record OR Row history → copy/export to ticket. **Largely missing today.**
- **Flow C — Compliance proof + handoff (P3):** Home (Prove card) → Evidence verdict → Redaction/Retention → Exports. Evidence trust-rail links already excellent; *close the export loop* (carry the proof/filter into Exports).
- **Flow D — Health sweep (P4) — the model flow:** Home health chips deep-link to the offending screen → resolve → back. Don't touch it; use as the template for B/C.

## 5. Microcopy & Orientation

Matters most at: the Home hub (orient), empty states (diagnose + next move), screen intros (set the mental model in one line). Brand voice = precise, grounded, quietly confident.

- **Home record-first prompt (NEW):** *"Look up one record's history — Have a record or customer in question? Enter its id to see what changed, when, and who did it — no filters needed."*
- **Timeline empty state recovery nudge:** *"No captured changes match these filters in this window. Widen the time range, or clear the table filter to search everything."*
- **Evidence intro (keep verbatim — exemplary):** *"What can Threadline prove right now?"* — a question in the user's voice, the model for other screens.
- **Consider question-form titles for the proof cluster** where a persona is uncertain what the screen answers: Export Status → "What's ready to hand off?"; Retention History → "What was purged, and did it succeed?" (Tradeoff: warmer but longer — apply selectively; leave Coverage/Policy titles, which already have strong ledes.)
- **Empty-state-as-diagnostic for P5 (keep + replicate):** Evidence's empty state cites `mix threadline.evidence.show` — replicate the "here's the CLI/API to verify" pattern in Coverage and Exports empty states.
- **Scoped-view chip (keep verbatim):** *"Results are limited to the records you are authorized to see."*

## Priority actions (feeds Phase 140 + per-screen phases)

1. **Record-first cordoned path** (Home → filtered Timeline / Row history) — P2/J4, Flow B. Highest value.
2. **First-class Row-history entry** (from Home prompt + Timeline rows) — J2.
3. **Close the export loop** (Timeline/Evidence → pre-filtered Exports) — J6, Flow C.
4. **Correlation-id paste/deep-link** on Home's Find card — P1, Flow A.
5. **Prove-group separator before Exports** + optional Verify→"Trust" card rename.
6. **Microcopy pass** — record-first prompt, Timeline empty-state nudge, question-form proof-cluster titles, CLI-diagnostic empty states.

**Preserve as-is (already right):** the triad, health row, trust-rail cross-links, scope chip, accessible header.
