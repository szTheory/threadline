# Milestone v1.20: Scale and Governance Depth

**Status:** ✅ SHIPPED 2026-05-24
**Phases:** 75-84
**Total Plans:** 22

## Overview

v1.20 moved Threadline from capture-and-investigation foundations into governed
lifecycle management. The milestone added batched retention with operator
visibility, actor-owned saved views, built-in background exports, and truthful
Oban/S3 adapter seams without making those optional integrations library-owned
runtime dependencies.

## Milestone Summary

**Key accomplishments:**

- Added governance schemas plus `Threadline.Storage` and `Threadline.ExportQueue` behaviour seams.
- Shipped batched retention pruning with run tracking and a Retention History operator surface.
- Repaired saved-view ownership so the default `actor_fn` mount path is actor-owned without extra adopter wiring.
- Made built-in background exports truthful end to end: supervised startup, lifecycle timestamps, cleanup, and actor-scoped status UI.
- Closed adapter-backed export delivery with controller-owned local-or-remote download resolution plus startup validation for Oban and S3.
- Rewrote the milestone evidence chain so Phases 75-79 and 84 all close on current-tree proof rather than summary-only claims.

**Issues resolved:**

- Missing retention runtime supervision and named trigger path.
- Missing saved-view session handoff on the normal operator mount path.
- Missing built-in export task-supervisor and cleanup startup.
- S3-backed download failures caused by local-path-only controller logic.
- Stale milestone authority surfaces and incomplete Nyquist closeout artifacts.

**Issues deferred:**

- None within v1.20 scope after Phase 84 closeout.

**Technical debt incurred:**

- No milestone-specific debt was intentionally accepted at close; future work should open under a new milestone rather than piggyback on v1.20.
