```elixir
defmodule ThreadlinePhoenixWeb.SigraContextPlug do
  @moduledoc """
  Sets `x-correlation-id` from Sigra state if and only if the header is absent.

  Mirrors `Plug.RequestId`'s check-before-set idiom — explicit integrator intent
  always wins. Threadline.Plug then reads the (now-populated) header normally.

  This plug runs BEFORE Threadline.Plug in the `:api` pipeline. See
  `guides/integrations/sigra.md` for the full wiring contract.
  """

  @behaviour Plug
  import Plug.Conn

  @impl true
  def init(opts), do: opts

  @impl true
  def call(conn, _opts) do
    case get_req_header(conn, "x-correlation-id") do
      [_ | _] ->
        conn

      [] ->
        case Threadline.Integrations.Sigra.audit_context_overrides_from_conn(conn) do
          %{correlation_id: cid} when is_binary(cid) ->
            put_req_header(conn, "x-correlation-id", cid)

          _ ->
            conn
        end
    end
  end
end
```

Rules:
- Module name MUST be `ThreadlinePhoenixWeb.SigraContextPlug` (matches the file path under `lib/threadline_phoenix_web/`).
- `@behaviour Plug` is mandatory (mirrors `Plug.RequestId`'s declaration).
- The `case`-on-`get_req_header` pattern is the literal idiom from `Plug.RequestId.call/2` — a Phoenix dev recognizes it on sight (CONTEXT D-10).
- The plug NEVER overrides an existing `x-correlation-id` header. This is the trust-boundary contract for T-44-04 (correlation forgery): the integrator owns the header.
- Do NOT add any logic beyond what's shown — no logging, no telemetry, no validation. Plan 03's doc-contract test asserts the body shape verbatim.
