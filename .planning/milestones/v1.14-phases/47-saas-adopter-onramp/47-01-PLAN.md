<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Example source -> published quickstart | Unreviewed edits in `examples/threadline_phoenix/` can desync copied guide snippets unless extraction is enforced. |
| Maintainer-authored STG evidence -> adopter-facing docs | Editorial content can accidentally imply third-party endorsement or point to unverifiable external evidence. |
| Guide files -> ExDoc output | A guide can exist on disk but be omitted from published docs if `docs.extras` is not updated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-01 | Tampering | Marker-backed quickstart snippets | mitigate | Use source markers per D-01/D-03, `extract!/2` hard-fail behavior per D-07, and a dedicated doc-contract test that asserts extracted blocks appear verbatim in `guides/getting-started-saas.md`. |
| T-47-02 | Information Disclosure | Walked STG example | mitigate | Constrain the walked example to fictional placeholders per D-18, require `<!-- ADOPT-EXAMPLE-DISCLAIMER -->`, and extend `stg_doc_contract_test.exs` to reject real vendor naming and enforce in-repo evidence pointers only. |
| T-47-03 | Repudiation | Evidence claims in backlog guide | mitigate | Require at least one reproducible in-repo pointer in an `OK` row and preserve explicit `Issue`/`N/A` labels so the example cannot masquerade as blanket production proof. |
| T-47-04 | Denial of Service | Docs publication path | mitigate | Add only the new guide to `mix.exs` `docs.extras` and verify with `mix docs` so the guide is built in the same path maintainers publish. |
</threat_model>
