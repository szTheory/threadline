<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Maintainer working tree -> release tag | Uncommitted local edits can cause the validated tree to differ from the taggable artifact. |
| `mix.exs` docs/package config -> published Hex package and HexDocs | Packaging or ExDoc drift can silently hide shipped guides or expose the wrong release surface. |
| Changelog/README/CONTRIBUTING prose -> installer and maintainer behavior | Incorrect release copy can misroute adopters, mismatch version/tag data, or skip required publish steps. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-01 | Tampering | `mix verify.release` / maintainer working tree | mitigate | Enforce a clean-tree check per D-07 before any release validation runs, so the verified artifact matches the tree that will be tagged. |
| T-48-02 | Tampering | ExDoc extras and package files | mitigate | Add `test/threadline/release_artifact_contract_test.exs` per D-10 to compare `package[:files]`, `docs[:extras]`, group ordering, and guides on disk. |
| T-48-03 | Repudiation | `CHANGELOG.md` and `CONTRIBUTING.md` release guidance | mitigate | Require a dated `0.3.0` changelog heading via `bin/verify-release-shape` and literal maintainer-runbook assertions for `mix verify.release` and waiting for green CI on `main` before tagging. |
| T-48-04 | Information Disclosure | README / docs routing | accept | Release docs are public by design; the risk is misrouting rather than secret leakage, so mitigate drift with literal README contract assertions and accept public visibility. |
| T-48-05 | Denial of Service | Release pre-flight scope | mitigate | Keep `verify.release` limited to docs/package metadata checks per D-08 and D-09, avoiding DB-dependent gates that would make release validation flaky or unavailable on a packaging-only machine. |
</threat_model>
