# Phase 248 canonical verification: PostgreSQL capacity diagnosis

## Finding

The reported `mix ci.all` failure is a PostgreSQL connection-capacity failure in the example stage. The root suite completed with 3,400 tests, zero failures, three exclusions, and the coverage check passed in 409.4 seconds. `verify.example` then failed before its ExUnit suite could start: `ThreadlinePhoenix` could not ensure its test database existed because Postgrex received SQLSTATE `53300` (`too_many_connections`). The provided log tail identifies the example test helper's `storage_up/1` as the failing boundary. That leaves the canonical alias nonzero; later Dialyzer, Dialyzer-slice, and browser gates were not reached. See `mix.exs` (lines 212–241, 343–353), `examples/threadline_phoenix/test/test_helper.exs` (lines 3–27), and the supplied run log.

The source config gives the example SQL Sandbox a pool of `System.schedulers_online() * 2`; this host has 18 online schedulers, so it requests 36 connections. The root test repo pool is two. PostgreSQL is 14.17 with `max_connections=100` and three superuser-reserved slots; the post-failure snapshot showed 30 idle connections belonging to other databases and no Threadline sessions. The measured 36-slot example pool plus root and notifier connections is plausibly within an isolated 100-connection cluster, while shared-server occupancy can consume the remaining headroom. A temporary private cluster removes shared-server connection contention without changing the shared server or other projects' sessions.

The source confirms the database port is configurable end to end. Root and example test configs read `DB_HOST` and `DB_PORT`; `verify.example` adds only `MIX_ENV` and `RETRY_NETWORK` to its inherited environment; `verify.example_browser` explicitly forwards `DB_HOST` and `DB_PORT`; and the E2E runner plus its SQL probes use those values. `PGHOST`/`PGPORT` are not read by Ecto config, so `DB_HOST=127.0.0.1` and `DB_PORT=<private port>` are the routing controls; setting `PGHOST`/`PGPORT` as well is optional. One test helper embeds port 5432 in a live operator-preview custody probe (`test/threadline/operator_surface/operator_evidence_contract_test.exs`, lines 426–436), but its call requires both `THREADLINE_OPERATOR_EVIDENCE_MODE=live` and `THREADLINE_OPERATOR_PREVIEW_REQUIRED=1` (lines 772–829). `ci.all` does not set either variable, so this is not a blocker in the reported default invocation. If both opt-ins are inherited, that preview probe remains a real port-5432 exception and must be resolved before retrying; do not silently mask an intentionally enabled evidence run.

The migrations create only the `citext` extension. The installed PostgreSQL 14.17 and PostgreSQL 15.17 packages include the `citext` control/SQL files and shared library; a read-only listing of the PG15.17 paths confirms the extension files are already present. No package installation is required. The root and example test helpers connect as `postgres`/`postgres`; Ecto's `storage_up/1` connects to maintenance database `postgres` and creates the named test database, so the private cluster needs a `postgres` login with the configured password and `CREATEDB`/superuser rights. The initdb-created `postgres` superuser is sufficient; no additional application role or extension package is required. `storage_up/1`'s `run_query/2` strips `:pool` and `:pool_size` and starts one transient Postgrex connection; it does not create another 36-connection pool. See `config/test.exs` (lines 5–11), `examples/threadline_phoenix/config/test.exs` (lines 13–35), `deps/ecto_sql/lib/ecto/adapters/postgres.ex` (lines 208–237, 484–500), and `examples/threadline_phoenix/priv/repo/migrations/20260527161605_create_sigra_auth_tables.exs` (line 5).

## Recommendation

Use one task-owned PostgreSQL 15.17 cluster on a verified free loopback port, with `max_connections=100`, the shared server's `C/C` locale and UTF-8 template, and the same timezone/text-search defaults. Bind it only to loopback and a unique temporary data/socket directory. Route the entire canonical invocation with `DB_HOST=127.0.0.1` and that port (and set `PGHOST`/`PGPORT` too only for CLI fallback); retain the configured `postgres` credentials and let the existing checks create/migrate their own test databases. Sample `pg_stat_activity` on this private cluster during the run to record peak connections and establish actual headroom; count the monitor connection in that peak. Stop and remove only this task-owned cluster after the bounded run.

Then make exactly one specifically diagnosed `mix ci.all` retry, not a repeat-until-failure run. The targeted `mix verify.example` stage alone would be a smaller causal probe, but it cannot restore a successful canonical result and would leave later gates unobserved. Reuse the prior root-stage success only as historical evidence; the canonical alias must complete its unvisited later gates to produce a zero exit. Keep the existing stop on the nine-run flake repeat intact. Do not kill other-project sessions, raise shared PostgreSQL limits, change the configured pool/concurrency, or restart the machine.

The original failure occurred against shared PostgreSQL 14.17, below the declared PostgreSQL 15 minimum. That version and its capacity evidence explain the failure, but the revised recommendation deliberately uses the already-installed PostgreSQL 15.17 at the supported floor. A passing private run would establish the canonical flow on PG15 with isolated connection capacity; because the server version differs, it would not reproduce the exact shared PG14 capacity condition. The local Elixir 1.17.3/OTP 27 plus PG15 combination is not the full minimum or current CI tuple and does not replace CI evidence for those tuples (`mix.exs`, lines 36–42).

## Limits

This is a source/config/log diagnosis, not a successful rerun. No database, service, process, dependency, test, or repository state was changed. A passing isolated retry would establish that the canonical flow works against the selected PostgreSQL 15.17 setup with sufficient isolated connection capacity; it would not prove why the shared server reached its limit, nor replace supported-version CI evidence.

## Addendum: use installed PostgreSQL 15.17

The Homebrew PostgreSQL 15.17 `initdb`/`pg_config` tools are already installed, and their sharedir/pkglibdir contain `citext.control`, its SQL scripts, and `citext.so`; no install or download is needed. This supersedes the initial PG14.17 private-cluster choice: use PG15.17 with the same 100-connection limit, C/C UTF-8 template, timezone, and loopback-only isolation. The shared failure evidence remains from PG14.17, below the declared floor; a local Elixir 1.17.3/OTP27 plus PG15 run is useful supported-floor evidence but is not the full min/current CI tuple.
