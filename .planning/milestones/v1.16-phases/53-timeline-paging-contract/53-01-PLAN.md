<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external filter/cursor input -> timeline query layer | Caller-supplied paging input is untrusted and can create silent duplication, skipping, or unstable traversal if under-validated. |
| timeline paging contract -> export streaming contract | Divergent cursor semantics would make investigation reads and export traversals disagree about what the "next page" means. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-01 | T | cursor advancement | mitigate | Encode one descending `(captured_at, id)` keyset rule and lock it with tie-heavy tests. |
| T-53-02 | R | validation posture | mitigate | Reject ambiguous/partial paging input with explicit `ArgumentError`-style failures before query execution. |
| T-53-03 | I | export/query parity | mitigate | Reuse or centralize the keyset predicate so export streaming and timeline paging traverse the same result set. |
| T-53-04 | D | large investigation windows | mitigate | Use keyset paging instead of offset pagination so later pages do not degrade or reorder under large windows. |
| T-53-05 | E | compatibility | mitigate | Keep `Threadline.timeline/2` eager and backward-compatible; add the paged contract alongside it, not as a return-shape break. |
</threat_model>
