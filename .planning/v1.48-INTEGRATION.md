### API and authorization coverage

All 11 mounted LiveViews share the `live_session :threadline` `Auth` hook. `threadline_operator_surface/2` fails compilation unless the host supplies a usable unary `authorize_fn` or the exact explicit `adopter_acknowledges_unauthenticated: true` opt-out; `pipe_through` alone is not accepted as Threadline authorization. The example mount uses actual host callbacks. Coverage, evidence and policy/retention capabilities default denied and are separately checked.

The five companion HTTP endpoints use their own authorization plugs because LiveView hooks do not protect controller routes. Export downloads also enforce requester ownership, completed state and expiry in the controller. This covers the different direct-request path rather than treating hidden LiveView affordances as authorization.
