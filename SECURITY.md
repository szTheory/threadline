# Security policy

## Supported releases

Security fixes are provided for the latest published minor release of Threadline. Check [GitHub Releases](https://github.com/szTheory/threadline/releases) for the current release before reporting or upgrading. Older minor releases may not receive security fixes.

## Report a vulnerability privately

Use GitHub [private vulnerability reporting](https://github.com/szTheory/threadline/security/advisories/new) for suspected or undisclosed vulnerabilities. Do not disclose vulnerability details in issues, pull requests, or other public project spaces.

Include, when available:

- the affected Threadline version or commit;
- the security impact and affected deployment context;
- a minimal reproduction without secrets, personal data, or production audit records;
- known mitigations or workarounds; and
- whether the issue has been disclosed elsewhere.

Maintainers will acknowledge a report as soon as practical, investigate it, and coordinate next steps through the private advisory. Response and remediation times depend on severity, complexity, and maintainer availability.

For ordinary defects, feature requests, and usage questions, choose the matching issue form. For abuse or conduct concerns, follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md); those reports use a separate route.
